量子 LDPC 码的译码器要回答一个问题：看到一串警报，该把哪些比特翻回来？表面码可以把警报两两配对；qLDPC 码里一个错误常常同时点亮三条或更多检查，配对无从谈起。BP-OSD 分两步：置信传播（BP）让比特和检查反复交换「你有多可能出错」，给每个比特打一个可靠度；有序统计译码（OSD）按这个排序解一个线性方程组，保证交出一个与警报相符的修复。本页从三个比特的例子讲起，每一步都能手算或在实验台上复现，读完你可以自己写出一个 BP-OSD。 A decoder for quantum LDPC codes answers one question: given a pattern of alarms, which qubits should be flipped back? The surface code can pair its alarms two by two; in a qLDPC code one error often lights three or more checks at once, and pairing no longer makes sense. BP-OSD works in two steps. Belief propagation (BP) lets qubits and checks repeatedly exchange “how likely are you to be flipped”, which gives every qubit a reliability; ordered-statistics decoding (OSD) then solves a system of linear equations in that order and is guaranteed to return a repair that matches the alarms. The page starts from a three-bit example; every step can be checked by hand or on a bench, and by the end you can write a BP-OSD decoder yourself.

Let bit 2 be flipped: e = (0, 1, 0). The rule for a matrix times a vector is “multiply row i with e entry by entry and add”: row c1 gives 1·0 + 1·1 + 0·0 = 1, row c2 gives 0·0 + 1·1 + 1·0 = 1, so s = (1, 1) and both checks are lit. Now let bits 1 and 2 be flipped: e = (1, 1, 0). Row c1 gives 1 + 1 = 2, which is 0 mod 2 (the two errors cancel; this check sees an even number); row c2 gives 1. So s = (0, 1). Addition mod 2 is also written ⊕: 0 ⊕ 0 = 0, 0 ⊕ 1 = 1 ⊕ 0 = 1, 1 ⊕ 1 = 0, and ⊕ of two 0/1 columns is taken entry by entry.

译码器只看得到 s，看不到 e。它交出一个修复 c：把 c 里为 1 的比特都翻一次。修复至少要让症状清零，这就是条件 H c = s。清零之后留在比特上的是残留 e ⊕ c（真实错误与修复叠加，同一比特翻两次等于没翻）。因为 H(e ⊕ c) = H e ⊕ H c = s ⊕ s = 0，残留不点亮任何检查。不点亮任何检查的 X 型算符只有两种：

The decoder sees s, not e. It returns a repair c: flip every qubit where c has a 1. A repair must at least clear the syndrome, which is the condition H c = s. After that, what remains on the qubits is the residual e ⊕ c (the true error plus the repair; flipping a qubit twice leaves it unchanged). Since H(e ⊕ c) = H e ⊕ H c = s ⊕ s = 0, the residual lights no check. An X-type operator that lights no check is one of two kinds:

  • 逻辑算符logical operator：不点亮任何检查、却不是检查乘积的算符。它悄悄改写了存储的逻辑信息；残留是逻辑算符就是逻辑错误。：不点亮任何检查、却不是检查乘积的算符。它改写了存储的信息，残留是逻辑算符就是失败。

怎么判断残留属于哪一种？看它与每个 Z 型逻辑算符 Z̄ 重叠的比特数是奇是偶。重叠奇数个，二者反对易，残留翻转了 Z̄ 的读数，是逻辑错误；每个 Z̄ 都重叠偶数个，残留是稳定子。要看的是奇偶，不是「有没有一条绕过去的串」：两条平行的绕圈串合起来与 Z̄ 重叠两次，它们的乘积正好是夹在中间的那些检查之积，无害。图 0.1 在最小的环面码上把这件事画出来。

How do we tell which kind a residual is? Count, for every Z-type logical operator Z̄, how many qubits the residual shares with it. An odd overlap means the two anticommute, the residual flips Z̄’s reading, and decoding failed; an even overlap with every Z̄ means the residual is a stabilizer. What matters is the parity, not whether “a string winds around”: two parallel winding strings together overlap Z̄ twice, and their product is exactly the product of the checks between them, which is harmless. So the decoder faces a multiple-choice question: many repairs agree with s, they fall into classesClass (coset): repairs that differ by a stabilizer form one class. All repairs in a class have the same effect; with k logical qubits a syndrome has 2k classes. of repairs that differ by a stabilizer, repairs in the same class have the same effect, and choosing the right class means success. Sections 1.1 to 1.3 of “Decoders · High-School Edition” turn this into “optimal decoding = bet on the most probable class” for the surface code; Chapter 1 here rederives it with classical codes, and Chapter 4 returns to quantum classes.

0.2为什么配对在这里不管用Why pairing does not work here

环面码里，H 的每一列恰好有两个 1：一条边上的 X 错误点亮它两侧的两个面。于是可以把每个可能的错误画成连接两个警报的一条边，一批错误的症状就是这些边的端点，译码就是把亮着的警报两两连起来，挑总长度最短的连法。这就是最小重量完美匹配，它建立在「一个错误 = 两个端点」上。

In the toric code every column of H has exactly two ones: an X error on an edge lights the two faces beside it. So every possible error can be drawn as an edge joining two alarms, the syndrome of a batch of errors is the set of endpoints, and decoding is joining the lit alarms in pairs with the shortest total length. That is minimum-weight perfect matching, and it rests on “one error = two endpoints”.

IBM 提出的 gross 码（[[144,12,12]]，《BB 码 · 译码器》1.2 节）不是这样：它的 HZ 每列有三个 1。本页的脚本按那一页的编号重算了一遍：比特 1 上的 X 错误点亮 Z 检查 4、7、13。一个错误连着三个警报，画出来不是边，而是一条超边hyperedge：同时连接三个或更多顶点的「边」。含超边的图叫超图；完美匹配是为普通的两端点边定义的。。「两两配对」这个说法本身就用不上了。

IBM’s gross code ([[144,12,12]], “BB Codes · Decoders”, §1.2) is different: every column of its HZ has three ones. This page’s script recomputed it with that page’s numbering: an X error on qubit 1 lights Z checks 4, 7 and 13. One error attached to three alarms is not an edge but a hyperedgeAn “edge” joining three or more vertices at once. A graph with hyperedges is a hypergraph; perfect matching is defined for ordinary two-ended edges., and “join in pairs” no longer applies.

能不能退回最笨的办法，把所有与 s 相符的修复列出来逐个比较？第 1 章会数：gross 有 278 ≈ 3.0 × 1023 个，列不完。一般的线性码上，「找与症状相符的最轻错误」是 NP 难问题（Bravyi 等 2308.07915 的补充材料引 Berlekamp、McEliece 与 van Tilborg 1978 年的结果）。实用的译码器只能是近似的，BP-OSD 是其中最常用的通用方案之一。

Could we fall back on the crudest method and list every repair that agrees with s? Chapter 1 counts them: gross has 278 ≈ 3.0 × 1023, far too many. For a general linear code, “find the lightest error that matches the syndrome” is NP-hard (the supplement of Bravyi et al., 2308.07915, cites Berlekamp, McEliece and van Tilborg, 1978). Practical decoders have to be approximate, and BP-OSD is one of the most widely used general-purpose ones.

BP-OSD 的分工一句话说完：BP 排序，OSD 解方程。BP 给每个比特一个实数，表示它有多可能出错；若按这些数逐位判决得到的修复已经满足 H c = s，就直接交出。若不满足，OSD 接手：按 BP 的排序挑出最可能出错的一组比特，在它们身上解 H c = s，其余比特设为 0，保证症状清零。

The division of labour in one sentence: BP ranks, OSD solves. BP gives every qubit a real number that says how likely it is to be flipped; if the bit-by-bit decisions from these numbers already satisfy H c = s, that repair is returned. If not, OSD takes over: following BP’s ranking it picks the group of qubits most likely to be flipped, solves H c = s on them, sets every other qubit to 0, and is guaranteed to clear the syndrome.

关键想法Key idea

译码 = 在所有满足 H c = s 的修复里选一个，使残留与每个 Z̄ 的重叠为偶数。环面码一个错误点亮两个警报，可以配对；gross 这样的 qLDPC 码一个错误点亮三个，只能换别的办法。BP-OSD 的办法是：BP 给每个比特打分排序，OSD 沿这个排序解线性方程组。

Decoding = choosing, among all repairs with H c = s, one whose residual overlaps every Z̄ an even number of times. In the toric code one error lights two alarms and pairing works; in a qLDPC code like gross one error lights three, and a different method is needed. BP-OSD’s method: BP scores and ranks the qubits, and OSD solves the linear system along that ranking.

译码器看到症状，要猜错误。「猜」有好几种问法，答案不一定相同。这一章先在经典的比特上把问题问清楚，再引入整页都要用的对数似然比：它把贝叶斯公式里的乘法变成加法，BP 的两条规则就写在它上面。 A decoder sees a syndrome and has to guess the error. “Guess” can be asked in several ways, and the answers need not agree. 1.1检查、症状与噪声模型Checks, syndromes and the noise model

第 1 到第 3 章只用经典比特，因为 BP 本来就是经典 LDPC 码的译码器，量子码只是把它借过去用（第 4 章）。方程还是 s = H e：比特排成一列 e，检查写成矩阵 H，症状 s 告诉我们哪些检查看到了奇数个错误。例子仍用补课 0.A 的三比特重复码：两条检查 c1 = b1 ⊕ b2、c2 = b2 ⊕ b3。

Chapters 1 to 3 use classical bits only, because BP is originally a decoder for classical LDPC codes and quantum codes borrow it (Chapter 4). The equation is still s = H e: the bits form a column e, the checks form a matrix H, and the syndrome s says which checks saw an odd number of errors. The example is again the three-bit repetition code of Catch-up 0.A: two checks c1 = b1 ⊕ b2 and c2 = b2 ⊕ b3.

检查 i 要告诉邻居 j：「按其他邻居现在的说法，再加上我亮没亮，关于你没错还是出错，我能提供多大的似然比。」1.3 节已经在 p = 0.1 的例子里算过一次：a 没错时检查亮要求 b ⊕ c 为奇（0.18），a 出错时要求为偶（0.82），似然比 0.18 : 0.82。一般情形只差一件事：其他邻居不止两个，各自的出错概率也不再相同，怎么算它们「之和为奇」的概率？

Check i has to tell neighbour j: “given what my other neighbours currently say, and whether I am lit, this is the likelihood ratio I can offer on whether you are clean or flipped.” §1.3 did it once for p = 0.1: with a clean, a lit check needs b ⊕ c odd (0.18); with a flipped, even (0.82); ratio 0.18 : 0.82. The general case needs one more thing: with more than two other neighbours, each with its own flip probability, what is the probability that their sum is odd?

答案用偏差bias：δ = P(0) − P(1) = 1 − 2P(出错)。p = 0.1 时 δ = 0.8。它等于 tanh(L/2)。几个独立比特之和（mod 2）的偏差 = 各自偏差之积。记账最方便：一个比特的偏差 δ = P(0) − P(1) = 1 − 2 × P(出错)，p = 0.1 时 δ = 0.8。关键事实是：几个独立比特之和（mod 2）的偏差，等于各自偏差的乘积（补课 2.A 给出一行证明）。例：两个 δ = 0.8 的比特，和的偏差 0.64，为奇数的概率 (1 − 0.64)/2 = 0.18，和上面数出来的一样。偏差与 LLR 之间只隔一个函数：δ = tanh(L/2)，反过来 L = 2 artanh δ = ln[(1 + δ)/(1 − δ)]。核对：L = ln 9 时 tanh(L/2) = (9 − 1)/(9 + 1) = 0.8。

Three things to read off. First, m is the log of a likelihood ratio, not odds: it carries no prior of j’s own, and j adds it to its own LLR (§2.3). In the example 2.20 − 1.52 = 0.68, exactly the result of §1.3. Second, j’s own message is left out: the check reports what the others say. Third, sign and size can be read separately: artanh is odd, so the sign of m = (−1)s × the product of the other neighbours’ LLR signs; B is a product of numbers of absolute value at most 1, so |m| is at most the smallest |L| among the other neighbours. Plainly: a check is never surer than its least sure neighbour. Chapter 3’s min-sum starts from this. For a check with only two neighbours the product has a single factor, and the rule reduces to m = ± the other neighbour’s L (minus if lit).

Two independent bits u, v with flip probabilities qu, qv. u ⊕ v = 1 needs exactly one flipped: P = qu(1 − qv) + qv(1 − qu) = qu + qv − 2quqv. Substitute eL = P(0)/P(1) and multiply top and bottom by P(1): (P(0) − P(1))/(P(0) + P(1)) = P(0) − P(1) = δ. Inverting: δ = (eL − 1)/(eL + 1) ⇔ eL = (1 + δ)/(1 − δ) ⇔ L = ln[(1 + δ)/(1 − δ)], a function written 2 artanh δ.

2.3比特的规则，与一轮的流程The bit rule, and one round

比特 j 从每条邻居检查收到一个似然比的对数。如果这些证据互相独立，1.3 节说它们直接相加：总 LLR = 先验 + 所有邻居检查的消息。比特回话给检查 i 时，用总数减去 i 自己刚发来的那一条，理由和检查的规则一样：不把 i 的话还给 i，否则 i 会把自己的意见当成新证据。

Bit j receives the log of a likelihood ratio from each neighbouring check. If these pieces of evidence are independent, §1.3 says they simply add: total LLR = prior + every neighbouring check’s message. When the bit replies to check i it uses the total minus the message i itself just sent, for the same reason as in the check rule: do not hand i’s words back to i, or i would count its own opinion as new evidence.

Lj = L0 + Σi mi→j
Lj→i = Lj − mi→j
cj = 1 ⇔ Lj < 0
停止：Hc = s 或达到 max_iterstop: Hc = s or max_iter reached

Alternating the two rules is BP. The most common order is the flooding scheduleEach iteration first lets all checks speak at once, then all bits sum up at once. The alternative is the serial (layered) schedule, which updates check by check; see §3.4.: at the start every bit sends the prior L0 to each neighbouring check; then each iteration has two half-steps, first all checks speak at once by the rule of §2.2, then all bits sum up and reply at once. L[j→i] = L0 for every edge                         # 第 0 轮：只有先验# iteration 0: priors only
repeat up to max_iter times:
    for every check i and neighbour j:             # 前半步：检查发言# first half: checks speak

    for every bit j:                               # 后半步：比特汇总# second half: bits sum up

        L[j→i] = L[j] − m[i→j] for each check i of j

每轮的工作量正比于边数，而且每条边上的计算只用到相邻节点的数，所以 BP 天然适合并行硬件。这也是它在量子纠错里受重视的原因之一（第 7 章说延迟）。

The work per iteration is proportional to the number of edges, and the computation on each edge uses only numbers from adjacent nodes, so BP suits parallel hardware naturally. That is one reason it matters in quantum error correction (Chapter 7 discusses latency).

BP 为什么只是近似，以及常见变体Why BP is only approximate, and its common variants

2.4 节的精确性靠一个前提：一个比特收到的几条消息互不相干。图里一旦有圈，这个前提就破了，BP 会把同一条证据数两次。这一章先在三张小图上把「数两次」算出来，再讲实际使用中最常见的三种改动：min-sum、阻尼和串行调度，以及每种改动的出处。 The exactness of §2.4 rests on one premise: the messages a bit receives are unrelated to each other. 3.1圈与重复计数Cycles and double counting

Tanner 图里的圈cycle：从一个节点出发，沿不同的边走，不走回头路，最后回到出发点的路径。Tanner 图里比特与检查交替出现，所以圈长（边数）总是偶数，至少是 4。是一条从某个节点出发、不走回头路、又回到出发点的路径；比特和检查交替出现，所以圈长（边数）是偶数，最短是 4。图里最短的圈长叫围长girth：Tanner 图里最短的圈的长度（边数）。树没有圈，围长记为 ∞。围长越短，消息越快绕回自己。（girth）。有圈时，比特 j 发出的消息沿圈走一圈会回到 j 手里，j 把它当作另一条检查的新证据再加一遍。消息每轮走两条边（检查→比特、比特→检查），所以长 g 的圈要 g/2 轮才绕回来：圈越短，回来得越快。

Messages cross two edges per iteration (check→bit, bit→check), so a cycle of length g brings a message back after g/2 iterations: the shorter the cycle, the sooner it returns.

四比特环，一个错误。四个比特排成环，检查 c1 = b1 ⊕ b2、c2 = b2 ⊕ b3、c3 = b3 ⊕ b4、c4 = b4 ⊕ b1，Tanner 图本身就是一个长 8 的圈（《BB 码 · 译码器》2.2 节的同一个例子）。b4 出错，c3、c4 亮。穷举：b4 的精确 LLR 是 −4.39（出错概率约 0.99），其他三个 +4.39。BP 第 1 轮就判对了（b4 = −2.20），但之后 b4 依次是 −6.59、−10.99、−6.59、−10.99、−15.38……，第 11 轮到 −28.56，每 4 轮净增 −8.79。它的意见沿环走一圈（8 条边 = 4 轮）回到自己，被当作新证据再加一次。这里多出来的只是把握，判决没错。

The four-bit ring, one error. Four bits in a ring with checks c1 = b1 ⊕ b2, c2 = b2 ⊕ b3, c3 = b3 ⊕ b4, c4 = b4 ⊕ b1; the Tanner graph is itself one cycle of length 8 (the same example as “BB Codes · Decoders”, §2.2). b4 is flipped, c3 and c4 are lit. By enumeration the exact LLR of b4 is −4.39 (flipped with probability about 0.99) and the other three are +4.39. BP decides correctly in iteration 1 (b4 = −2.20), but then b4 goes −6.59, −10.99, −6.59, −10.99, −15.38, …, reaching −28.56 at iteration 11, a net −8.79 every 4 iterations. Its own opinion travels once around the ring (8 edges = 4 iterations), comes back, and is added again as new evidence. What grows here is only confidence; the decision is right.

[7,4] Hamming 码，一个错误。这是经典编码里的老朋友：7 个比特，3 条检查，第 j 列是 j 的二进制写法（行 1 是最低位）。于是 c1 碰比特 1、3、5、7，c2 碰 2、3、6、7，c3 碰 4、5、6、7。任意两条检查共享两个比特，比如 c1、c2 都碰 3 和 7，于是有长 4 的圈 比特 3 → c1 → 比特 7 → c2 → 比特 3（图 3.1）。比特 7 出错，三条检查都亮。穷举给出：比特 7 的 LLR −0.97，其他六个 +2.20；最可能的单个图样就是「只有比特 7」（后验 0.72）。

The [7,4] Hamming code, one error. An old friend of classical coding: 7 bits, 3 checks, column j is the binary expansion of j (row 1 is the lowest bit). So c1 touches bits 1, 3, 5, 7, c2 touches 2, 3, 6, 7, c3 touches 4, 5, 6, 7. Any two checks share two bits; c1 and c2 both touch 3 and 7, giving the length-4 cycle bit 3 → c1 → bit 7 → c2 → bit 3 (Fig. 3.1). Bit 7 is flipped and all three checks are lit. Enumeration gives: LLR −0.97 for bit 7, +2.20 for the other six; the most likely single pattern is “bit 7 alone” (posterior 0.72).

BP 第 1 轮：每条检查亮着、有 4 个邻居，它对每个邻居说 −2 artanh(0.8³) = −1.13。比特 3 在 c1、c2 里，收到两条 −1.13：2.20 − 2.26 = −0.06，判为出错；比特 5、6 同理；比特 7 收到三条：2.20 − 3.39 = −1.20。硬判决是 {3, 5, 6, 7}，它满足全部三条检查，带停止规则的 BP 在第 1 轮就「收敛」了。可残留 {3, 5, 6} 是 Hamming 码的一个码字（第 3、5、6 列相加为 0），这是一次译码失败，而精确的边缘 LLR 明确说比特 3 没错（+2.20）。错在哪里：c1 和 c2 都在「怪」比特 3，但两者的理由是同一件事，就是比特 7 大概没错时它们都需要别人来解释；把这两条消息相加，同一条理由算了两次。不停下的话，BP 在两种状态之间来回摆，在步进器的 Hamming 预设上可以看到。

BP iteration 1: each check is lit with 4 neighbours and tells each of them −2 artanh(0.8³) = −1.13. Bit 3 sits in c1 and c2 and receives two −1.13: 2.20 − 2.26 = −0.06, decided flipped; likewise bits 5 and 6; bit 7 receives three: 2.20 − 3.39 = −1.20. The hard decision {3, 5, 6, 7} satisfies all three checks, and BP with the stopping rule has “converged” after one iteration. But the residual {3, 5, 6} is a codeword of the Hamming code (columns 3, 5, 6 add to zero), so this is a decoding failure, while the exact marginal says plainly that bit 3 is clean (+2.20). What went wrong: c1 and c2 both “blame” bit 3, but for the same reason, namely that if bit 7 is probably clean then each of them needs someone else to explain it; adding their two messages counts that one reason twice. Without stopping, BP swings between two states, as the Hamming preset of the stepper shows.

好处是只剩比较大小和改符号，没有 tanh 与 artanh。坏处是系统地高估把握：三比特检查的例子里，精确消息 −1.52，普通 min-sum 给 −2.20，比特 a 的 LLR 从 0.68 掉到 0.00。所以通常乘一个小于 1 的系数 α：α = 0.8 给 −1.76，α = 0.625 给 −1.37。只有两个邻居的检查，普通 min-sum（α = 1）与精确规则完全相同（只有一个「其他邻居」），所以链和环上普通 min-sum 看不出差别（归一化 min-sum 仍会把每条消息乘上 α）；在 Hamming 预设上切换规则就能看到：普通 min-sum 第 1 轮给比特 3、5、6 的是 −2.20，比特 1、2、4 的是 0.00，比特 7 的是 −4.39（精确规则是 −0.06 与 −1.20），之后在两个状态之间来回摆。

The gain is that only comparisons and sign changes remain, no tanh or artanh. The cost is a systematic overestimate of confidence: in the three-bit check example the exact message is −1.52, plain min-sum gives −2.20, and bit a’s LLR drops from 0.68 to 0.00. Hence the usual factor α below 1: α = 0.8 gives −1.76, α = 0.625 gives −1.37. For a check with two neighbours plain min-sum (α = 1) equals the exact rule (there is only one “other neighbour”), so on chains and rings plain min-sum shows no difference (normalized min-sum still multiplies every message by α); switch rules on the Hamming preset to see it: plain min-sum gives bits 3, 5, 6 −2.20, bits 1, 2, 4 0.00 and bit 7 −4.39 in iteration 1 (the exact rule gives −0.06 and −1.20), then swings between two states.

3.4串行调度：同一轮里先说的先用The serial schedule: what is said first is used first

关键想法Key idea

圈让一条证据沿圈回到出发点，被当成新证据再加一次。后果从「只是过度自信」（四比特环，−28.56 对 −4.39）到「收敛到错误答案」（Hamming 码，{3, 5, 6, 7}）不等。min-sum 用最小的 |L| 代替乘积，省计算、高估把握，常乘一个 α < 1；阻尼放慢更新，能压住摇摆，但压不出一个选边站的答案；串行调度让同一轮里先算出的值马上被用上。

A cycle brings a piece of evidence back to where it started, and it is added again as new. 量子码：变了什么Quantum codes: what changes

把 BP 搬到量子 CSS 码上，有三件事变了：X 错误和 Z 错误分开译码，去极化噪声的先验要换算，以及最要紧的退化：相差一个稳定子的修复同样正确。退化让「每个比特最可能的取值」这个问题本身失灵，这正是 BP 需要 OSD 收尾的主要原因。 Moving BP to quantum CSS codes changes three things: X and Z errors are decoded separately, depolarizing priors have to be converted, and, most important, degeneracy: repairs that differ by a stabilizer are equally correct. Degeneracy makes the question “what is each qubit most likely to be” break down, which is the main reason BP needs OSD to finish the job.

4.1CSS 码：两个经典问题CSS codes: two classical problems

一个 Pauli 错误可以拆成「X 部分」和「Z 部分」：Y = X 与 Z 同时出现（差一个相位，对纠错无关），所以一个错误写成两列 0/1，x 记哪些比特有 X 部分，z 记哪些有 Z 部分。CSS 码的 Z 检查只含 Z，只对 X 部分敏感；X 检查只对 Z 部分敏感。于是量子症状分成两半：sZ = HZ x 与 sX = HX z，各是一个第 1 章那样的经典译码问题。Roffe 等（2005.07016）的说法是：假设 X 与 Z 错误不相关，「the CSS code can be decoded independently as two classical codes」。第 0 到第 3 章做的就是其中一半。

A Pauli error splits into an “X part” and a “Z part”: Y is X and Z together (up to a phase, which does not matter for correction), so an error becomes two 0/1 columns, x marking the qubits with an X part and z those with a Z part. A CSS code’s Z checks contain only Z and respond only to the X part; its X checks respond only to the Z part. The quantum syndrome therefore splits in two: sZ = HZ x and sX = HX z, each a classical decoding problem like Chapter 1. Roffe et al. (2005.07016) put it this way: assuming uncorrelated X and Z errors, “the CSS code can be decoded independently as two classical codes”. Chapters 0 to 3 did one of the two halves.

4.2去极化噪声：先验怎么换算，分开译码丢掉了什么Depolarizing noise: converting the priors, and what separate decoding throws away

去极化噪声depolarizing noise：每个比特以概率 p 出错，出错时 X、Y、Z 各占三分之一，即各 p/3。是量子纠错里最常用的模型：每个比特以概率 p 出错，出错时 X、Y、Z 各占一份，各 p/3。X 部分出错的情形是 X 或 Y，概率 2p/3；Z 部分同理。所以分开译码时，每一半的先验是 pX = pZ = 2p/3，L0 = ln((1 − 2p/3)/(2p/3))。

Depolarizing noiseEach qubit is hit with probability p, and a hit is X, Y or Z with a third each, i.e. p/3 each. is the most common model in quantum error correction: each qubit is hit with probability p, and a hit is X, Y or Z, p/3 each. The X part is flipped when the error is X or Y, probability 2p/3; the same for the Z part. So with separate decoding each half has prior pX = pZ = 2p/3, L0 = ln((1 − 2p/3)/(2p/3)).

丢掉的是两部分之间的关联。p = 0.1 时：两部分同时出错就是 Y，概率 p/3 = 0.033；若两部分独立，只会是 (2p/3)² = 0.0044，相差 7.5 倍。换个说法：已知某比特的 X 部分出错，它的 Z 部分出错的概率是 P(Y)/(P(X) + P(Y)) = 1/2，远高于不知情时的 2p/3 = 0.067。分开译码的两个 BP 互不通气，用不上这条信息。能用上它的做法是把每个比特当成四值（I、X、Y、Z）来传消息：Panteleev 与 Kalachev 写道，对去极化信道，「it is better to use the non-binary version of the syndrome BP decoder ... which also takes into account the correlations between X and Z errors in qubits」，Poulin 与 Chung 用的也是这种四值 BP。本页只讲分开译码的二值 BP；第 6 章的实验台只放 X 错误，那是码容量模型，不存在这个问题。

What is thrown away is the correlation between the two parts. For p = 0.1: both parts flipped means Y, probability p/3 = 0.033; if the parts were independent it would be (2p/3)² = 0.0044, 7.5 times less. Put differently: given that a qubit’s X part is flipped, its Z part is flipped with probability P(Y)/(P(X) + P(Y)) = 1/2, far above the uninformed 2p/3 = 0.067. The two BPs of separate decoding do not talk to each other and cannot use this. The way to use it is to pass messages about each qubit as a four-valued variable (I, X, Y, Z): Panteleev and Kalachev write that for the depolarizing channel “it is better to use the non-binary version of the syndrome BP decoder ... which also takes into account the correlations between X and Z errors in qubits”, and Poulin and Chung use such a four-valued BP as well. This page covers only binary BP with separate decoding; the bench of Chapter 6 has X errors only, the code-capacity model, where the issue does not arise.

5.1为什么还要一步线性代数Why one more step of linear algebra

第 3、4 章的失败里，BP 的数并非没用。拐角错误上，比特 4、5、11、14 的 LLR 是 +0.38，其余都在 +2 以上：它清楚地指出了「嫌疑最大的四个」，只是没法在两个等价修复之间选边。缺的是一个保证 H c = s 的步骤，而「找一个满足 H c = s 的 c」是纯线性代数，一次高斯消元就够。OSD 的想法是让 BP 决定在哪里解：嫌疑大的比特放进方程组里当未知数，嫌疑小的直接设为 0。

In the failures of Chapters 3 and 4, BP’s numbers were not useless. On the corner error, qubits 4, 5, 11, 14 have LLR +0.38 and all the others are above +2: BP points plainly at “the four main suspects”, it just cannot pick a side between two equivalent repairs. What is missing is a step that guarantees H c = s, and “find a c with H c = s” is pure linear algebra, one Gaussian elimination. OSD’s idea is to let BP decide where to solve: suspicious qubits become unknowns in the system, unsuspicious ones are set to 0.

5.3OSD-0：保证症状清零，不保证成功OSD-0: the syndrome is guaranteed, success is not

0 阶 OSDOSD-0：非主元全设为 0，只解一次方程，不尝试任何改动。消元后每个主元比特直接等于它那一行的症状位。（OSD-0）把非主元全设为 0。消元后的矩阵里每个主元列只在自己那一行有 1，所以每个主元比特直接等于它那一行的症状位：右表给出 b1 = 1、b2 = 1、b3 = 0，再加 b4 = 0，修复 {b1, b2}，恰好是真实错误。换一个排序，让 b1 或 b2 排到最后，比如 b3, b4, b1, b2：主元依次是 b3、b4、b1，b2 成为非主元，OSD-0 得到 {b3, b4}，同样正确。只把 b4 提到最前（b4, b1, b2, b3）不够：非主元变成 b3，解仍是 {b1, b2}。这就是 OSD 在退化面前的作用：排序里先到的比特进基集，平局就此打破，交出等价修复中的一个。

Order-0 OSDOSD-0: set every non-pivot to 0 and solve once, trying no changes. After elimination each pivot qubit equals the syndrome bit of its row. (OSD-0) sets every non-pivot to 0. In the eliminated matrix each pivot column has a 1 only in its own row, so each pivot qubit simply equals its row’s syndrome bit: the right table gives b1 = 1, b2 = 1, b3 = 0, plus b4 = 0, repair {b1, b2}, which is the true error. An ordering that puts b1 or b2 last, say b3, b4, b1, b2, makes b3, b4, b1 the pivots and b2 the non-pivot, and OSD-0 returns {b3, b4}, equally right. Moving only b4 to the front (b4, b1, b2, b3) is not enough: the non-pivot becomes b3 and the solution is still {b1, b2}. That is what OSD does against degeneracy: qubits earlier in the ranking enter the basis set, the tie is broken, and one of the equivalent repairs comes out.

保证只有一条：只要症状确实来自某个错误（方程组有解），OSD 交出的 c 满足 H c = s。它不保证残留是稳定子。拐角错误上，BP 的排序以 4、5、11、14 开头（LLR 相同，按编号），主元依次收下 4、5、11，14 的列被前三列表出，成为非主元；OSD-0 交出 {5, 11}，是图 4.1 的修复 B，与真实错误 {4, 14} 同类，成功。Hamming 码（比特 7 出错）是另一种情形：BP 第 1 轮已经「收敛」到 {3, 5, 6, 7}，标准的 BP-OSD 在收敛时不调用 OSD，所以交出的仍是这个错误答案（3.1 节）。若拿第 1 轮的 LLR 强行跑 OSD-0，排序是 7, 3, 5, 6, 1, 2, 4，主元 7、3、5，解出 {7}，正确。

The guarantee is exactly one: as long as the syndrome really came from some error (the system has a solution), the c returned by OSD satisfies H c = s. It does not guarantee a stabilizer residual. On the corner error BP’s ranking starts with 4, 5, 11, 14 (equal LLRs, by number); the pivots accept 4, 5, 11, and 14’s column is expressed by those three and becomes a non-pivot; OSD-0 returns {5, 11}, repair B of Fig. 4.1, in the same class as the true error {4, 14}: success. The Hamming code (bit 7 flipped) is a different case: BP has already “converged” to {3, 5, 6, 7} in iteration 1, standard BP-OSD does not call OSD after convergence, and the wrong answer stands (§3.1). Running OSD-0 anyway with the iteration-1 LLRs gives the order 7, 3, 5, 6, 1, 2, 4, pivots 7, 3, 5, and the solution {7}, which is right.

Scoring. Under independent noise the probability of a repair c is proportional to ∏cj=1 pj/(1 − pj), so “most likely” means “smallest Σcj=1 ln((1 − pj)/pj)”, the score used on this page’s benches. When all pj are equal it is the weight times a constant: pick the lightest. The ldpc source and the supplement of Bravyi et al. (2308.07915) use Σ ln(1/pj); with equal p the ranking is identical, and with unequal p (circuit-level decoding, Chapter 7) the two are close when p is small. One more detail: Roffe et al. and ldpc set the non-pivots to 0 in OSD-0, while Panteleev and Kalachev set them to BP’s hard decisions. 5.5代价：高斯消元是延迟的瓶颈Cost: Gaussian elimination is the latency bottleneck

对 m × n 的矩阵做消元，每个主元要扫一遍所有行、每行最多 n 位，工作量大约 m · n · r 次位运算。qLDPC 码里 m、r 都与 n 成正比，所以是 O(n³)：n 翻倍，时间最多约 8 倍。Panteleev 与 Kalachev 写道，很多情形下 OSD-0 就够了，「the computational cost of the decoding is O(n³)」，一般的 OSD-w 是 O(n³ + n 2w)。ldpc 的文档说它的 OSD-0 用一种提前终止的消元（fast-solve），「terminates the Gaussian elimination as soon as the syndrome becomes linearly dependent on the columns eliminated up to that point」。

Eliminating an m × n matrix scans every row for each pivot, up to n bits per row, about m · n · r bit operations. In qLDPC codes m and r are proportional to n, so this is O(n³): doubling n multiplies the time by at most about 8. Panteleev and Kalachev write that in many cases OSD-0 is enough and “the computational cost of the decoding is O(n³)”, while general OSD-w costs O(n³ + n 2w). The ldpc documentation says its OSD-0 uses an early-stopping elimination (fast-solve) that “terminates the Gaussian elimination as soon as the syndrome becomes linearly dependent on the columns eliminated up to that point”.

和 BP 对比就看出问题所在：BP 每轮的工作量与边数成正比，每条边上的计算只用邻居的数，可以大规模并行；高斯消元每一步都要看整张矩阵，行与行之间有先后依赖，耗时还随症状变化。实时纠错要求译码跟上症状产生的速度，所以在 BP-OSD 里拖慢速度的通常是 OSD 这一步。第 7 章的几种新方法主要就是冲着它来的。

The comparison with BP shows the problem: BP’s work per iteration is proportional to the number of edges, and each edge uses only its neighbours’ numbers, so it parallelizes massively; each step of Gaussian elimination looks at the whole matrix, rows depend on earlier steps, and the time varies with the syndrome. Real-time correction needs decoding to keep pace with the syndromes, so in BP-OSD the step that usually sets the pace is OSD. Several newer methods in Chapter 7 target exactly this.

5.6排序为什么重要：对照 QEC-Bank 的 css-pivot 基线Why the ranking matters: the QEC-Bank css-pivot baseline

QEC-Bank 的译码器登记表里有一条不看任何概率的基线 css-pivot，原文：「Solves the X- and Z-syndrome linear systems by left-to-right GF(2) elimination with free variables fixed to zero; it scales polynomially but ignores likelihoods and degeneracy, so it is a reproducible baseline rather than a competitive decoder」。换成本章的话：它就是按编号顺序（而不是按 BP 的排序）做的 OSD-0。两者唯一的差别是列的顺序，所以把它们放在一起，就能看出 BP 的排序值多少。

The QEC-Bank decoder registry has a baseline, css-pivot, that ignores all probabilities: “Solves the X- and Z-syndrome linear systems by left-to-right GF(2) elimination with free variables fixed to zero; it scales polynomially but ignores likelihoods and degeneracy, so it is a reproducible baseline rather than a competitive decoder”. In this chapter’s words: it is OSD-0 in index order instead of BP’s ranking. The only difference between the two is the column order, so putting them side by side shows what BP’s ranking is worth.

  • Hamming 码，比特 7 出错。按编号，最先独立的三列是 1、2、4（第 3 列 = 第 1 列 + 第 2 列），于是比特 3、5、6、7 都被强制为 0。症状 (1, 1, 1) = 第 1、2、4 列之和，解出 {1, 2, 4}，重量 3；残留 {1, 2, 4, 7} 是一个码字，失败。按 BP 排序的 OSD-0 解出 {7}。
  • 环面码的拐角错误。按编号的主元是 0, 1, 2, 3, 4, 5, 9, 10，比特 11 和 14 被强制为 0，解出 {5, 9, 10}，重量 3，残留与 Z̄ 重叠奇数次，失败。按 BP 排序的 OSD-0 交出 {5, 11}，成功。4.4 节的清点里，BP 不收敛的 54 个两比特错误，OSD-0 全部成功，css-pivot 失败 20 个。
  • Hamming code, bit 7 flipped. By index the first three independent columns are 1, 2, 4 (column 3 = column 1 + column 2), so bits 3, 5, 6, 7 are forced to 0. The syndrome (1, 1, 1) is the sum of columns 1, 2, 4, giving {1, 2, 4}, weight 3; the residual {1, 2, 4, 7} is a codeword: failure. OSD-0 in BP’s ranking gives {7}.
  • The toric code’s corner error. The index-order pivots are 0, 1, 2, 3, 4, 5, 9, 10; qubits 11 and 14 are forced to 0, the solution is {5, 9, 10}, weight 3, and the residual overlaps Z̄ an odd number of times: failure. OSD-0 in BP’s ranking returns {5, 11}: success. In the count of §4.4, OSD-0 succeeded on all 54 two-qubit errors where BP did not converge, and css-pivot failed on 20.

两者的消元一模一样，差别全在「让哪些比特当未知数」：按编号，最可能出错的比特常常被排在非主元里、被强制设成 0，方程只好用一堆别的比特去凑症状，凑出来的修复更重，更容易落进错误的类。在步进器上选好预设后按「跳到结尾」，就能看到两个结果并排。

The elimination is identical; the whole difference is which qubits are made unknowns. In index order the most suspicious qubits often end up as non-pivots forced to 0, the system has to assemble the syndrome from other qubits, and the resulting repair is heavier and more likely to land in the wrong class. 关键想法Key idea

OSD = 按 BP 的 LLR 排序 + 沿排序做高斯消元 + 非主元设 0 解主元（OSD-0），更高阶再在排序靠前的非主元上试几种改动，按 Σ ln((1 − p)/p) 挑最轻的。它保证 H c = s，在等价修复之间选一个，但不保证选对类；代价是 O(n³) 的全局消元，是 BP-OSD 延迟的瓶颈。同样的消元按编号顺序做，就是 QEC-Bank 的 css-pivot 基线，它在本章两个例子上都失败。

OSD = sort by BP’s LLRs + Gaussian elimination along the ranking + non-pivots set to 0 and pivots solved (OSD-0); higher orders also try a few changes on the leading non-pivots and keep the lightest by Σ ln((1 − p)/p). It guarantees H c = s and picks one among equivalent repairs, but does not guarantee the right class; its cost, a global O(n³) elimination, is BP-OSD’s latency bottleneck. 6.1完整流程与 ldpc 的参数The full pipeline and the ldpc parameters

标准 BP-OSD 一次译码的全部步骤：由每个比特的出错概率 pj 算出先验 L0 = ln((1 − pj)/pj)；跑 BP，最多 max_iter 轮，每轮后做硬判决，满足 H c = s 就停下交出 c；若跑满仍不满足，用最后一轮的 LLR 排序，做 OSD（0 阶或更高阶），交出它的解。Roffe 等描述他们的实现时写道：「the OSD post-processing step is called when the BP algorithm fails to converge」。

One decoding with standard BP-OSD, complete: from each qubit’s flip probability pj compute the prior L0 = ln((1 − pj)/pj); run BP for at most max_iter iterations, taking a hard decision after each and stopping with c as soon as H c = s; if the decisions still miss the syndrome at the end, rank by the last LLRs, run OSD (order 0 or higher) and return its solution. 第 7 章Chapter 7

电路级译码：同一套方法，换一张矩阵Circuit-level decoding: the same method, a different matrix

真实的症状是电路测出来的，测量本身也会错，一个门的故障可以同时影响好几次测量。BP-OSD 在这里几乎不用改：只要把「比特 × 检查」的矩阵换成「故障机制 × 探测器」的矩阵，每一列带上自己的概率。这一章在最小的例子上把这张矩阵搭出来，再讲长时间运行时怎样按时间窗口译码，以及为什么延迟重要，最后列出几种新的后处理方法。 Real syndromes are measured by circuits, measurements themselves fail, and one faulty gate can affect several measurements at once. BP-OSD barely changes: replace the “qubit × check” matrix by a “fault mechanism × detector” matrix, with each column carrying its own probability. This chapter builds that matrix on the smallest example, then explains decoding a long run in time windows and why latency matters, and lists a few newer post-processing methods.

7.1探测器与探测器错误模型Detectors and the detector error model

测量会错时，单看某一轮的读数没有意义：一个读错的检查会在那一轮亮起、下一轮又「恢复」。所以比较的是相邻两轮的读数：探测器detector：若干次测量结果的一个奇偶组合，没有任何故障时它的值确定（通常是 0）。常见的是「同一条检查相邻两轮读数之差」。它为 1 就说它亮了。是若干次测量结果的一个奇偶组合，没有故障时它的值确定为 0，最常见的就是「同一条检查这一轮与上一轮读数之差」（《译码器 · 高中数学版》5.1 节讲过它在表面码上的样子）。然后把每一种可能的单个故障列出来，记下它会让哪些探测器翻转、会不会翻转我们关心的逻辑读数。这张表就是探测器错误模型detector error model, DEM：一张表，每一列是一种独立发生的故障机制，带一个概率，记录它翻转哪些探测器（症状）和哪些逻辑观测量。译码就是根据亮的探测器推断逻辑观测量是否被翻转。（DEM）。常用的纠错电路模拟软件 StimGidney（2021，arXiv:2103.02202）写的开源软件，能快速模拟纠错电路（反复测量检查的量子电路）并抽样出测量记录，还定义了 DEM 的文件格式。（Gidney 2021）的文档这样定义它：「A detector error model is a list of independent error mechanisms. Each error mechanism has a probability, symptoms (the detectors that the error flips), and frame changes (the logical observables that the error flips)」。

When measurements can fail, a single round’s readings mean little: a misread check lights up in that round and “recovers” in the next. So adjacent rounds are compared: a detectorA parity of several measurement outcomes whose value is fixed (usually 0) when nothing fails. The common one is “the change of one check between two consecutive rounds”. It is lit when it equals 1. is a parity of several measurement outcomes whose value is 0 when nothing fails, most often “this round’s reading of a check minus the previous round’s” (“Decoders · High-School Edition”, §5.1, shows it on the surface code). Then list every possible single fault and record which detectors it flips and whether it flips the logical readout we care about. That table is the detector error modelDEM: a table whose columns are independent fault mechanisms, each with a probability, recording which detectors (symptoms) and which logical observables it flips. Decoding means inferring from the lit detectors whether the logical observable was flipped. (DEM). Each error mechanism has a probability, symptoms (the detectors that the error flips), and frame changes (the logical observables that the error flips)”.

最小的例子：三比特重复码（只防比特翻转），两条检查 A = Z0Z1、B = Z1Z2，测两轮，最后把三个数据比特直接读出来。探测器六个：A1、B1 是第 1 轮的读数（初始奇偶已知为 0）；A2、B2 是第 2 轮与第 1 轮之差；A3、B3 是由最后读出的数据算出的奇偶与第 2 轮之差。逻辑观测量 L 是比特 0 的最后读数。故障机制：三个时刻（第 1 轮前、两轮之间、读出前）三个比特各可能翻转，共 9 种；两轮各两次测量各可能读错，共 4 种；再手工加一种关联故障 MAB1：第 1 轮的两个读数同时读错（例如两个辅助比特的读出互相串扰）。图 7.1 画出前两类故障各点亮哪些探测器。

The smallest example: the three-bit repetition code (protecting against bit flips only), checks A = Z0Z1 and B = Z1Z2, measured for two rounds, then the three data qubits are read out directly. Six detectors: A1, B1 are the round-1 readings (the initial parities are known to be 0); A2, B2 are round 2 minus round 1; A3, B3 are the parities computed from the final data readout minus round 2. The logical observable L is the final reading of qubit 0. Fault mechanisms: at three times (before round 1, between the rounds, before readout) each of the three qubits may flip, 9 in all; each of the two readings in each of the two rounds may be wrong, 4 in all; and one correlated fault added by hand, MAB1: both round-1 readings wrong at once (for instance through crosstalk between the two ancilla readouts). Fig. 7.1 shows which detectors the first two kinds light.

把 14 列排成矩阵，就是下面实验台里的表：行 = 6 个探测器，列 = 14 种机制，每列上方是它的概率（数据翻转与读错各 0.05，关联读错 0.02，都是为教学取的数），最下面一行 L 记录每种机制是否翻转逻辑观测量。除 MAB1 外每列至多两个 1：这个小码的普通故障都是「边」。MAB1 有四个 1，是一条超边（0.2 节）。匹配译码要求每列至多两个 1，所以只能把它拆成两条边 MA1 + MB1（Stim 的文件格式允许给一个机制附上「建议的分解」，把它写成几个更简单的机制之和）。拆开后，MAB1 的 0.02 并进这两条边，当作各自独立发生：每条边的概率变成「恰好一个来源发生」的 0.05 × (1 − 0.02) + 0.02 × (1 − 0.05) = 0.068。代价是模型再也表达不了「两个读错一起来」：它给「MA1 与 MB1 同时发生」的概率是 0.068 × 0.068 ≈ 0.0046，而真实模型光 MAB1 一项就有 0.02。BP-OSD 不需要拆：它把这一列原样放进矩阵，先验 L0 = ln(0.98/0.02)。

Arranging the 14 columns as a matrix gives the table in the bench below: rows = 6 detectors, columns = 14 mechanisms, each column headed by its probability (data flips and misreadings 0.05 each, the correlated misreading 0.02, all chosen for teaching), and the bottom row L recording whether each mechanism flips the logical observable. Apart from MAB1 every column has at most two ones: the ordinary faults of this small code are “edges”. MAB1 has four ones, a hyperedge (§0.2). Matching needs at most two ones per column, so it would have to split MAB1 into the two edges MA1 + MB1 (Stim’s file format lets a mechanism carry a “suggested decomposition” into simpler mechanisms). After the split, MAB1’s 0.02 is merged into those two edges as if it struck each of them independently: each edge’s probability becomes that of “exactly one source fires”, 0.05 × (1 − 0.02) + 0.02 × (1 − 0.05) = 0.068. The price is that the model can no longer say that the two misreads come together: it gives “MA1 and MB1 both happen” probability 0.068 × 0.068 ≈ 0.0046, while the true model has 0.02 from MAB1 alone. BP-OSD needs no split: the column goes into the matrix as it is, with prior L0 = ln(0.98/0.02).

7.2在 DEM 上跑 BP-OSDRunning BP-OSD on the DEM

译码问题的形状与第 0 章完全相同：矩阵 D（探测器 × 机制）代替 H，亮的探测器代替症状，未知数是「哪些机制发生了」，每个未知数的先验来自它那一列的概率。BP 在 D 的 Tanner 图上传消息，卡住时 OSD 沿排序解 D c = s。不同的只有最后一步：译码器要交出的不是一个修复，而是一个比特，「逻辑观测量翻没翻」，预测值是 L 行与解释 c 的点积（模 2）。所以这里的「类」就是 L 的值：两个解释只要预测同一个 L，效果就相同，哪怕它们本身差别很大。Bravyi 等把 BB 码的电路做成这样一张矩阵，称为「linearized noise model」，他们写道它「ignores possible cancellations between errors generated by two or more faulty operations」（两个故障互相抵消的情形被忽略，这类情形的概率是 O(p²)），并按 CSS 结构把 X、Z 分开，得到两张矩阵 DX、DZ：对 [[144,12,12]] 码测 12 轮，它们分别有 8857 列和 8785 列，每列至多 6 个 1、每行至多 35 个 1。

The decoding problem has exactly the shape of Chapter 0: the matrix D (detectors × mechanisms) replaces H, the lit detectors replace the syndrome, the unknowns are “which mechanisms happened”, and each unknown’s prior comes from its column’s probability. BP passes messages on D’s Tanner graph, and when it stalls OSD solves D c = s along the ranking. Only the last step differs: the decoder must return not a repair but one bit, “was the logical observable flipped”, predicted as the dot product (mod 2) of row L with the explanation c. So the “class” here is the value of L: two explanations that predict the same L have the same effect, however different they are. Bravyi et al. turn the BB-code circuits into such a matrix, calling it a “linearized noise model”, which “ignores possible cancellations between errors generated by two or more faulty operations” (cases where two faults cancel are ignored; they occur with probability O(p²)); following the CSS structure they split X and Z into two matrices DX, DZ: for the [[144,12,12]] code with 12 rounds these have 8857 and 8785 columns, with at most 6 ones per column and at most 35 per row.

实验台默认只发生了 MAB1，亮 A1、B1、A2、B2。穷举这个模型的 214 种组合：最可能的解释就是 MAB1 本身，在与读数相符的组合中占 0.766；逻辑观测量被翻转的后验概率 0.013。按「用 BP-OSD 译码」：BP 第 1 轮就满足了全部探测器，但它的逐位判决是 {X1@1, X1@2, MA1, MB1, MAB1}：三种解释各自点亮同样四个探测器，三个加起来（模 2）仍是那四个，所以满足 D c = s。这个解释很重，不是最可能的那个（与 3.1 节的 Hamming 码是同一种现象），但它预测 L = 0，与事实一致，所以这次译码成功。把模型切成「把 MAB1 拆开并进 MA1、MB1 两条边」：BP 第 5 轮收敛到 {MA1, MB1}，同样预测 L = 0，这也是拆开后的模型里最可能的解释（占 0.598）；可这个模型认为同样的读数下 L 被翻转的概率是 0.040，约为完整模型（0.013）的三倍。拆开超边丢掉的，就是这类概率上的准确性。

By default only MAB1 has happened on the bench, lighting A1, B1, A2, B2. Enumerating all 214 fault sets of this model: the most likely explanation is MAB1 itself, with a share of 0.766 among the sets matching the readings; the posterior probability that the observable was flipped is 0.013. Press “Decode with BP-OSD”: BP satisfies every detector in iteration 1, but its bit-by-bit decision is {X1@1, X1@2, MA1, MB1, MAB1}: three explanations each light the same four detectors, and all three together (mod 2) still light those four, so D c = s holds. This explanation is heavy and not the most likely one (the same phenomenon as the Hamming code of §3.1), but it predicts L = 0, which is the truth, so this decoding succeeds. Switch the model to “MAB1 split and merged into the MA1 and MB1 edges”: BP converges at iteration 5 to {MA1, MB1}, also predicting L = 0, and this is also the split model’s most likely explanation (share 0.598); but this model puts the probability that L was flipped, given the same readings, at 0.040, about three times the full model’s 0.013. Accuracy of probabilities like this is what splitting the hyperedge gives up.

7.3时间窗口，以及延迟为什么重要Time windows, and why latency matters

一次长时间的存储实验要测成千上万轮，整段历史一起译码既不可能（要等实验结束）也太大。常见的办法是滑动窗口译码sliding-window decoding：每次只译码最近 W 轮组成的一段（窗口），只把最早 F 轮的修正定下来（提交），然后窗口向后滑 F 轮。F < W 时相邻窗口重叠。：每次取最近 W 轮组成一个窗口，只把最早的 F 轮的结论定下来（提交），剩下的留给下一个窗口，然后窗口向后滑 F 轮（图 7.2）。Huang 与 Puri（2311.03307）说明这个做法最早由 Dennis 等为表面码提出，叫 overlapping recovery；他们在超图积码与提升积码上、现象学噪声（数据比特与测量会错，但测量电路本身不出错）下用 BP-OSD 做窗口译码，发现重叠窗口（F < W）的逻辑寿命显著长于不重叠的窗口（F = W）：例如在 [[625,25,8]] 超图积码上、p = 0.7% 时，W = F = 16 的寿命比 W = 3、F = 1 小近一个数量级。他们的摘要还拿滑动窗口与单发译码single-shot decoding：每测一轮，只用这一轮的读数译码一次并立刻修正，相当于 W = F = 1 的窗口。（每测一轮只用这一轮的读数译码一次，即 W = F = 1）比较，说窗口带来的改进「may not cost a larger decoding complexity」。正文的依据是：四份 [[625,25,8]] 码用 W = 4、F = 1 的窗口译码，每份码的每个窗口要处理的症状位数 W(n − k)/2 = 1200，与 [[2500,100]] 码单发译码一样多，逻辑寿命却更长。

A long memory experiment measures thousands of rounds, and decoding the whole history at once is both impossible (it would wait for the end) and too large. The usual method is sliding-window decodingDecode only the most recent W rounds (the window), commit the corrections for the earliest F rounds, then slide the window forward by F rounds. With F < W consecutive windows overlap.: take the most recent W rounds as a window, commit the conclusions for only its earliest F rounds, leave the rest to the next window, and slide forward by F rounds (Fig. 7.2). Huang and Puri (2311.03307) note that the method was first proposed by Dennis et al. for the surface code under the name overlapping recovery; using BP-OSD for window decoding of hypergraph-product and lifted-product codes under phenomenological noise (data qubits and measurements fail, but the measurement circuit itself does not), they find that overlapping windows (F < W) give a markedly longer logical lifetime than non-overlapping ones (F = W): for example, on the [[625,25,8]] hypergraph-product code at p = 0.7%, W = F = 16 gives a lifetime nearly ten times shorter than W = 3, F = 1. Their abstract also compares sliding windows with single-shot decodingDecoding once per measurement round, using only that round’s readings, and correcting at once: a window with W = F = 1. (decoding once per round from that round’s readings alone, i.e. W = F = 1) and says the window’s improvement “may not cost a larger decoding complexity”. The body backs this up: four copies of the [[625,25,8]] code decoded with W = 4, F = 1 process W(n − k)/2 = 1200 syndrome bits per copy and window, as many as single-shot decoding of the [[2500,100]] code, and still live longer.

延迟重要，是因为症状是按固定节奏源源不断产生的。译码一个窗口的时间若比产生它的时间长，没译完的数据就越积越多；需要根据译码结果决定下一步操作（比如逻辑门）时，处理器只能干等。5.5 节说过 BP 天然并行、OSD 的消元是全局的，所以 BP-OSD 的延迟主要花在 OSD 上。作为一个具体的量级，Wolanski 与 Barber 的摘要报告，他们的 ambiguity clustering 实现在 M2 CPU 上译码 gross 码每轮症状提取用 135 µs，并称这「already fast enough to keep up with neutral atom and trapped ion systems」（已经快到能跟上中性原子与离子阱系统）。

Latency matters because syndromes arrive continuously at a fixed pace. If decoding a window takes longer than producing it, undecoded data piles up; and when the next operation (a logical gate, say) depends on the decoding result, the processor can only wait. §5.5 noted that BP is naturally parallel while OSD’s elimination is global, so BP-OSD’s latency is spent mostly in OSD. For a concrete scale, Wolanski and Barber’s abstract reports that their ambiguity-clustering implementation decodes the gross code in 135 µs per round of syndrome extraction on an M2 CPU, which they call “already fast enough to keep up with neutral atom and trapped ion systems”.

下面几种方法都保留 BP，改的是 BP 之后（或 BP 本身）的做法。每条只写摘要里说的事；性能数字都只在摘要所说的码、噪声与比较对象下成立，本页没有复现它们。除 belief matching 外，它们都没有登记在 QEC-Bank 的译码器表里。

The methods below all keep BP and change what happens after it (or inside it). Each entry states only what the abstract says; performance numbers hold only for the codes, noise and comparisons the abstract names, and this page did not reproduce them. Except for belief matching, none is registered in the QEC-Bank decoder table.

  • 局部统计译码（localized statistics decoding, LSD），Hillmann 等，arXiv:2406.18655（未登记于 QEC-Bank）：不在整张矩阵上消元，而用一种并行的「on-the-fly elimination」找出、验证并求解译码图上的局部区域；摘要称它与最先进的译码器性能相当，同时降低了低于阈值区间的运行时复杂度。ldpc 软件包里有它的实现（BpLsdDecoder）。
  • 模糊聚类（ambiguity clustering, AC），Wolanski 与 Barber，arXiv:2406.14527（未登记于 QEC-Bank）：BP 之后把测量数据分成可以各自独立译码的簇；摘要报告在 BB 码、0.3% 电路级去极化噪声下比 BP-OSD 快至多 27 倍，准确度相当。
  • Relay-BP，Müller 等，arXiv:2506.01779（未登记于 QEC-Bank）：不用 OSD，只改进 BP 本身：给每个比特加上「无序的记忆强度」（3.3 节），并把多次这样的 BP 接力运行；摘要称它在 BB 码上明显优于 BP+OSD+CS-10，在表面码上与最小重量匹配相当，并且适合用 FPGA/ASIC两类专用硬件。FPGA（现场可编程门阵列）是可以反复重新接线的芯片；ASIC（专用集成电路）是为一个任务专门制造的芯片。它们都能做到比普通 CPU 低得多、也更稳定的延迟，这正是实时译码需要的。（可重新接线的芯片 / 专门制造的芯片，延迟都比 CPU 低）实现。
  • Belief matching，Higgott 等，arXiv:2203.04948（QEC-Bank 登记键 higgott2023beliefmatching）：用 BP 估计关联故障，再给匹配图重新赋权，最后仍用最小重量匹配；适用于每个故障最多点亮两个探测器（或可分解成这样）的码，比如表面码。摘要报告在他们的电路噪声模型下表面码阈值 0.94%，标准匹配是 0.82%。

  • Ambiguity clustering (AC), Wolanski and Barber, arXiv:2406.14527 (not registered in the QEC-Bank): after BP, the measurement data are divided into clusters that can be decoded independently; the abstract reports up to 27 times faster than BP-OSD with matched accuracy on BB codes under 0.3% circuit-level depolarizing noise.

关键想法Key idea

电路级译码把「比特 × 检查」换成「故障机制 × 探测器」：每列一个独立发生的机制，带自己的概率，记下它翻转的探测器和逻辑观测量。BP-OSD 原样工作，先验来自每列的概率；超边（一个故障点亮三个以上探测器）不必拆开。译码器最后只需猜对「逻辑观测量翻没翻」。长实验按重叠的时间窗口译码；OSD 的全局消元是延迟的主要来源，这是新方法的主攻方向。

Circuit-level decoding replaces “qubit × check” by “fault mechanism × detector”: each column is an independent mechanism with its own probability, recording the detectors and logical observables it flips. BP-OSD works unchanged, with priors from the column probabilities; hyperedges (a fault lighting three or more detectors) need not be split. In the end the decoder only has to guess “was the logical observable flipped”. Long experiments are decoded in overlapping time windows; OSD’s global elimination is the main source of latency and the main target of newer methods.

复盘整条推理链：译码 = 在满足 H c = s 的修复里选一个，使残留与每个 Z̄ 重叠偶数次；qLDPC 码的一个错误点亮三条以上检查，配对用不上（第 0 章）→ 「最可能的图样」与「每个比特最可能的取值」是两个问题，LLR 把贝叶斯的乘法变成加法（第 1 章）→ BP 的两条规则：检查用偏差之积，比特把消息相加；树上精确（第 2 章）→ 圈让证据被数两次，从过度自信到收敛到错误答案；min-sum、阻尼、串行调度（第 3 章）→ 量子码：CSS 分开译码，退化让逐比特判决交不出修复（第 4 章）→ OSD 按 BP 的排序做高斯消元，保证 H c = s，在等价修复里选边；按编号做同样的消元就差得多（第 5 章）→ ldpc 的参数、实验台与文献数字（第 6 章）→ 同一套方法用在探测器错误模型上（第 7 章）。

The chain of reasoning in one pass: decoding = choosing, among repairs with H c = s, one whose residual overlaps every Z̄ an even number of times; in qLDPC codes one error lights three or more checks and pairing is unavailable (Ch. 0) → “the most likely pattern” and “the most likely value of each bit” are different questions, and the LLR turns Bayes’ products into sums (Ch. 1) → BP’s two rules: checks multiply biases, bits add messages; exact on trees (Ch. 2) → cycles make evidence count twice, from overconfidence to converging on a wrong answer; min-sum, damping, the serial schedule (Ch. 3) → quantum codes: separate CSS decoding, and degeneracy that keeps bit-by-bit decisions from producing a repair (Ch. 4) → OSD does Gaussian elimination in BP’s order, guarantees H c = s and picks a side among equivalent repairs; the same elimination in index order does much worse (Ch. 5) → ldpc’s parameters, the bench and literature numbers (Ch. 6) → the same method on detector error models (Ch. 7).
