两张测量时间表
是不是同一回事 Are two measurement schedules
the same thing?

环面码这样的静态码，每一轮测同一份检查清单。蜂窝码这样的动态码，清单每一轮都换：第 0 轮测这 9 对比特，第 1 轮测那 9 对，第 2 轮再换一批，然后从头来。于是「码」不再是一份清单，而是一张时间表——测什么、按什么顺序。两张长得不一样的时间表，可能只是同一部电影从不同的一秒开始放，也可能是两部真正不同的电影；Atlas 里有一对时间表，每一轮单独看都合法、都一样像，整部放完却一张存 2 个逻辑比特、一张存 20 个。今天没有任何机器能判定「两张时间表是不是同一回事」，Atlas 卡片上只有人手写的一句「像」。这一篇讲这道开放问题是什么、Atlas 现在怎么凑合、为什么我们想要答案、一个合格的答案长什么样。 A static code such as the toric code measures the same list of checks every round. A dynamical code such as the honeycomb code changes the list every round: round 0 measures these 9 pairs of qubits, round 1 those 9, round 2 another batch, then it starts over. So the “code” is no longer a list but a schedule: what is measured, in what order. Two schedules that look different may be one film started at different seconds, or two genuinely different films; the Atlas holds a pair of schedules whose rounds are each legal and each equally plausible on their own, yet one stores 2 logical qubits after the whole film and the other 20. No machine today decides “are these two schedules the same thing?”; Atlas cards carry only a hand-written “alike”. This guide explains what the open problem is, how the Atlas copes today, why we want the answer, and what a qualifying answer looks like.

速查回顾：五条随身事实Quick recap: five facts to carry

这一篇只依赖 Toric Code 教程里的五件事，外加同系列《同一个码穿不同的衣服》的一个词。每一条都给出原处的链接。 This guide relies on five things from the toric-code guide, plus one word from “The same code in different clothes” in this series. Each comes with a link to where it was taught.

#事实Fact原处Where it was taught
1一条奇偶检查只问「这几个比特里 1 的个数是偶数吗」（两个比特时就是「这两位一样吗」），答案是 +1 或 −1。几个比特的奇偶 = 把它们的 0/1 加起来看奇偶，记号 ⊕（1 ⊕ 1 = 0，不进位）。A parity check only asks “is the number of 1s among these bits even?” (for two bits: “are they the same?”), answering +1 or −1. The parity of several bits = add their 0/1 values and look at odd/even, written ⊕ (1 ⊕ 1 = 0, no carry).2.3 节section 2.3
2两条泡利串要么对易、要么反对易：数它们在同一比特上放了两个都不是 I、且不同的字母的位置数，偶数则对易，奇数则反对易（碰撞定理）。Two Pauli strings either commute or anticommute: count the qubits where both carry a non-identity letter and the letters differ; even means commute, odd means anticommute (the collision theorem).4.2 节section 4.2

4一个稳定子码是一份两两对易的检查清单；n 个比特、r 条独立检查，存 k = n − r 个逻辑比特（前提是这些检查乘不出 −I，否则没有任何状态能同时通过它们。符号要算进去：X₁、X₂、−X₁X₂ 两两对易，三条相乘却是 −I。每条检查都是带 + 号的全 X 串或全 Z 串时自动满足：这样的串相乘不产生任何符号，乘出单位的只能是 +I。测量得到的瞬时稳定子群（1.2 节）里，每条检查带的是测得的符号，也自动满足：它的每条检查都被此刻的实际状态 |ψ⟩ 通过，若某个乘积等于 −I，就得有 −|ψ⟩ = |ψ⟩，不可能）。环面码 L = 3：n = 18，r = 16，k = 2。A stabilizer code is a list of pairwise commuting checks; n qubits and r independent checks store k = n − r logical qubits (provided no product of the checks equals −I, otherwise no state passes them all. Signs count here: X₁, X₂, −X₁X₂ commute pairwise, yet the three multiply to −I. The condition holds automatically when every check is an all-X or all-Z string with a + sign: multiplying such strings never produces a sign, so the only identity they can make is +I. It also holds for an instantaneous stabilizer group produced by measurement (1.2), where each check carries its measured sign: the actual current state |ψ⟩ passes every one of those checks, so a product equal to −I would force −|ψ⟩ = |ψ⟩, which is impossible). 第 1 章Chapter 1

这个问题用人话说是什么：同一个答案，不同的算法The problem in plain words: one answer, different procedures

先在 4 个比特上做一件小学算术：用两种不同的顺序算同一个奇偶，然后问自己「我凭什么说这两种顺序算的是同一个东西」——答案是几条重写规则。再把「顺序」换成「测量的先后」，「奇偶」换成「逻辑比特」，就是这道开放问题。 First do a piece of primary-school arithmetic on 4 bits: compute the same parity in two different orders, then ask yourself “on what grounds do I say the two orders compute the same thing?”; the answer is a few rewriting rules. Replace “order” by “order of measurements” and “parity” by “logical qubits”, and you have this open problem.

1.1玩具：四个比特的奇偶，三种算法The toy: the parity of four bits, three procedures

四个比特 a、b、c、d，每个是 0 或 1，要算它们的奇偶 a ⊕ b ⊕ c ⊕ d。一台只会两个数相加的机器，得分步做，而分步的顺序有很多种：

Four bits a, b, c, d, each 0 or 1; compute their parity a ⊕ b ⊕ c ⊕ d. A machine that can only add two numbers must proceed in steps, and the order of steps can vary:

算法甲：((a ⊕ b) ⊕ c) ⊕ dProcedure A: ((a ⊕ b) ⊕ c) ⊕ d
算法乙：(a ⊕ b) ⊕ (c ⊕ d)　　算法丙：(a ⊕ d) ⊕ (b ⊕ c)Procedure B: (a ⊕ b) ⊕ (c ⊕ d)　　Procedure C: (a ⊕ d) ⊕ (b ⊕ c)

记号：a、b、c、d = 四个比特的值（0 或 1）；括号 = 先算谁；⊕ = 不进位加法（第 0 章事实 1）。

Notation: a, b, c, d = the values of the four bits (0 or 1); parentheses = what is computed first; ⊕ = addition without carry (fact 1 of Chapter 0).

三种算法给出同一个答案吗？最笨的办法：把 a、b、c、d 的全部 2⁴ = 16 种取值代进去，逐个比。可行，但 40 个比特就是 2⁴⁰ ≈ 10¹² 种，笨办法就死了。聪明的办法是规则。⊕ 只满足两条：

Do the three procedures give the same answer? The dumb way: substitute all 2⁴ = 16 assignments of a, b, c, d and compare one by one. Feasible, but at 40 bits that is 2⁴⁰ ≈ 10¹² assignments and the dumb way dies. The clever way is rules. ⊕ obeys exactly two:

规则 R1（交换）：x ⊕ y = y ⊕ xRule R1 (commute): x ⊕ y = y ⊕ x
规则 R2（结合）：(x ⊕ y) ⊕ z = x ⊕ (y ⊕ z)Rule R2 (associate): (x ⊕ y) ⊕ z = x ⊕ (y ⊕ z)

记号：x、y、z = 任意三个 0/1 值（可以本身是括号里的算式）。R1 代入 x、y 的 4 种取值、R2 代入 x、y、z 的 8 种取值就能验证。

Notation: x, y, z = any three 0/1 values (each may itself be a bracketed expression). R1 is verified by the 4 assignments of x, y, and R2 by the 8 assignments of x, y, z.

现在从甲出发，一步只用一条规则：((a ⊕ b) ⊕ c) ⊕ d ＝R2 (a ⊕ b) ⊕ (c ⊕ d)，这是乙，一步到。再从乙到丙，六步：(a ⊕ b) ⊕ (c ⊕ d) ＝R2 a ⊕ (b ⊕ (c ⊕ d)) ＝R1 a ⊕ ((c ⊕ d) ⊕ b) ＝R2 a ⊕ (c ⊕ (d ⊕ b)) ＝R1 a ⊕ ((d ⊕ b) ⊕ c) ＝R2 a ⊕ (d ⊕ (b ⊕ c)) ＝R2 (a ⊕ d) ⊕ (b ⊕ c)，这是丙。每一步只用了 R1 或 R2 中的一条，请逐步核对。这条链就是「甲、乙、丙是同一回事」的证明：不需要代 16 种值，任何人都能一步一步检查。

Now start from A, one rule per step: ((a ⊕ b) ⊕ c) ⊕ d =R2 (a ⊕ b) ⊕ (c ⊕ d), which is B, in one step. From B to C, six steps: (a ⊕ b) ⊕ (c ⊕ d) =R2 a ⊕ (b ⊕ (c ⊕ d)) =R1 a ⊕ ((c ⊕ d) ⊕ b) =R2 a ⊕ (c ⊕ (d ⊕ b)) =R1 a ⊕ ((d ⊕ b) ⊕ c) =R2 a ⊕ (d ⊕ (b ⊕ c)) =R2 (a ⊕ d) ⊕ (b ⊕ c), which is C. Each step uses exactly one of R1, R2; check them one by one. This chain is the proof that A, B and C are the same thing: no 16 substitutions needed, and anyone can check it step by step.

要点Key idea

「两个算法是同一回事」有两种说法。按结果：所有输入都给同一个输出——要代入全部 2n 种输入。按规则：存在一条只用允许规则的改写链把一个变成另一个——一条链就是一份任何人能核对的证书。规则本身叫这门算术的语义semantics：规定「什么改写是合法的、什么算相等」的那套规则。R1、R2 是「重新排序、重新加括号」这类改写的语义（要处理 a ⊕ a = 0 之类的化简还得加规则）；本篇的开放问题要为「测量时间表」找一套语义。。板上原文 “as target semantics” 里的 semantics 就是这个意思：先定好允许哪些规则，再谈「相等」。

There are two ways to say “two procedures are the same thing”. By result: every input gives the same output; this needs all 2n inputs substituted. By rules: there exists a chain of rewrites, each an allowed rule, turning one into the other; the chain is a certificate anyone can check. The rules themselves are the semanticsThe set of rules fixing “which rewrites are legal, what counts as equal”. R1, R2 are the semantics of “reordering and re-bracketing” (simplifications such as a ⊕ a = 0 need further rules); this open problem seeks a semantics for “measurement schedules”. of the arithmetic. That is what “as target semantics” on the board means: first fix which rules are allowed, then talk about “equal”.

Two edges of different rounds sharing a vertex carry two different non-identity letters there (say X and Y for XX and YY), exactly 1 such position: they anticommute. By fact 3 of Chapter 0, measuring round 1 erases part of round 0's information. So where is the “code”? In the instantaneous stabilizer groupISG: all checks (and their products) the current state satisfies, each with a + or − sign. An ideal (error-free) measurement of a string P updates it in one of three ways: (a) P or −P is already in the group → the outcome is certain, fixed by that element's sign, and the group is unchanged; (b) P commutes with every current check but neither P nor −P is in the group → append P with the measured sign; the outcomes ±1 are equally likely; (c) P anticommutes with some current checks → pick one of them as pivot, multiply the other anticommuting ones by the pivot (they then commute with P), and replace the pivot by P with the measured sign; the count stays the same.: everything the state satisfies right now. The three cases (a), (b), (c) are in the tooltip (source: Hastings and Haah, arXiv:2107.02194, section 1.3); a six-qubit example below walks through them. The Atlas ISGTracker updates the group string by string with these rules and records the number r of independent checks after each round. For honeycomb L3x3, starting from an empty list, r runs:

r = 9, 12, 14, 16, 16, 16, …　　⇒　　dynamic_k = 18 − 16 = 2

Right after a round, each just-measured edge (say ZaZb, with its ±1 outcome known) locks its two qubits a and b into a two-dimensional subspace: two qubits have 4 basis states |00⟩, |01⟩, |10⟩, |11⟩, the check lets only 2 of them through (|00⟩ and |11⟩ for outcome +1), so the pair holds just one effective qubit. The first: the check becomes Zb, acting on b alone; the outcome pins b to |0⟩ or |1⟩, independent of everything else, which is what “split out” means. The other two: XaXb and Za, which commute with the check, become X and Z on qubit a, so the effective qubit lives on a, with the old XaXb as its X and Za as its Z. (All three can be checked by multiplying 4 × 4 matrices; this guide's check script does so.) The just-measured edges form a perfect matching, so these gates act on pairwise disjoint pairs and can all run at once: that is depth one, one parallel layer of gates. Local Clifford = each gate touches only two neighbouring qubits and maps Pauli strings to Pauli strings. After the layer, each just-measured edge leaves one effective qubit, and on those effective qubits the hexagon operators are the checks of a toric code on a coarser hexagonal lattice (the paper's section 1.4, Fig. 2). This step is not the single-qubit relabelling of fact 5 in Chapter 0: a relabelling touches one qubit and keeps the qubit count, whereas each gate here acts on a pair and splits one of its qubits out.

改写规则怎样对待这些结果？论文给了三点。第一，把所有 b 都固定下来，剩下的就是一张普通 ZX 图（“for any fixed outcome configuration, we recover a plain vanilla ZX network”）。第二，融合和变色这两条规则对带经典输出的点照样成立，② 两腿即导线则不能用在带输出的点上（论文把 ② 叫 identity 规则，原话：“apart from the identity rule, these rules also work with the proposed extension”）。第三，两个同色、都带输出的点融合时，结果只剩一个输出，取值 b₁ ⊕ b₂；论文说只有当我们只关心这两个结果的奇偶时才能这样合（“A merge is possible, as long as only the joint parity of the outcomes is relevant”）。也就是说，改写保住的不是每一个单独的结果，而是一些结果的奇偶组合：无错时取值固定、用来抓错的那些组合（论文叫 checks，对应「探测器」），以及读出逻辑信息的那些组合。两张时间表的图即使量子部分相同，挂着的结果也可以不同；论文自己就说，它的融合式网络与电路式网络「严格说并不等价，因为挂着一组更大、不同的经典结果」（“strictly speaking, not equivalent … because there is a larger and different set of classical outcomes attached”），两者要靠结果组合之间的对应才连得起来。所以「两张图能互相改写」本身还不是时间表等价：还得说清一张表的每个检查组合、每个逻辑读数对应到另一张表的哪个组合。另外，Atlas 的 Schedule(n, rounds) 是一份固定的轮次列表，下一轮测什么不看结果，结果只决定瞬时稳定子群里各条检查的符号；若将来的时间表要按结果选下一步，图里还得画进这种分支，本篇不讨论。

How do the rewrite rules treat these outcomes? The paper makes three points. First, fixing every b leaves an ordinary ZX diagram (“for any fixed outcome configuration, we recover a plain vanilla ZX network”). Second, fusion and colour change still hold for dots with a classical output, while ② (two legs is a wire) may not be used on such a dot (the paper calls ② the identity rule: “apart from the identity rule, these rules also work with the proposed extension”). Third, when two dots of the same colour, both with outputs, are fused, only one output is left, with value b₁ ⊕ b₂; the paper allows this only when just the parity of the two outcomes matters (“A merge is possible, as long as only the joint parity of the outcomes is relevant”). So rewriting preserves not each individual outcome but certain parity combinations of outcomes: those that are fixed when nothing goes wrong and are used to catch errors (the paper's checks, the “detectors”), and those that read out logical information. Two schedules' diagrams may agree in their quantum part and still carry different outcomes; the paper itself says its fusion-based network is “strictly speaking, not equivalent” to the circuit-based one “because there is a larger and different set of classical outcomes attached”, and the two are linked through a correspondence between outcome combinations. So “the two diagrams can be rewritten into each other” is not yet schedule equivalence: one must also say which combination in the other schedule each check combination and each logical readout corresponds to. Also, an Atlas Schedule(n, rounds) is a fixed list of rounds: what is measured next never depends on an outcome, and outcomes only set the signs of the checks in the instantaneous stabilizer group. A future schedule that chose its next step from an outcome would need that branching drawn into the diagram too; this guide does not treat it.

4.2什么算解决What counts as solved

一台程序，输入两个 Schedule 对象，做三步：把每张时间表画成带经典输出的 ZX 图（4.1 节）；判定两张图能否用允许的规则互相改写到（或者把每张图改写到一个典范形再比较）；输出「同一回事 / 不是」，并在答「是」时交出改写链——像 1.1 节那六步一样，每一步只用一条规则，任何人（或任何程序）都能逐步核对——外加一张结果对照表：一张表的每个检查组合、每个逻辑读数，对应到另一张表的哪个结果组合（4.1 节末段说了为什么缺它不行）。若还要说两张表的 d 相同，还得先规定故障模型，并交出保持权重的故障对应（3.2 节表格第三行）。答「不是」时最好也给理由：一个在规则下不变、却在两张图上取值不同的量（比如 dynamic_k 的 2 与 20）。有了这台程序，第 2 章那六段 curated 的话中「像」的部分就能变成一条条有证书的 derived 边；「不是」的部分（逐帧像、整体不像）也各有凭据。

A program that takes two Schedule objects and does three things: draw each schedule as a ZX diagram with classical outputs (4.1); decide whether the two diagrams can be rewritten into each other by the allowed rules (or rewrite each into a canonical form and compare); output “the same thing / not”, and when it says “yes” hand over the rewrite chain, like the six steps of 1.1, each step one rule, checkable step by step by any person or program, together with an outcome table: which outcome combination in the other schedule each check combination and each logical readout corresponds to (the end of 4.1 says why it cannot be left out). To claim also that the two schedules have the same d, one must first fix a fault model and hand over a weight-preserving fault correspondence (row three of the table in 3.2). When it says “no” it should ideally give a reason: a quantity invariant under the rules that differs between the two diagrams (such as dynamic_k, 2 versus 20). With this program, the “alike” parts of Chapter 2's six curated paragraphs become derived edges with certificates, and the “not” parts (alike frame by frame, not as a whole) each get their evidence.

dynamic_k 相同只是不否决；P 和 Q 是同一回事吗？在「理想测量、没有测错」的意义上是，而且能证：Q 的两轮里所有串两两对易，对易的测量先后顺序不影响结果（第 0 章事实 3：只有反对易的串才会抹掉信息），所以把 Q 的第 0 轮和第 1 轮合成一轮就是 P。相同的是对齐的完整周期结束时的状态：Q 每做完一个周期（第 2t、2t + 1 两轮），它的瞬时稳定子群和逻辑算符与 P 做完第 t 轮时相同，符号也按对应的读数对得上：Q 第 2t 轮的 9 个星读数和第 2t + 1 轮的 9 个面读数，与 P 第 t 轮的 18 个读数一一对应（同一条检查对同一条检查），两边的瞬时稳定子群都由对应的读数定符号。中间时刻并不相同：Q 第 0 轮刚结束时群里只有 8 条独立的星（r = 8），P 此时已有 16 条。这是一条「对易的轮次可以合并或拆开」的规则，作用和 1.1 节的 R1 一样；在 ZX 语言里它对应一条允许的局部改写，本篇不画。诚实地说，这只证明了两张表是同一个码，没有证明它们是同一个容错对象：一旦测量本身会出错，P 一轮读 18 个数、Q 一轮只读 9 个，探测器和能抓住的错误可能不同，那一层本篇没有碰。反过来看 honeycomb：它三轮之间反对易，这条规则用不上，这正是它的等价问题比环面码难得多的原因。

Equal dynamic_k merely fails to veto; are P and Q the same thing? In the sense of “ideal measurements, no measurement errors”, yes, provably: within Q's two rounds all strings commute pairwise, and the order of commuting measurements does not affect the result (fact 3 of Chapter 0: only anticommuting strings erase information), so merging Q's rounds 0 and 1 into one round gives P. What agrees is the state at matched ends of complete cycles: each time Q completes a cycle (rounds 2t and 2t + 1), its ISG and logical operators equal P's after round t, with signs matching under the outcome correspondence: Q's 9 star readings in round 2t and 9 plaquette readings in round 2t + 1 correspond one to one to the 18 readings of P's round t (each check to the same check), and on both sides the ISG takes its signs from the corresponding readings. In between they differ: right after Q's round 0 the group holds only 8 independent stars (r = 8), while P already has 16. This is a rule, “commuting rounds may be merged or split”, playing the role of R1 in 1.1; in ZX language it corresponds to one allowed local rewrite, not drawn here. Honestly, this proves only that the two schedules are the same code, not the same fault-tolerant object: once measurements themselves can fail, P reads 18 numbers per round and Q only 9, so the detectors and the errors caught may differ; that layer is untouched here. Look back at honeycomb: its three rounds anticommute, this rule does not apply, and that is exactly why its equivalence problem is so much harder than the toric code's.

5.2沙盘：两族检查互不打扰Sandbox: the two families do not disturb each other

在下面 L = 3 的环面沙盘上放几个 Z 错误，再放几个 X 错误。Z 错误只让星报警，X 错误只让面报警；两族检查各看各的，谁先测、谁后测都不改变对方的读数。这就是 5.1 节那条「对易的轮次可以合并」在眼前的样子。想象把星的读数和面的读数分在两轮里读，或一轮里一起读——报警的图案一样。

On the L = 3 toric sandbox below, place a few Z errors, then a few X errors. Z errors make only stars fire, X errors only plaquettes; each family watches its own, and which is measured first changes nothing in the other's readout. That is 5.1's rule “commuting rounds may be merged” before your eyes. Imagine reading the stars and the plaquettes in two separate rounds or together in one: the alarm pattern is the same.

尾声Epilogue

两条规则、一部电影、一句人写的「像」Two rules, one film, one hand-written “alike”

回放一遍。四个比特的奇偶有很多种算法，R1、R2 两条规则把它们连成一家：一条改写链就是一份证书，不必代入 2n 种输入。一张测量时间表是「一轮一轮的泡利串」，静态码是周期 1 的特例；蜂窝码周期 3，每轮 9 条两比特测量，r 序列 9、12、14、16 停住，dynamic_k = 2。两张表是不是同一回事，不能逐帧判断：按颜色分轮与按方向分轮每一帧都合法，整部放完却是 2 对 20。Atlas 今天对动态码的机器比对只落在一帧的字节和 dynamic_k 这个不变量上，说「相同」时不可信；honeycomb 卡片上六段 curated 视图与一条 curated 边全靠人写。合格的答案是一台按 ZX 规则改写并交出改写链的程序；难在改写没有方向、语义还在被定、要保持的对象自己还没算全——open-research。环面码的 P 与 Q 是高中水平能完整证明的一对「同一个码」（理想测量意义下）；蜂窝码不是，因为它的三轮反对易。

Replay. The parity of four bits has many procedures, and the two rules R1, R2 tie them into one family: a rewrite chain is a certificate, with no need to substitute 2n inputs. A measurement schedule is “Pauli strings round by round”, a static code being the period-1 special case; the honeycomb code has period 3, 9 two-qubit measurements per round, an r sequence 9, 12, 14, 16 that then stops, dynamic_k = 2. Whether two schedules are the same thing cannot be judged frame by frame: grouping by colour and grouping by direction are legal in every frame, yet the whole film ends at 2 versus 20. Today the Atlas machine comparison for dynamical codes rests on the bytes of one frame and the invariant dynamic_k, untrustworthy when it says “same”; the honeycomb card's six curated views and one curated edge are all written by people. A qualifying answer is a program that rewrites by the ZX rules and hands over the chain; the difficulty is that rewriting has no direction, the semantics is still being fixed, and the object to be preserved is itself not fully computed: open-research. The toric code's P and Q are a pair of “the same code” (under ideal measurements) fully provable at high-school level; the honeycomb code is not, because its three rounds anticommute.
