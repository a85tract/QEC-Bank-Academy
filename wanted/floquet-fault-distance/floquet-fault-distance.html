码距该怎么数 When the checks change every round,
how do you count distance?

环面码的码距是一个静态的数：所有检查一次写定，d = 能骗过全部检查、又改写逻辑信息的最轻泡利串的重量，L × L 环面码 d = L。有一类码不是这样运转的：它每一轮测不同的检查，按一张时间表轮换，任何一轮的检查清单都不是「这个码」，整部电影才是。这时「最少几个故障能溜过去」必须在电影里数——故障可以是某一时刻翻了一个比特（空间方向），也可以是某次读数读错了（时间方向），两种方向要分开数。QEC-Bank 的蜂窝码条目在 d 那一栏写的是 ?，不是因为没人算过，而是因为把静态快照的码距填进去会「给错误的对象贴上机器的确定性」。这一篇讲这道开放问题是什么、QEC-Bank 现在怎么凑合、为什么我们想要答案、一个合格的答案长什么样。 The distance of the toric code is a static number: all checks are fixed once, d = the weight of the lightest Pauli string that fools every check yet rewrites the logical information, and the L × L toric code has d = L. One class of codes does not run this way: it measures different checks every round, rotating through a schedule, and no single round's check list is “the code”; the whole film is. Then “the fewest faults that slip through” must be counted inside the film. A fault may be a bit flipped at some moment (the space direction) or a reading misread (the time direction), and the two directions are counted separately. The QEC-Bank honeycomb entry shows ? in its d column, not because nobody has computed anything, but because filling in the distance of a static snapshot would “attach machine certainty to the wrong object”. This guide explains what the open problem is, how the QEC-Bank copes today, why we want the answer, and what a qualifying answer looks like.

这个问题用人话说是什么：在一部电影里数故障The problem in plain words: counting faults inside a film

三个比特、六轮测量。先让每一轮问同样的两个问题（静态码），再让问题按时间表轮换（动态码），亲手算出每一轮的读数、每一个「探测器」的值，再数「最少几个故障能既不被发现、又改写信息」。最后给这些东西命名，念板上的原文。 Three bits, six rounds of measurement. First let every round ask the same two questions (a static code), then rotate the questions on a schedule (a dynamical code); compute by hand each round's reading and each “detector” value, then count “the fewest faults that both escape detection and rewrite the information”. Finally name these things and read the board's wording.

The last two rows are detectorsThe XOR of two consecutive readings of the same check, equal to 1 only when “the answer changed”. Section 5.1 of “Decoders · High-School Edition” introduced it to cope with readings that are themselves wrong: a single misread affects one round and lights a pair of detectors in time; a real bit flip changes the reading from that round onward and lights the detector once.: they do not ask “what is the reading” but “did the answer change since last time” (section 5.1 of “Decoders · High-School Edition”). Why ask this way? Because real measurements can be misread: if in round 1 c1 should read 0 but reads 1 while the bits did not move, then D1(1) = 1 and D1(2) = 1; the reading bounces back next round and the detector lights as a pair along time, whereas a genuine flip keeps the reading at 1 from then on and lights the detector once, in the round of the flip. In plain words: detectors turn “a bit went wrong” and “a reading went wrong” into two patterns of different shape.

Three things to notice. One: the flip happens before round 2, but round 2 asks c3 = b1 ⊕ b3, which does not involve b2, so the reading stays 0; only round 3's c1 sees it. In a dynamical code a fault stays hidden until the next “relevant question” is asked, with a delay set by the schedule. Two: two detectors light (S(3), S(4)), exactly one for each of the two checks containing b2, like the two endpoints of a chain in the toric code (fact 4 of Chapter 0), except that the “endpoints” sit at different times. Three: if instead of a flip the reading of round 4 were wrong once, then c(4) = 1 with everything else 0, S(4) = 1, and three rounds later S(7) would be 1 too; the other half of that pair falls outside this six-round table. In plain words: the same fault draws different patterns in a static and in a dynamical code; the schedule fixes the pattern's shape, and the observation window decides whether the whole pattern can be seen.

玩具的边界Where the toy ends

这个玩具是经典的：c1、c2、c3 三条检查两两对易，先问哪条都不会破坏别的答案，「轮换」只是节省了每轮的测量次数。真正的 Floquet 码不是这样。QEC-Bank 蜂窝码条目（honeycomb，本条 yaml 里 related 的唯一一项）的卡片描述原文：“A period-three dynamical stabilizer memory made only from weight-two Pauli measurements on a honeycomb torus. Edge operators are fixed as XX, YY, or ZZ by direction, while a plaquette three-coloring partitions them into three perfect-matching rounds. The code is the ordered schedule and its outcome-dependent instantaneous stabilizer group, not any one static set of mutually commuting edge checks; after startup that group carries two toric-code logical qubits.” 关键在于不同轮的检查反对易（第 0 章事实 2）：测了这一轮，上一轮的一部分答案就被抹掉，「此刻状态满足哪些检查」这份清单——瞬时稳定子群ISG, instantaneous stabilizer group：此刻状态满足的全部检查（含乘积）。每测一条新串就按规则更新。两张测量时间表篇 1.2 节给出了更新规则与蜂窝码 L3x3 的秩序列 9, 12, 14, 16, 16, …（ISG）——每轮都在变。它的 n = 2·L1·L2，L3x3 实例 n = 18，稳定后独立检查 16 条，剩 k = 2（两张测量时间表篇 1.2 节照抄了 QEC-Bank 推导页的秩序列 9, 12, 14, 16）。本篇不重复这部分；玩具只负责演示「读数分布在时间里、探测器要跨轮比较」这一件事，这一件事在经典玩具和蜂窝码里是一样的。

This toy is classical: the three checks c1, c2, c3 commute pairwise, asking one never spoils another's answer, and “rotating” merely saves measurements per round. Real Floquet codes are not like that. The card description of the QEC-Bank honeycomb entry (honeycomb, the only item under related in this yaml) reads: “A period-three dynamical stabilizer memory made only from weight-two Pauli measurements on a honeycomb torus. Edge operators are fixed as XX, YY, or ZZ by direction, while a plaquette three-coloring partitions them into three perfect-matching rounds. The code is the ordered schedule and its outcome-dependent instantaneous stabilizer group, not any one static set of mutually commuting edge checks; after startup that group carries two toric-code logical qubits.” The crux is that checks of different rounds anticommute (fact 2 of Chapter 0): measuring this round erases part of last round's answers, and the list “which checks does the state satisfy right now”, the instantaneous stabilizer groupISG: all checks (and products) the current state satisfies, updated by a rule at every new measured string. Section 1.2 of the schedule-equivalence guide gives the update rule and the rank profile 9, 12, 14, 16, 16, … of honeycomb L3x3. (ISG), changes every round. Its n = 2·L1·L2; the L3x3 instance has n = 18, 16 independent checks once settled, leaving k = 2 (section 1.2 of the schedule-equivalence guide copies the rank profile 9, 12, 14, 16 from the QEC-Bank derivation page). This guide does not repeat that part; the toy's only job is to show “readings are spread over time and detectors compare across rounds”, which is the same in the classical toy and in the honeycomb code.

1.3在电影里数故障：空间型与时间型Counting faults in the film: spacelike and timelike

静态码的码距问：最轻的「骗过所有检查、又改写信息」的错误有多重。把它搬进电影里，先约定什么叫一个故障fault：电影里的一个基本坏事件。本篇只允许两种：某个比特在某一轮之前翻转（记 (d, i, t)）；某一轮的读数被读反（记 (m, t)）。每个故障算 1。：要么「第 t 轮之前比特 bi 翻转」，要么「第 t 轮的读数读反」，各算 1。一组故障未被发现，指整部电影里所有探测器都是 0；一组故障改写了信息，指电影结束时把三个比特读出来、按多数票译码，得到 1 而不是制备时的 0。这里要分清两样东西：比特的物理状态可能是 110 这种不合法的状态（既不是 000 也不是 111），而译码输出只看多数票，110 译成 1，所以也算改写了信息；失败看的是译码输出，不要求物理状态恰好落到 111。故障距离fault distance：所有「未被发现且改写信息」的故障集合中最小的故障数。它是电影里的量，依赖时间表、探测器定义和观察窗口；静态码距是它在「一轮、完美读数」这个特例下的值。就是这类集合里最少的故障数。两种方向的故障画在同一张时空图上：

The distance of a static code asks how heavy the lightest error is that “fools every check yet rewrites the information”. To carry this into the film, first agree what a faultOne elementary bad event in the film. This guide allows two kinds: bit b_i flips before round t (written (d, i, t)); the reading of round t is inverted (written (m, t)). Each counts 1. is: either “bit bi flips before round t” or “the reading of round t is inverted”, each counting 1. A set of faults is undetected if every detector in the whole film is 0; it rewrites the information if, when the three bits are read out at the end of the film and decoded by majority vote, the result is 1 instead of the prepared 0. 空间型（spacelike）故障集合：在同一时刻翻三个比特（图中琥珀色）。之后每条检查的读数都不变（1 ⊕ 1 = 0 ⊕ 0 = 0），所有探测器为 0，而 000 变成了 111——多数票翻了。3 个故障，未被发现且改写信息。有没有更少的？翻两个比特，第三个就和它们不同，含第三个比特的两条检查迟早会被问到并读出 1，所以不行——前提是窗口两头都「封口」：开头的读数和制备值 000 比较，结尾把三个比特读出来和最后的读数比较。不封口时会有漏洞：在第 0 轮之前翻 b1、b2（等于一开始就制备成了 110），读数从头到尾都不变，没有任何探测器可比；结尾读出 110，多数票译成 1，2 个故障就溜过去并改写了信息；在最后一两轮之前翻转，相关的问题再也等不到，也是 2 个就够（见下面的记号段）。空间型故障距离 = 3，等于重复码的静态码距——不奇怪，这类故障就是「某一帧里的一条静态错误」。

Spacelike fault sets: flip all three bits at one moment (amber in the figure). Every check's reading is unchanged afterwards (1 ⊕ 1 = 0 ⊕ 0 = 0), every detector is 0, and 000 has become 111: the majority flipped. 3 faults, undetected and rewriting. Any fewer? Flip two bits and the third differs from them; the two checks containing the third bit will sooner or later be asked and read 1, so no — provided both ends of the window are “sealed”: the first readings are compared with the prepared 000, and at the end the three bits are read out and compared with the last readings. Unsealed, there are loopholes: flip b1 and b2 before round 0 (as if 110 had been prepared) and the readings never change, so no detector has anything to compare; the final readout 110 decodes to 1, and 2 faults slip through and rewrite the information; flip bits before the last round or two and the relevant question never comes, again 2 suffice (see the notation paragraph below). Spacelike fault distance = 3, equal to the repetition code's static distance, unsurprisingly, since such a fault set is “a static error in one frame”.

时间型（timelike）故障集合：只碰读数，不碰比特（图中蓝色）。在轮换时间表里，把 c1 在 t = 0 和 t = 3 两次都读反：c(0) = 1，c(3) = 1，S(3) = 1 ⊕ 1 = 0，六轮里没有任何探测器亮。2 个故障就没被发现。同样的窗口换成 1.1 节的静态码：要让 D1(1) 到 D1(5) 全为 0，c1 的六次读数必须全部读反——6 个故障。同一部电影的长度，时间表不同，时间方向上「溜过去」的代价从 6 降到 2。（这里轮换表用的是 1.2 节的 S 探测器；4.3 节会看到 S 漏了一条约束，把探测器找全后轮换表的数是 4，仍然小于 6。）这类故障集合改写的不是比特，而是从读数得出的推断。在 Floquet 码里，量子信息始终编码在数据比特上，不在读数里；但读出逻辑值要用的逻辑算符带一个 ± 号，这个号由此前的测量结果决定。Hastings 与 Haah（arXiv:2107.02194，1.4 节）写明：外逻辑算符（把 honeycomb 码看成子系统码时，不属于它的稳定子群的那一组逻辑算符）的符号取决于检查结果的历史，必须把这些符号记下来，才能正确推断逻辑值（卡片也说瞬时稳定子群是 “outcome-dependent”，即依赖测量结果的）。读反一次，记下的符号就可能是错的，逻辑值的推断跟着错，所以它们可能是逻辑故障——推导页把未被探测的故障分成三种情形，只有「改变逻辑类」那一种才算，另一种只是改写了读数与稳定子代表元（「此刻这组检查各自答 +1 还是 −1」的记录）而没动编码信息，分辨它们需要一次可观测量的计算；在经典玩具里比特没动、多数票不变，它们只演示「未被发现」这一半——这是玩具替代不了的部分，本篇只做描述。

Timelike fault sets: touch only readings, never bits (blue in the figure). In the rotating schedule, misread c1 at both t = 0 and t = 3: c(0) = 1, c(3) = 1, S(3) = 1 ⊕ 1 = 0, and no detector lights in six rounds. 2 faults go undetected. The same window with the static code of 1.1: for D1(1) through D1(5) to be all 0, all six readings of c1 must be inverted, 6 faults. Same film length, different schedule, and the cost of “slipping through” along time drops from 6 to 2. (The rotating schedule here uses the S detectors of 1.2; section 4.3 shows that S misses one constraint, and with a complete detector set the rotating number is 4, still below 6.) What such sets rewrite is not a bit but the inference drawn from the readings. In a Floquet code the quantum information stays encoded in the data qubits, not in the readings; but the logical operators used to read out the logical value carry a ± sign fixed by earlier measurement outcomes. Hastings and Haah (arXiv:2107.02194, section 1.4) state that an outer logical operator (one of the logical operators that is not in the stabilizer group of the honeycomb code viewed as a subsystem code) carries a sign that depends on the history of check outcomes, and that these signs must be recorded to infer the logical value correctly (the card, too, calls the instantaneous stabilizer group “outcome-dependent”). One misread can make a recorded sign wrong, and the inferred logical value goes wrong with it, so they can be logical faults there — the derivation page sorts undetected faults into three cases, and only the one that flips a logical class counts; another merely rewrites outcomes and stabilizer representatives (the record of “which of the current checks answer +1 and which −1”) without touching the encoded information, and telling them apart needs an observable calculation; in the classical toy the bits do not move and the majority stands, so they only illustrate the “undetected” half. This is the part the toy cannot replace, and this guide only describes it.

The page's last sentence fixes the shape of the answer: “The result should be keyed by circuit and observation window, not placed as a family-wide scalar on the honeycomb check matrix.” In plain words: the answer is not one number hung under the name “honeycomb” but records of the form “this circuit, this window → these two numbers”. A qualifying answer = an engine that takes the seven inputs above and emits such records, plus the records it produces on honeycomb L3x3 and L6x6.

4.2难度词：hard-engineering，「知道怎么做，但要做很多」The difficulty word: hard-engineering, “known how, but much to build”

Wanted 板只用两个难度词：open-research（没人知道怎么做，例如标准译码器篇）和 hard-engineering。本条是后者，理由在卡片和推导页上都能读到：定义有了——blackwell2025distance（Blackwell 与 Haah，“The code distance of Floquet codes”，2025）给出了「最轻的未被发现且非无害的时空错误」这个定义；具体电路算过——gidney2021fault 为明确的电路构造了周期探测器图和匹配问题，卡片把它列为 standard 译码器；结构验证有了——QEC-Bank 引擎已经能算 snapshot k 和 dynamic_k，Lean Complete v1（在机器证明检查器 Lean 里的一套核对）能核对每一轮内的检查两两对易，以及「行空间复现」：从空的稳定子群出发重放时间表，过了启动阶段、在某个快照时刻（不晚于第六个周期末）记下当时的瞬时稳定子群，再放一个周期，回到周期里的同一位置时，它能乘出的全部检查与快照时是同一个集合。比较时不看 ± 号：带正号还是负号取决于每次的测量结果，每个周期都可能不同，所以带符号的稳定子并不重复，重复的只是去掉符号后的那张清单（「行空间」就是把每条检查写成一行 0/1、不记符号后，这些行能加出的全部行）。Blackwell 与 Haah（arXiv:2510.05549）也是这样处理的：他们把 S 与 −S 视为一类来讨论周期性，并证明这种周期性只在启动阶段之后成立。缺的是把这些接成一台通用引擎：从时间表生成电路（第 2 项）、生成探测器与 DEM（第 4 项）、实现无害商（第 6 项）、在非图状的 DEM 上搜索（第 7 项），并对每张电路、每个窗口重跑。人话：路线图是清楚的，每一步都有人做过局部版本；难在把七项全部做成机器、做通用、做到能重放。

The board uses two difficulty words only: open-research (nobody knows how, e.g. the standard-decoders guide) and hard-engineering. This item is the latter, for reasons readable on the card and the derivation page: the definition exists: blackwell2025distance (Blackwell and Haah, “The code distance of Floquet codes”, 2025) defines “the lightest undetectable non-benign spacetime error”; explicit circuits have been analysed: gidney2021fault built the periodic detector graphs and matching problem for explicit circuits, and the card lists it as the standard decoder; structural verification exists: the QEC-Bank engine already computes snapshot k and dynamic_k, and Lean Complete v1 (a suite of checks in the proof checker Lean) verifies that the checks within each round commute, and “row-space recurrence”: replay the schedule starting from the empty stabilizer group, record the instantaneous stabilizer group at a snapshot time after the start-up stage (no later than the end of the sixth period), run one more period, and at the same point of the cycle the set of all checks it can multiply out is the same set as at the snapshot. Signs are ignored in the comparison: whether a check carries + or − depends on each round's measurement outcomes and can differ from period to period, so the signed stabilizers do not repeat; only the list with signs stripped does (the “row space” is what you get by writing each check as a row of 0s and 1s, with no sign, and taking every row those rows can add up to). Blackwell and Haah (arXiv:2510.05549) treat it the same way: they discuss periodicity with S and −S counted as one, and prove that this periodicity holds only after the start-up stage. What is missing is wiring these into one general engine: circuits from schedules (item 2), detectors and DEM (item 4), the benign quotient (item 6), search over non-graphlike DEMs (item 7), rerun per circuit and per window. In plain words: the roadmap is clear and every step has a partial version somewhere; the difficulty is making all seven items into a machine, general, and replayable.

4.3玩具就能演示的三个难处Three difficulties the toy alone already exhibits

一、答案依赖探测器有没有找全。把 1.2 节的探测器换成 T(t) = c(t) ⊕ c(t+1) ⊕ c(t+2)——三轮连读的异或，因为 c1 ⊕ c2 ⊕ c3 = (b1 ⊕ b2) ⊕ (b2 ⊕ b3) ⊕ (b1 ⊕ b3) = 0 恒成立，这也是一条合法的探测器。用它，1.3 节那对读反（t = 0 与 t = 3）会被抓住（T(0) = T(1) = T(2) = T(3) = 1），不封口窗口里最轻的未被发现的读反集合变成 4 个（例如 t = 0, 1, 3, 4）。同一张时间表、同一个窗口，S 型探测器给 2，T 型给 4。T 为什么多抓到东西？因为 T(t) ⊕ T(t+1) = c(t) ⊕ c(t+3) = S(t+3)：每条 S 都是两条相邻 T 的异或，S 能查出的，T 全都查得出；反过来，T(0) = c(0) ⊕ c(1) ⊕ c(2) 不是任何几条 S 的异或，是 S 漏掉的一条约束。可以数出来：比特不动时，六次读数只能是 000000、101101、110110、011011 四种之一（由三个比特是什么决定），这四种构成 6 位里一个 2 维的集合，所以读数之间一共有 6 − 2 = 4 条独立约束；T(0) 到 T(3) 正是这 4 条，S(3) 到 S(5) 只占其中 3 条。探测器找全时，一组读反不被发现，当且仅当它本身就像上面某一种合法的读数序列，而最轻的非零一种有 4 个 1，这就是 4 的来历。所以 2 对 4 不是「同一组约束换个写法，码距就变了」（换一组能互相异或出来的探测器，这个数不会变），而是 S 型探测器漏了一条约束，给出的 2 偏低。板上把 “Detector design” 写在最前面，是因为探测器要先找全，算出的码距才可信。

One: the answer depends on whether the detector set is complete. Replace the detector of 1.2 with T(t) = c(t) ⊕ c(t+1) ⊕ c(t+2), the XOR of three consecutive readings; since c1 ⊕ c2 ⊕ c3 = (b1 ⊕ b2) ⊕ (b2 ⊕ b3) ⊕ (b1 ⊕ b3) = 0 always, this is a legitimate detector too. With it, the misread pair of 1.3 (t = 0 and t = 3) is caught (T(0) = T(1) = T(2) = T(3) = 1), and the lightest undetected set of misreads in the unsealed window becomes 4 (e.g. t = 0, 1, 3, 4). Same schedule, same window: S-type detectors give 2, T-type give 4. Why does T catch more? Because T(t) ⊕ T(t+1) = c(t) ⊕ c(t+3) = S(t+3): every S is the XOR of two neighbouring T's, so whatever S detects, T detects too; conversely T(0) = c(0) ⊕ c(1) ⊕ c(2) is not the XOR of any S's, so it is a constraint S misses. You can count it: with the bits left alone, the six readings can only be one of 000000, 101101, 110110, 011011 (depending on what the three bits are), a 2-dimensional set inside the 6-bit strings, so the readings obey 6 − 2 = 4 independent constraints; T(0) to T(3) are exactly those 4, while S(3) to S(5) cover only 3 of them. With a complete detector set, a set of misreads goes undetected exactly when it looks like one of those legitimate reading sequences itself, and the lightest nonzero one has four 1s: that is where the 4 comes from. So 2 versus 4 is not “the same constraints written another way changed the distance” (swapping to detectors that are XORs of each other leaves the number unchanged); the S-type detectors miss one constraint, and their 2 is too low. That is why the board writes “Detector design” first: the detector set must be complete before the distance means anything.

二、答案依赖窗口和边界。1.3 节的记号段：加上「开头与 0 比较、结尾读出比特」，时间型的 2 和 6 都消失；去掉结尾读出，空间型从 3 掉到 2。这就是第 1 项和第 4 项里 “conventions” 与 “temporal boundaries” 的分量，也是推导页坚持 “keyed by circuit and observation window” 的原因。

Two: the answer depends on the window and its boundaries. The notation note of 1.3: add “compare the start with 0, read out the bits at the end” and the timelike 2 and 6 vanish; drop the final readout and spacelike falls from 3 to 2. That is the weight carried by “conventions” and “temporal boundaries” in items 1 and 4, and the reason the page insists on “keyed by circuit and observation window”.

三、搜索会撞上同一堵墙。玩具的六轮窗口里有 3 × 6 = 18 个可能的翻转故障和 6 个读反故障，共 24 个，故障集合有 224 ≈ 1.7 × 107 种，本篇的核对脚本按重量从小到大穷举到 4 就停了，没有问题。蜂窝码 L3x3 一个周期只有 27 次两比特测量，但电路级的故障字母表里每次测量有多个位置，再乘上窗口长度，候选数很快回到大码的码距篇 1.4 节那种 2n 的增长；而 DEM 一旦不是图状的（有的故障亮三个以上探测器），就没有匹配那样的多项式捷径。人话：玩具上一秒钟能穷举完的事，在真实电路上重新变成「排除所有更轻候选」的老问题。

Three: the search hits the same wall. The toy's six-round window has 3 × 6 = 18 possible flip faults and 6 misread faults, 24 in all, hence 224 ≈ 1.7 × 107 fault sets; this guide's check script enumerated by increasing weight and stopped at 4 without trouble. Honeycomb L3x3 has only 27 two-qubit measurements per period, but a circuit-level fault alphabet has several locations per measurement, multiplied by the window length, and the candidate count soon returns to the 2n growth of section 1.4 of the distance-for-large-codes guide; and once the DEM is not graphlike (some faults light three or more detectors) there is no polynomial shortcut like matching. In plain words: what a toy exhausts in a second becomes, on a real circuit, the old problem of “exclude every lighter candidate”.

记号：T(t) = 第 t、t+1、t+2 三轮读数的异或；224 = 24 个故障各「有或无」的组合总数；27 = 蜂窝码 L3x3 一个周期内的测量次数（3 轮 × 9 条，出自两张测量时间表篇 1.2 节的公式行）。「4 个」与「1.7 × 107」是本篇算的。

Notation: T(t) = the XOR of the readings of rounds t, t+1, t+2; 224 = all “present or absent” combinations of 24 faults; 27 = measurements per period of honeycomb L3x3 (3 rounds × 9, from the formula line of section 1.2 of the schedule-equivalence guide). The “4” and “1.7 × 107” were computed for this guide.

尾声Epilogue

一部电影、两个方向、七项输入、一个问号One film, two directions, seven inputs, one question mark

回放一遍。静态码每轮问同样的问题，码距是一帧里的数；动态码按时间表轮换问题，「码」是整部电影，故障要在电影里数。探测器问「和上次比变了吗」，把比特翻转与读反画成不同形状。故障距离是「未被发现且改写信息」的最小故障数，空间型与时间型分开报：3 比特玩具里空间型 3（两头封口）；时间型方向玩具只能数「最少几个读反不被发现」，在不封口的六轮窗口里轮换表 2、静态表 6，换成三轮探测器则 4。QEC-Bank 的蜂窝码卡片 n、k、dynamic_k 都是 verified，d 是问号并登记为指向本条的 claim_gap，因为推导页写明「快照的码距是错误的对象」。合格的答案是一台接受七项输入、按电路和窗口输出两个数的引擎；难度是 hard-engineering，因为定义（blackwell2025distance）、具体电路的探测器（gidney2021fault）、结构验证（dynamic_k）都已存在，缺的是把它们接成通用、可重放的机器。

Replay. A static code asks the same questions every round and its distance is a number in one frame; a dynamical code rotates its questions on a schedule, “the code” is the whole film, and faults must be counted inside it. Detectors ask “did the answer change since last time” and draw bit flips and misreads as different shapes. The fault distance is the smallest number of faults that are “undetected and rewrite the information”, reported separately for the spacelike and timelike directions: in the 3-bit toy, spacelike 3 (both ends sealed); in the timelike direction the toy can only count “the fewest misreads that go undetected”: in an unsealed six-round window, rotating 2 and static 6, or 4 with three-round detectors. On the QEC-Bank honeycomb card n, k and dynamic_k are verified while d is a question mark registered as a claim_gap pointing at this item, because the derivation page states that “the snapshot's distance is the wrong object”. A qualifying answer is an engine taking seven inputs and emitting two numbers per circuit and window; the difficulty is hard-engineering, since the definition (blackwell2025distance), detectors for explicit circuits (gidney2021fault) and structural verification (dynamic_k) all exist, and what is missing is wiring them into a general, replayable machine.

[[n, k, d]]双方括号，读「n k d 码」Double brackets, read “an n k d code”n 个物理比特、k 个逻辑比特、码距 d；蜂窝码 L3x3 是 [[18, 2, ?]]。n physical qubits, k logical qubits, distance d; honeycomb L3x3 is [[18, 2, ?]].
L, L1, L2读「L」Read “L”环面码的边长（n = 2L²）；蜂窝环面的行数与列数（n = 2·L1·L2）。Side length of the toric code (n = 2L²); rows and columns of the honeycomb torus (n = 2·L1·L2).
bi,　cj,　c(t)读「比特 i、检查 j、第 t 轮的读数」Read “bit i, check j, the reading of round t”玩具的三个比特；三条检查 c1 = b1 ⊕ b2，c2 = b2 ⊕ b3，c3 = b1 ⊕ b3；轮换表里第 t 轮唯一的读数。The toy's three bits; the three checks c1 = b1 ⊕ b2, c2 = b2 ⊕ b3, c3 = b1 ⊕ b3; the single reading of round t in the rotating schedule.
⊕读「异或」或「模 2 加」Read “XOR” or “add mod 2”0⊕0 = 1⊕1 = 0，0⊕1 = 1；「一样吗」的算术形式。0⊕0 = 1⊕1 = 0, 0⊕1 = 1; the arithmetic form of “are they the same?”.
t,　W读「轮次、窗口长度」Read “round, window length”t = 0, 1, 2, … 是轮次；W 是观察窗口的轮数（本篇 6；不叫 T，因为 T(t) 是 4.3 节的探测器）。t = 0, 1, 2, … is the round; W is the number of rounds in the observation window (6 here; not called T, since T(t) is the detector of 4.3).
Dj(t),　S(t),　T(t)读「探测器」Read “detector”Dj(t) = cj(t) ⊕ cj(t−1)（静态表）；S(t) = c(t) ⊕ c(t−3)（轮换表，同一条检查）；T(t) = c(t) ⊕ c(t+1) ⊕ c(t+2)（轮换表，三轮连读）。理想电影里全为 0。Dj(t) = cj(t) ⊕ cj(t−1) (static); S(t) = c(t) ⊕ c(t−3) (rotating, same check); T(t) = c(t) ⊕ c(t+1) ⊕ c(t+2) (rotating, three consecutive readings). All 0 in an ideal film.
(d, i, t),　(m, t)读「翻转故障、读反故障」Read “flip fault, misread fault”第 t 轮之前比特 bi 翻转；第 t 轮的读数被读反。各算 1。Bit bi flips before round t; the reading of round t is inverted. Each counts 1.
sp(t),　Dp(t) = sp(t) sp(t−Δ)读「六边形 p 的推断符号，与它的探测器」Read “the inferred sign of hexagon p, and its detector”QEC-Bank 推导页里蜂窝码探测器的写法：sp(t) 由若干轮的边读数乘出，Δ（读「德尔塔」）是与几轮前比较的延迟。是本篇 S(t) 的蜂窝码版本。The QEC-Bank derivation page's form of the honeycomb detector: sp(t) is a product of edge readings from several rounds, Δ (read “delta”) the delay compared with. The honeycomb version of this guide's S(t).
dynamic_k,　r读「动态 k、秩」Read “dynamic k, rank”r = 某轮结束时瞬时稳定子群里独立检查的条数（L3x3：9, 12, 14, 16, 16, …）；dynamic_k = n − 稳定后的 r = 2。r = independent checks in the ISG at the end of a round (L3x3: 9, 12, 14, 16, 16, …); dynamic_k = n − the settled r = 2.
d = ?读「d 未登记」Read “d not registered”条目页对「claims 里没有 d」的写法；蜂窝码两个实例都是。The entry page's rendering of “no d among the claims”; both honeycomb instances.
⌊W/3⌋,　224读「W 除以 3 向下取整、2 的 24 次方」Read “W over 3 rounded down, 2 to the 24”练习 1(c) 的答案；玩具窗口里故障集合的总数 ≈ 1.7 × 107。The answer of exercise 1(c); the number of fault sets in the toy window, ≈ 1.7 × 107.

术语Term白话定义Plain definition
静态码 / 动态码（Floquet 码）static / dynamical (Floquet) code每轮问同样的检查 / 按时间表轮换检查，整部电影才是码。The same checks every round / checks rotating on a schedule, the whole film being the code.
时间表（schedule）scheduleSchedule(n, rounds)：n 个比特加一份逐轮的检查清单；静态码是周期 1 的特例。Schedule(n, rounds): n qubits plus a round-by-round list of checks; a static code is the period-1 special case.
瞬时稳定子群（ISG）instantaneous stabilizer group (ISG)此刻状态满足的全部检查；每测一条新串就更新。All checks the current state satisfies; updated at every new measurement.
探测器（detector）detector若干次读数的异或，理想电影里恒为 0；「和上次比变了吗」。An XOR of several readings, always 0 in an ideal film; “did it change since last time?”.
故障（fault）fault电影里的一个基本坏事件：比特翻转或读数读反。One elementary bad event in the film: a bit flip or a misread.
故障距离（fault distance）fault distance「未被发现且改写信息」的故障集合的最小大小；依赖时间表、探测器、窗口。The smallest size of an “undetected and rewriting” fault set; depends on schedule, detectors, window.
空间型 / 时间型（spacelike / timelike）spacelike / timelike故障集合的两个方向：某一时刻翻比特 / 沿时间读反。板上要求分开报。The two directions of a fault set: bits flipped at one moment / misreads along time. The board requires them reported apart.
无害（benign）历史benign history未点亮探测器、也不改变编码信息的故障历史；码距只数非无害的。A fault history lighting no detector and changing no encoded information; the distance counts only non-benign ones.
探测器错误模型（DEM）detector error model (DEM)「每种故障点亮哪些探测器、是否改写逻辑、概率多大」的清单。The list of “which detectors each fault lights, whether it rewrites the logical, with what probability”.
图状 / 非图状（graphlike / beyond-graphlike）graphlike / beyond-graphlike每种故障至多亮两个探测器（可用匹配）/ 有的亮三个以上（要搜索）。Every fault lights at most two detectors (matching applies) / some light three or more (search needed).
时间边界（temporal boundaries）temporal boundaries窗口开头与制备值、结尾与读出比特怎么比较；两头都比较叫「两头封口」。改变它就改变数字。How the window's start compares with the prepared value and its end with the read-out bits; comparing at both ends is called “sealing both ends”. Changing it changes the number.
快照码距（snapshot distance）snapshot distance把某一帧当静态码算出的码距；QEC-Bank 拒绝把它填进 d。The distance of one frame treated as a static code; the QEC-Bank refuses to file it under d.
claim_gapsclaim_gaps卡片字段：登记某个属性缺席并指向负责的 Wanted 项。A card field registering an absent property and pointing at the responsible Wanted item.
