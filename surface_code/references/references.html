「参考文献」侧面看起来只是一张书单，其实是这个条目的地基：Atlas 里凡不是机器重算出来的数字——阈值、硬件结果、逻辑门的代价、各种表示的对应关系——都必须指向一个注册过的文献键。本教程先教你读懂一个键（dennis2002topological 这样的字符串是怎么造出来、登记在哪、被谁引用），再按「它回答什么问题」把 39 条文献分成八组，逐条说明它为什么在 Atlas 里、被哪个侧面引用；最后带你从一个具体的数字出发，一步一步追到原始论文。 The References facet looks like a reading list; it is really this entry's foundation. Every number in the Atlas that is not machine-recomputed, thresholds, hardware results, gate costs, cross-model correspondences, must point at a registered bibkey. This guide first teaches you to read a key (how a string like dennis2002topological is formed, where it is registered, who cites it), then sorts all 39 references into eight groups by the question each answers, saying for every one why it is in the Atlas and which facet cites it; finally it walks from one concrete number, step by step, back to the original paper.

第 1 章Chapter 1

怎样读一份带来源键的文献表How to read a provenance-keyed bibliography

普通论文的参考文献编号 [12] 只告诉你「去文末找第 12 条」。Atlas 的文献键做得更多：它是一个全局唯一、可被程序检查的名字，条目里的每一句「文献说……」都必须挂在某个键上，而每个键又必须在一份受控注册表里有完整的元数据。 An ordinary paper's “[12]” only says “look up item 12 at the end”. An Atlas bibkey does more: it is a globally unique, machine-checkable name; every “the literature says …” inside the entry must hang on a key, and every key must have complete metadata in one controlled registry.

1.1一个键的解剖Anatomy of a key

看 dennis2002topological：第一作者姓（dennis）+ 年份（2002）+ 标题里一个有辨识度的词（topological）。这个约定让键既好念又几乎不会撞车。所有键登记在 registry/refs.yaml，每条至少有 id、title、authors、year、url（arXiv 链接）。注册表还允许 alias_of：当一次文献调研用了另一个键指向同一篇论文，就登记为别名而不是第二篇——例如 bravyi2024high 是 bravyi2024bicycle 的别名，roffe2020bposd 是 roffe2020decoding 的别名，bluvstein2023logical 是 bluvstein2024logical 的别名。表面码条目的 39 个键全部在注册表中，元数据齐全；Atlas 的参考文献页也没有把任何一条标为「metadata pending」。

Take dennis2002topological: first author's surname (dennis) + year (2002) + one distinctive title word (topological). The convention keeps keys pronounceable and nearly collision-free. All keys are registered in registry/refs.yaml, each with at least id, title, authors, year, url (an arXiv link). The registry also allows alias_of: when a literature sweep used a different key for the same paper, it is recorded as an alias rather than a second paper. Thus bravyi2024high is an alias of bravyi2024bicycle, roffe2020bposd of roffe2020decoding, bluvstein2023logical of bluvstein2024logical. All 39 keys of the surface entry are in the registry with complete metadata; the Atlas references page marks none of them “metadata pending”.

键key = 姓surname + 年份year + 标题词title word　·　dennis + 2002 + topological

1.2键住在哪里Where the keys live

在条目源文件 atlas/surface/card.yaml 里，键以三种方式出现。其一，条目级的 refs 列表：39 个键按顺序排好——这就是 Atlas 参考文献页显示的那张表，一条不多一条不少。其二，侧面记录里的 refs 列表：每个译码器、每个实现、每个表示、每条关系、每个分类标签都带自己的几个键；例如译码器 mwpm 在「码容量」噪声下的那条记录引用 dennis2002topological, wang2003confinement, higgott2022pymatching。其三，逻辑操作用 origin: {kind: claimed, ref: KEY}：每个门只挂一个键，并且诚实地写着 claimed——这些操作的可行性来自论文，Atlas 没有重算。有 11 个键（如 bravyi2009nogo、aharonov1997fault）只出现在条目级列表里，不绑定任何侧面记录：它们支撑的是直觉文（intuition.md）里的论证，而不是某条可执行的断言。下一章会把这一点标在每条文献旁。

In the entry source atlas/surface/card.yaml, keys appear in three ways. First, the entry-level refs list: the 39 keys in order; this is exactly the table the Atlas references page shows, no more, no less. Second, refs lists inside facet records: every decoder, realization, representation, relation and category tag carries its own few keys; the mwpm decoder record under code-capacity noise, for instance, cites dennis2002topological, wang2003confinement, higgott2022pymatching. Third, logical operations use origin: {kind: claimed, ref: KEY}: one key per gate, honestly labelled claimed, because these operations' feasibility comes from papers and the Atlas has not recomputed it. Eleven keys (such as bravyi2009nogo and aharonov1997fault) appear only in the entry-level list and are bound to no facet record: they support arguments in the intuition essay (intuition.md) rather than any executable assertion. The next chapter marks this beside each reference.

1.3为什么每条论断都要指向一个键Why every claim points at a key

因为 Atlas 把「机器算出来的」和「文献说的」严格分开。推导页 pedagogy/derivations.md 专门列出哪些数由机器算、哪些由文献说（Atlas 叫它 provenance split，来源分界）：n、k、CSS 结构和两个小实例的码距是机器验证的（n = 物理比特数，k = 逻辑比特数，d = 码距，定义见 Toric Code 教程 4.4 节与4.6 节）；L=5 的码距下界由定理与文献承担、上界由一个可重跑的随机见证承担，所以那个实例标 bounded（L 为格子边长）；而阈值与硬件结果「不是一张裸校验矩阵的性质」，它们永远是文献论断，旁边必须写全噪声模型与译码器。于是每个不能重算的数字都需要一个键——没有键的数字在 Atlas 里不允许存在。下表是条目里出现的全部来源词汇：

Because the Atlas keeps “what the machine computed” strictly apart from “what the literature says”. The derivations page pedagogy/derivations.md lists which numbers a machine computes and which the literature asserts (the Atlas calls this the provenance split): n, k, the CSS structure and the two small exact distances are machine-verified (n = physical qubits, k = logical qubits, d = distance; definitions in the toric-code guide, §4.4 and §4.6); the L=5 distance has a theorem-and-literature lower bound and a rerunnable seeded witness for the upper bound, so that instance is marked bounded (L is the lattice side); thresholds and hardware results “are not properties of a bare check matrix” and remain literature claims with the noise model and decoder written beside them. Hence every number that cannot be recomputed needs a key; a keyless number is not allowed in the Atlas. The table lists every provenance word the entry uses:

关键想法Key idea

一个文献键是一份契约：「这个数字不是我算的，是这篇论文说的，你可以去核对。」下面 39 条文献，每一条都要回答同一个问题——它在 Atlas 里替谁作证。

A bibkey is a contract: “I did not compute this number; this paper states it, and you may check.” Each of the 39 references below must answer the same question: whose witness is it in the Atlas?

2.1奠基与构造：这个码是什么Foundations and construction: what the code is

  • Alexei Yu. Kitaev, "Fault-tolerant quantum computation by anyons" (2003)
    kitaev2003fault · 环面码及其任意子图像的原始出处（任意子：把警报看成可以在格子上移动的「粒子」，星报警与面报警是两种任意子）。被关系 same_bulk_phase_as → toric 引用（见关系导读第 3 章）。The original source for the toric code and its anyon picture (anyons: alarms viewed as “particles” that move on the lattice; star alarms and plaquette alarms are two kinds). Cited by the relation same_bulk_phase_as → toric (see the relations guide, Chapter 3).
  • Sergey B. Bravyi and Alexei Yu. Kitaev, "Quantum codes on a lattice with boundary" (1998)
    bravyi1998quantum · 毛 / 光边界的首次构造，平面表面码由此诞生。表示阶梯（Atlas 用 R1 到 R5 五级台阶，把同一个码写成越来越抽象的几种语言，见表示阶梯导读）R2「同调」视图的 curated 来源；同调视图把检查看成「取边界」。平面码里，一条 Z 串（Z 放在一串边上）要不触发任何星检查，端点只能落在毛边上（横边悬空、没有顶点的那两侧）；论文把这种端点全在边界上的链叫相对闭链。这样的串若等于若干面检查的乘积，例如绕一块面的小环，就是平凡的，不改变存下的信息；从一条毛边连到对面毛边的串不是检查的乘积，它才是逻辑算符。相差若干检查乘积的两条串算同一类（图 2.1）。First construction of rough/smooth boundaries; the planar surface code is born here. Curated origin of the R2 “homological” view on the representation ladder (the Atlas's five rungs R1 to R5 that write the same code in increasingly abstract languages; see the representation-ladder guide); the homological view reads checks as “taking a boundary”. On the planar code a Z string (Z on a chain of edges) trips no star check only if its endpoints lie on the rough edges (the two sides where horizontal edges end free, with no vertex); the paper calls such a chain, all of whose endpoints are on the boundary, a relative cycle. If such a string equals a product of face checks, like a small loop around one face, it is trivial and leaves the stored information alone; a string from one rough edge to the opposite one is not a product of checks, and it is the logical operator. Two strings that differ by a product of checks belong to the same class (Figure 2.1).
  • Eric Dennis, Alexei Kitaev, Andrew Landahl, and John Preskill, "Topological quantum memory" (2002)
    dennis2002topological · 引用最多的键：分类标签「topological」的来源、码容量译码器 mwpm 的 10.9%（最优译码）、R5「统计力学」视图（随机键 Ising 模型：把「最优译码能否成功」换算成一个带随机正负耦合的磁性模型是否有序，阈值就是它的相变点）、以及与环面码的关系。The most-cited key: source of the “topological” category tag, of the code-capacity mwpm record's 10.9% (optimal decoding), of the R5 “statistical-mechanics” view (random-bond Ising model: whether optimal decoding succeeds is translated into whether a magnet with random positive and negative couplings orders, and the threshold is its phase transition), and of the toric relation.
  • Héctor Bombín and Miguel A. Martín-Delgado, "Homological Error Correction: Classical and Quantum Codes" (2007)
    bombin2007homological · 把「检查 = 取边界；端点只落在相应类型边界上的串叫相对闭链，相差检查乘积的串算同一类；逻辑串是其中不是检查乘积的那些，即非平凡的相对同调类（检查乘积本身是平凡类，什么也不改）」讲成一般理论。与 bravyi1998quantum 共同支撑 R2 同调视图。Turns “checks = taking boundaries; strings whose endpoints lie only on the boundary of the matching type are relative cycles, and strings that differ by products of checks count as one class; the logical strings are the relative cycles that are not products of checks, i.e. the nontrivial relative-homology classes (a product of checks is the trivial class and changes nothing)” into a general theory. Supports the R2 homological view together with bravyi1998quantum.
  • Jean-Pierre Tillich and Gilles Zémor, "Quantum LDPC codes with positive rate and minimum distance proportional to the square root of the blocklength" (2009)
    tillich2009quantum · 定义超图积。是分类标签「hypergraph-product」、R1 校验矩阵视图（derived）、R2 超图积视图（canonical）、两条关系与导览多步的来源——本条目构造器的理论依据（qLDPC 教程 2.1 节）。Defines the hypergraph product. Source of the “hypergraph-product” category tag, the R1 check-matrix view (derived), the R2 HGP view (canonical), both relations and several tour steps: the theoretical basis of this entry's constructor (qLDPC guide, §2.1).
  • Dorit Aharonov and Michael Ben-Or, "Fault Tolerant Quantum Computation with Constant Error" (1997)
    aharonov1997fault · 阈值定理：足够弱的局域噪声可以被压到任意小。直觉文「设计问题」一节用它说明表面码要解决的不是「能不能」而是「以什么交互契约」。仅条目级。The threshold theorem: sufficiently weak local noise can be suppressed arbitrarily. The intuition essay's “design problem” uses it to say the surface code's question is not whether but under what interaction contract. Entry-level only.

2.2禁区与代价定理：它做不到什么No-go and tradeoff theorems: what it cannot do

  • Sergey Bravyi and Barbara M. Terhal, "A no-go theorem for a two-dimensional self-correcting quantum memory based on stabilizer codes" (2009)
    bravyi2009nogo · 二维局域稳定子哈密顿量不能自纠错。把检查当能量项，考虑所有「从一个逻辑态出发、每步只加一个局部错误、最后到达另一个逻辑态」的路径：每条路径途中都有一个能量最高点，能量壁垒是这个最高点（比基态高多少）在所有路径里的最小值。论文证明二维里这个壁垒被一个与系统大小无关的常数封顶：造出一条串的两个端点要花能量，但把串拉长不再加价，所以热涨落只需越过一个固定高度就能造成逻辑错误。直觉文「失效模式」里「没有被动热记忆」的依据。仅条目级。2D local stabilizer Hamiltonians cannot self-correct. Take the checks as energy terms and consider every path that starts in one logical state, adds one local error per step, and ends in another logical state: each path has a highest-energy point on the way, and the energy barrier is the smallest such height (above the ground state) over all paths. The paper proves that in 2D this barrier is capped by a constant independent of the system size: creating the two endpoints of a string costs energy, but stretching the string costs nothing more, so thermal fluctuations need only clear a fixed height to cause a logical error. Basis of “no passive thermal memory” in the intuition essay's failure modes. Entry-level only.
  • Sergey Bravyi, David Poulin, and Barbara Terhal, "Tradeoffs for reliable quantum information storage in 2D systems" (2010)
    bravyi2010tradeoffs · k·d² ≤ c·n（k 逻辑比特、d 码距、n 物理比特），前提是二维格点、每个格点只放有限个比特（比特密度有界）、每条检查只作用在固定大小的一块区域内；常数 c 只依赖这两个局域性参数。表面码 k = 1、d ∝ √n，使 k·d² 与 n 同阶，达到了这个标度，并不是说等号成立。BB 码教程 1.1 节从这里出发。仅条目级。k·d² ≤ c·n (k logical qubits, d distance, n physical qubits), assuming a 2D lattice with a bounded number of qubits per site (bounded qubit density) and every check acting within a region of fixed size; the constant c depends only on these two locality parameters. The surface code with k = 1, d ∝ √n makes k·d² of the same order as n: it saturates the scaling, which does not mean equality holds. The BB-code guide, §1.1 starts here. Entry-level only.
  • Sergey Bravyi and Jeongwan Haah, "Energy landscape of 3D spin Hamiltonians with topological order" (2011)
    bravyi2011energy · 三维拓扑序的能量壁垒分析（能量壁垒：见上一条 bravyi2009nogo 的定义），二维禁区在三维如何松动的对照。仅条目级。Energy-barrier analysis for 3D topological order (the energy barrier: defined in the bravyi2009nogo item above), the contrast case for how the 2D no-go loosens in 3D. Entry-level only.
  • Sergey Bravyi and Robert König, "Classification of topologically protected gates for local stabilizer codes" (2013)
    bravyi2013classification · Bravyi–König 定理：对二维拓扑稳定子码（检查几何局域、码距足够大），用深度固定、每个门只作用于相邻比特的电路实现的逻辑门都在 Clifford 群里；所以在这些前提下，没有这样实现的逻辑 T 门（格点手术教程 1.3 节）。仅条目级。The Bravyi–König theorem: for a 2D topological stabilizer code (geometrically local checks, large enough distance), every logical gate implemented by a constant-depth circuit of gates acting on nearby qubits lies in the Clifford group; so under these assumptions no logical T gate is implemented this way (lattice-surgery guide, §1.3). Entry-level only.
  • Jeongwan Haah, "Local stabilizer codes in three dimensions without string logical operators" (2011)
    haah2011local · 立方码：三维里没有串状逻辑算符的码（它的逻辑算符不能沿一条线铺开），是「逻辑信息一定住在串上」在三维不再成立的反例。仅条目级。The cubic code: a 3D code with no string-like logical operators (its logical operators cannot be laid out along a line), the counterexample to “logical data must live on strings” beyond 2D. Entry-level only.

2.3译码器与阈值：怎样纠、纠到哪Decoders and thresholds: how to correct, and how far

  • Chenyang Wang, Jim Harrington, and John Preskill, "Confinement-Higgs transition in a disordered gauge theory and the accuracy threshold for quantum memory" (2003)
    wang2003confinement · 两个数字的家：匹配译码在码容量下的 10.3%，以及唯象噪声（数据 + 测量都出错）下的 2.9%。被两条 mwpm 记录与 R5 统计力学视图引用。请勿把 2.9% 与 10.9% 混作同一阈值（译码器教程 6.1 节）。Home of two numbers: 10.3% for matching under code capacity, and 2.9% under phenomenological noise (data and measurement errors). Cited by two mwpm records and the R5 statistical-mechanics view. Never merge the 2.9% with the 10.9% (decoders guide, §6.1).
  • Austin G. Fowler, Matteo Mariantoni, John M. Martinis, and Andrew N. Cleland, "Surface codes: Towards practical large-scale quantum computation" (2012)
    fowler2012surface · 电路级 mwpm 记录的 0.57%/步（八步电路，约 4%/整周期）；同时是四条 claimed 操作的键：打洞编织 CNOT、逻辑 |0⟩/|+⟩ 初始化、逻辑 Z/X 读出、Pauli 框架更新。The circuit-level mwpm record's 0.57% per step (eight-step circuit, about 4% per full cycle); also the key behind four claimed operations: hole-braiding CNOT, logical |0⟩/|+⟩ initialization, logical Z/X readout, Pauli-frame update.
  • Oscar Higgott, "PyMatching: A Python package for decoding quantum codes with minimum-weight perfect matching" (2022)
    higgott2022pymatching · 最小重量完美匹配的开源实现，码容量 mwpm 记录引用它作为可复现的工具（译码器教程 2.3 节）。The open-source implementation of minimum-weight perfect matching; the code-capacity mwpm record cites it as the reproducible tool (decoders guide, §2.3).
  • Nicolas Delfosse and Naomi H. Nickerson, "Almost-linear time decoding algorithm for topological codes" (2021)
    delfosse2021almost · union-find 记录。做法：每个警报先自成一个团；含奇数个警报的团向外长一圈（加权生长版每次只长边界最短的奇团），两团相碰就合并；含偶数个警报的团停止生长；等所有团都含偶数个警报，在每个团里用剥离（peeling）算法从树的叶子往里一条边一条边地剥，得到一个与警报相符的修复。9.9% 与 2.6% 属于加权生长版：前者是二维环面码、只有独立的 Z 错误、测量完美，后者是唯象噪声（每轮数据比特 Z 错误与测量结果翻转以同一概率发生）；所有团一起均匀生长的版本是 9.2% 与 2.4%（论文第 5 节）。用小幅阈值换近线性时间（译码器教程第 4 章）。The union-find record. How it works: each alarm starts as its own cluster; a cluster holding an odd number of alarms grows by one layer (the weighted-growth version grows only the odd cluster with the shortest boundary each time), and clusters that touch merge; a cluster holding an even number of alarms stops growing; once every cluster is even, a peeling algorithm strips each cluster edge by edge from the leaves of a tree inward and returns a correction matching the alarms. The 9.9% and 2.6% belong to the weighted-growth version: the first for the 2D toric code with independent Z errors and perfect measurements, the second for phenomenological noise (per round, data-qubit Z errors and measurement flips at the same probability); growing all clusters uniformly gives 9.2% and 2.4% (Section 5 of the paper). A little threshold is traded for almost-linear time (decoders guide, Chapter 4).

补课 · 张量与收缩；有序统计后处理怎样给出一个与警报相符的修复Catch-up · Tensors and contraction; how ordered-statistics post-processing yields a correction that matches the alarms

张量与收缩。张量就是带若干个下标的一组数：一个下标是向量，两个下标是矩阵，三个以上照样可以。两个张量共享一个下标时，把这个下标的所有取值乘起来再加起来，叫收缩。最熟悉的例子是矩阵乘法 Cik = Σj AijBjk，共享的下标 j 被求和掉。取 A = [[1, 2], [3, 4]]，B = [[1, 0], [1, 1]]（下标从 0 数）：C00 = A00B00 + A01B10 = 1·1 + 2·1 = 3，同样算出 C01 = 2，C10 = 7，C11 = 4。张量网络就是许多小张量按图连起来，每条连线代表一个要被收缩的共享下标；矩阵乘积态是连成一条链的特例。张量网络译码器把「某一类错误的总概率」写成这样一张网络，收缩完得到一个数。

Tensors and contraction. A tensor is an array of numbers with some indices: one index is a vector, two a matrix, and three or more work the same way. When two tensors share an index, multiplying over every value of that index and adding up is a contraction. The most familiar case is matrix multiplication, Cik = Σj AijBjk, where the shared index j is summed away. With A = [[1, 2], [3, 4]] and B = [[1, 0], [1, 1]] (indices counted from 0): C00 = A00B00 + A01B10 = 1·1 + 2·1 = 3, and likewise C01 = 2, C10 = 7, C11 = 4. A tensor network is many small tensors joined along a graph, each link standing for a shared index to be contracted; a matrix-product state is the special case of a chain. A tensor-network decoder writes “the total probability of one class of errors” as such a network, and contracting it yields one number.

有序统计后处理（OSD）。置信传播给每个比特一个「出错概率」，但按 0.5 一刀切得到的猜测不一定与警报相符。OSD 用排序补救。例：三比特重复码，两条检查 c1 = b1 + b2、c2 = b2 + b3（模 2），两条都报警，s = (1, 1)。设置信传播给出 b1、b2、b3 出错的概率 0.2、0.3、0.25，全都低于 0.5，一刀切的猜测是「都没错」，与 s 不符。OSD 按概率从大到小排：b2、b3、b1；依次取它们在检查矩阵里的列，b2 列 (1, 1)、b3 列 (0, 1)，这两列已经线性无关，只在这两个比特上解方程，其余比特设为 0：e2·(1, 1) + e3·(0, 1) = (1, 1)，得 e2 = 1、e3 = 0。修复是翻转 b2，它正好点亮两条检查，与警报相符。

Ordered-statistics post-processing (OSD). Belief propagation gives each bit a “probability of error”, but cutting at 0.5 may give a guess that does not match the alarms. OSD repairs this by sorting. Example: the three-bit repetition code with checks c1 = b1 + b2 and c2 = b2 + b3 (mod 2), both alarming, s = (1, 1). Suppose belief propagation gives error probabilities 0.2, 0.3, 0.25 for b1, b2, b3, all below 0.5, so the cut-off guess is “no errors”, which does not match s. OSD sorts from most to least likely: b2, b3, b1; it takes their columns of the check matrix in that order, b2's column (1, 1) and b3's column (0, 1), which are already linearly independent, and solves only on these two bits with the rest set to 0: e2·(1, 1) + e3·(0, 1) = (1, 1), so e2 = 1, e3 = 0. The correction flips b2, which lights exactly the two checks, matching the alarms.

补课 · 张量上的 Z₂ 对称是什么意思Catch-up · What a Z₂ symmetry of a tensor means

Z₂ 是只有两个元素的群：「不动」和「翻转」，翻转两次等于不动。设一个小张量有四条内部连线（下标 a、b、c、d，各取 0 或 1），定义 Tabcd = 1 当 a + b + c + d 为偶数，否则为 0。把四条连线同时翻转（0 ↔ 1），和 a + b + c + d 变了 4，奇偶不变，所以每个分量都不变：Tabcd = T(1−a)(1−b)(1−c)(1−d)，例如 T0000 = T1111 = 1，T1000 = T0111 = 0。这就是「在内部连线上带一个 Z₂ 对称」。只翻一条连线则不行：T0000 = 1 会变成 T1000 = 0。收缩整张网络时，这样的对称可以沿连线在相邻张量之间推来推去，局部看不出任何变化；Schuch 等把基态简并和拓扑序追溯到这种约束。

Z₂ is the group with just two elements, “do nothing” and “flip”, where flipping twice is doing nothing. Take a small tensor with four internal links (indices a, b, c, d, each 0 or 1) and set Tabcd = 1 when a + b + c + d is even and 0 otherwise. Flipping all four links at once (0 ↔ 1) changes the sum by 4, which keeps its parity, so every entry is unchanged: Tabcd = T(1−a)(1−b)(1−c)(1−d), e.g. T0000 = T1111 = 1 and T1000 = T0111 = 0. That is what “carrying a Z₂ symmetry on its internal links” means. Flipping only one link fails: T0000 = 1 would become T1000 = 0. In the contracted network such a symmetry can be pushed along links from one tensor to its neighbours without any local change; Schuch et al. trace ground-state degeneracy and topological order back to this constraint.

3.2一个键如何钉住一条关系How a key pins a relation

对于「表面码是 HGP(rep_L, rep_L)」这条关系（L = 格子边长；关系导读第 2 章），源文件里还多两层保护：断言有自己的 id atlas-assertion:surface:relations:0，有位置 surface/card.yaml#/relations/0，还有内容的 sha256 哈希。refs 里只有 tillich2009quantum。所以核对流程是：哈希保证你看到的就是登记时的那句话；键保证那句话有出处；注册表保证出处可以打开。三者缺一，导出脚本就会拒绝生成页面。

For the relation “the surface code is HGP(rep_L, rep_L)” (L = lattice side; relations guide, Chapter 2) the source adds two more layers: the assertion has its own id atlas-assertion:surface:relations:0, a locator surface/card.yaml#/relations/0, and a sha256 of its content. Its refs hold only tillich2009quantum. So the audit reads: the hash guarantees you see the sentence as registered; the key guarantees the sentence has a source; the registry guarantees the source can be opened. Remove any one and the export script refuses to build the page.

3.3一个被防住的误引A misattribution that got caught

「Λ = 2.14」常被错挂到 2023 年那篇 Google 论文上。Atlas 的 realizations[0]（键 google2023suppressing）在描述里直接写道：「这是 2023 年的码距缩放结果；它没有报告后来 Willow 的压制因子。」也就是说，防误引的措施不是靠读者小心，而是把否定句写进记录本身。同类例子：bluvstein2024logical 的记录写明「不是低于阈值的存储器结论」；文献侦察报告写明 Fowler 等 2012 不讨论旋转几何。看到一个数字带着「不是……」的句子，那是 Atlas 在替你挡子弹。

“Λ = 2.14” is often pinned on Google's 2023 paper by mistake. The Atlas record realizations[0] (key google2023suppressing) says in its own description: “This is the 2023 distance-scaling result; it did not report the later Willow suppression factor.” The defence, in other words, is not reader vigilance but a negative sentence written into the record. Likewise bluvstein2024logical's record says “not a below-threshold surface-memory claim”, and the literature scout report notes that Fowler et al. 2012 does not discuss rotated geometry. When a number arrives with a “not …” clause, that is the Atlas taking the bullet for you.
