第 1 章Chapter 1

译码器在决定什么What a decoder decides

译码器不是在猜「哪些比特错了」——那件事原则上不可知，也不必知。它决定的是一件粗得多、也可判的事：错误属于哪一类。把这句话写成数学，「最优译码」的定义就自动掉出来，「最轻的链最可能」也只是一道对数题。 A decoder does not guess which qubits failed — that is unknowable in principle and unnecessary in practice. It decides something far coarser and decidable: which class the error belongs to. Write that sentence in mathematics and the definition of “optimal decoding” falls out, while “the lightest chain is the likeliest” becomes an exercise in logarithms.

1.1从症状到类From syndrome to class

设真实错误是一批出错的比特 E（本章只看 Z 错误，X 错误的故事在另一副眼镜里完全对称）。我们看到的只有症状 s = ∂E。任何一个候选修复 C，只要 ∂C = s，施加后症状就清零。此时残留的是 E ⊕ C：一条不点亮任何警报的链——要么是闭合的圈，要么两端都落在毛边界上。《Surface Code · 高中数学版》第 3 章的二分法接管，但要数的是奇偶：数一数残留里有几段是从左毛边界一直连到右毛边界的（叫横跨的串）。偶数段（0、2、4…），残留是若干面检查的乘积，无事发生；奇数段，残留等于逻辑算符 Z̄ 乘上一些面检查，是一次逻辑错误。为什么两段会抵消？两条横跨的串之间夹着一条带子，把带子里所有面检查乘起来，内部的边各被相邻两个面碰到两次、消掉，剩下的正好是这两条串（贴着毛边界的面在边界那一侧是开口的，不贡献竖边）。见图 1.1 ②。对一块 k = 1 的贴片，Z 错误只有这两类。

Let the true error be a set E of failed qubits (this chapter follows Z errors; the X story is identical through the other lens). All we observe is the syndrome s = ∂E. Any candidate repair C with ∂C = s clears the syndrome, leaving the residual E ⊕ C: a chain that lights no alarm — either a closed loop or a path whose two ends both sit on rough boundaries. The dichotomy of “The Surface Code · High-School Edition”, Chapter 3 takes over, but what it counts is a parity: count the pieces of the residual that run all the way from the left rough boundary to the right one (spanning strings). An even number (0, 2, 4, …) means the residual is a product of plaquette checks and nothing happened; an odd number means the residual is the logical operator Z̄ times some plaquettes, a logical error. Why do two cancel? Two spanning strings enclose a strip between them; multiply all the plaquettes in that strip, and every inner edge is touched by two neighbouring plaquettes and drops out, leaving exactly the two strings (a plaquette at a rough boundary is open on that side and contributes no vertical edge there). See Fig. 1.1 ②. For a k = 1 patch, Z errors fall into exactly two classes.

实用的数法（本页所有实验台判输赢就是这么数的）：数残留里有几个比特落在左边界那一列半截边上。每段横跨的串在那里占一个，两端都在左边界的路占两个，闭合的圈一个也不占，所以这个数的奇偶就是横跨串数的奇偶：奇数即输。

A practical count (it is how every bench on this page decides the verdict): count the residual qubits that lie on the column of half-edges at the left boundary. Each spanning string occupies one of them, a path with both ends on the left boundary occupies two, a closed loop none; so the parity of this count is the parity of the number of spanning strings, and odd means failure.

这里的「类」要说清楚。两条链 C、C′ 叫同一类，意思是它们的差 C ⊕ C′ 可以由面检查拼出来（闭合的圈、两端落在同一条毛边界上的路、偶数条横跨的串，都属于这种）。面检查作用在编码态上什么都不改变（编码态是每条检查的 +1 本征态），所以同类的两条链作为修复效果完全一样。例：两个警报在同一行、相距 2 步。修复甲是连接它们的直线（2 个比特）；修复乙先向上一步、横走 2 步、再向下一步（4 个比特）。甲 ⊕ 乙 恰好是一个 1 × 2 小矩形的边框，由两个面检查拼成，所以甲乙同类。修复丙把左边的警报推向左毛边界、右边的警报推向右毛边界：甲 ⊕ 丙 从左边界连到右边界，是一条（奇数条）横跨的串，所以丙与甲不同类——若甲是对的，丙就造成逻辑错误。

“Class” needs a precise meaning. Two chains C and C′ are in the same class when their difference C ⊕ C′ can be built from face checks (closed loops, paths with both ends on the same rough boundary, and even numbers of spanning strings all qualify). A face check changes nothing on an encoded state (encoded states are +1 eigenstates of every check), so two chains of the same class act identically as repairs. Example: two alarms on one row, 2 steps apart. Repair A is the straight path between them (2 qubits); repair B steps up once, runs 2 steps across, and steps down (4 qubits). A ⊕ B is exactly the rim of a 1 × 2 rectangle, built from two face checks, so A and B are in one class. Repair C pushes the left alarm to the left rough boundary and the right alarm to the right one: A ⊕ C runs from the left boundary to the right, one (an odd number of) spanning string, so C is not in A’s class — if A is right, C causes a logical error.

于是所有满足 ∂C = s 的修复也分成两类：与 E 同类的（修复成功）和不同类的（修复失败）。译码器在两类之间选一类，然后在那一类里随便挑一条链施加——挑哪条无所谓。译码是二选一，不是大海捞针。

So all repairs with ∂C = s split into two classes as well: those in E's class (repair succeeds) and those in the other (repair fails). The decoder picks a class, then applies any chain from it — which one is irrelevant. Decoding is a binary choice, not a search for a needle.

1.2最优译码 = 押概率最大的那一类Optimal decoding = bet on the most probable class

既然是二选一，最好的策略就是：算出「真实错误属于第一类」和「属于第二类」的概率，押大的（下面的折叠块说明为什么没有更好的策略）。要算概率，先得说清错误怎么产生。本章和第 2 至 4 章都用最简单的码容量模型code-capacity noise：只有数据比特出错，每个比特独立地以概率 p 出错；症状测量本身完美无误。在这个模型下测得的阈值叫码容量阈值。：每个数据比特独立地以概率 p 出一个 Z 错误，而检查的读数完全可靠（测量出错的情形留到第 5 章）。于是一条具体的、长 ℓ 的链（ℓ = 链上的比特数）出现的概率是 pℓ(1−p)n−ℓ，n 是贴片上数据比特的总数：ℓ 个比特错，其余 n−ℓ 个没错。一类的概率，就是把这一类里所有链的概率加起来。这样定义的译码器叫最大似然译码器maximum-likelihood decoder：给定症状，选总概率最大的那一类。它是任何译码器能达到的上限，代价是要对一类里所有链求和。，它是一切译码器的上限。

With a binary choice the best strategy is: compute the probability that the true error lies in class one versus class two, and bet on the larger (the fold below explains why nothing does better). To compute probabilities we must say how errors arise. This chapter and Chapters 2 to 4 use the simplest code-capacity modelCode-capacity noise: only data qubits fail, each independently with probability p; syndrome measurement itself is perfect. A threshold measured in this model is a code-capacity threshold.: each data qubit independently suffers a Z error with probability p, and check readouts are perfectly reliable (faulty measurements wait until Chapter 5). One specific chain of length ℓ (ℓ = the number of qubits on it) then occurs with probability pℓ(1−p)n−ℓ, where n is the total number of data qubits on the patch: ℓ qubits failed, the other n−ℓ did not. The probability of a class is the sum over every chain in it. The decoder so defined is the maximum-likelihood decoderGiven the syndrome, pick the class with the largest total probability. It is the ceiling for any decoder; the price is a sum over every chain in a class., the ceiling for all decoders.

为什么「押概率最大的类」就是最优？Why is “bet on the most probable class” optimal?

固定一个症状 s。译码器的任何策略最终都是「看到 s 就押某一类」。它在这个 s 下成功的概率，等于真实错误恰好落在被押的那一类的条件概率。两类的条件概率之和是 1，押大的那个，成功概率就不小于 1/2，而且没有任何别的选择能更高——因为你只有两个选项，而两个选项的成功概率就是这两个数。对每一个症状都这样做，总的成功概率就被逐项最大化了。这就是贝叶斯意义下的最优，没有别的魔法。

Fix a syndrome s. Any decoder strategy amounts to “on seeing s, bet on some class”. Its success probability under this s equals the conditional probability that the true error lies in the class it bet on. The two conditional probabilities sum to 1; betting on the larger gives at least 1/2, and nothing can do better — there are only two options, and their success probabilities are exactly those two numbers. Do this for every syndrome and the total success probability is maximised term by term. That is Bayesian optimality; no further magic.

关键想法Key idea

译码器有两种「最好」。最大似然：把一类里所有链的概率加起来，押总和大的类——真正的最优，但要求和。最小重量：只找一条最可能（最短）的链，押它所在的类——把求和换成了求最短，快得多，偶尔会错在「一类链多、单条不长」的情形（第 3 章）。整篇教程就是这两种「最好」之间的拉锯。

A decoder has two kinds of “best”. Maximum likelihood: sum the probabilities of every chain in a class and bet on the larger sum — truly optimal, but it sums. Minimum weight: find one most probable (shortest) chain and bet on its class — a sum replaced by a shortest-path search, far faster, and occasionally wrong when a class has many chains, none of them long (Ch. 3). This whole tutorial is the tug-of-war between the two.

第 2 章Chapter 2

最小重量完美匹配Minimum-weight perfect matching

「找最短的链」听起来像图论里的最短路，其实是另一个更巧的问题：把警报两两配对，使配对的路径总长最短。这一章给这个问题起名、数清它有多少种答案（多到吓人）、再说明为什么六十年前的一个算法能在多项式时间里找到最优解——以及本页的玩具版是怎么做的。 “Find the shortest chain” sounds like a shortest-path problem; it is really a subtler one: pair the alarms so that the total path length is minimal. This chapter names the problem, counts its candidate answers (frighteningly many), and explains why a sixty-year-old algorithm finds the optimum in polynomial time — and what this page's toy version does instead.

2.1症状图：警报是点，距离是边The syndrome graph: alarms as nodes, distances as edges

一条满足 ∂C = s 的链，就是若干段路径，每段连接两个警报（或连接一个警报与一段己方边界）。为什么？从任意一个警报出发，沿着链上的比特走：每经过一个不亮的检查，链在那里有偶数条边，进得去就出得来；所以只能停在另一个警报上，或者走出毛边界。把这段路径拿掉，剩下的链少了两个端点，再重复。拆到最后若还剩一些闭合的圈，它们不连任何警报，只会让链更重，最轻的链里不会有。把它反过来看：先决定谁和谁配对，再让每对之间走最短路——最短路的长度只取决于两个端点，可以预先算好。（两对的最短路若有重叠，重叠的比特错两次等于没错，⊕ 会把它们消掉，得到的链只会更轻；而这条更轻的链拆开来又是另一种配法，所以最轻的链一定是「某种配法 + 每对走最短路」。）于是问题只剩配对。画一张新图，叫症状图syndrome graph：顶点是全部警报（平面版再加一个「边界」虚拟顶点），任意两顶点之间连一条边，边的权重 = 两警报在格点上的最短距离乘 w₀。：顶点是警报，任意两点之间连一条边，权重是它们在格点上的最短距离（乘上 w₀，但同一个 p 下这是公因子，下面就用步数）。平面版再加一个虚拟顶点「边界」，每个警报到它的权重是到最近己方边界的步数。

A chain with ∂C = s is a bundle of paths, each joining two alarms (or one alarm to a boundary of its own kind). Why? Start at any alarm and walk along the chain’s qubits: at every unlit check the chain has an even number of edges, so whenever you get in you can get out; you can only stop at another alarm or leave through a rough boundary. Remove that path; the rest of the chain has two fewer endpoints; repeat. Any closed loops left over touch no alarm and only add weight, so the lightest chain has none. Flip the viewpoint: decide first who pairs with whom, then let each pair walk a shortest path — its length depends only on the two endpoints and can be precomputed. (If the shortest paths of two pairs overlap, a qubit flipped twice is not flipped at all, ⊕ cancels the overlap, and the chain only gets lighter; that lighter chain splits into another pairing, so the lightest chain is always “some pairing + a shortest path per pair”.) Only the pairing remains. The planar version adds a virtual “boundary” vertex, each alarm's weight to it being the steps to its nearest boundary of the right kind.

2.3六十年前的算法：开花A sixty-year-old algorithm: blossoms

六亿种配法不能穷举，但 1965 年 Jack Edmonds 给出了一个算法，能在多项式时间内精确找出最小重量完美匹配：运行时间只随警报数按某个固定次方增长，而不是像双阶乘那样爆炸。按今天的写法，他的原始版本约需 V²E 步（V = 症状图的点数，E = 边数；每两点都连边时 E ≈ V²/2，所以约 V⁴），Gabow 后来把它改进到 V³。这个算法叫开花算法blossom algorithm（Edmonds 1965）：沿「增广路」逐步增加配对数，同时用每个点上的「对偶变量」保证每一步都只用最便宜的边；遇到奇数长度的圈就把它缩成一个点（「花」），之后再展开。。它由四个想法拼成，下面逐个讲，每个想法都对应下面回放里的一种步骤。

Six hundred million pairings cannot be enumerated, but in 1965 Jack Edmonds gave an algorithm that finds the minimum-weight perfect matching exactly in polynomial time: its running time grows like a fixed power of the number of alarms, not explosively like the double factorial. In today’s terms his original version needs about V²E steps (V = nodes of the syndrome graph, E = edges; with every pair joined, E ≈ V²/2, so about V⁴), later improved by Gabow to V³. It is the blossom algorithmEdmonds 1965: raise the number of pairs one augmenting path at a time, while “dual variables” on the nodes guarantee that only the cheapest edges are ever used; an odd cycle is shrunk to one node (a “blossom”) and expanded later.. It is built from four ideas; we take them one at a time, and each matches one kind of step in the player below.

想法一 · 增广路：一次多配一对。一个匹配是一组互不相交的配对（每个警报最多出现在一对里），还没配上的警报叫未配点。一条增广路augmenting path：从一个未配点出发、到另一个未配点结束的路径，路上的边交替地「不在匹配里、在匹配里、不在匹配里……」。把路上每条边的身份对调，配对数就加一。从一个未配点出发，交替地走「不在匹配里的边」和「在匹配里的边」，到另一个未配点结束。把路上每条边的身份对调——在的变不在、不在的变在——两端的未配点就都配上了，中间的点仍然各配一个，配对数加一。例：四个警报 A1、A2、A3、A4 排成一行，现在只有 A2–A3 配着。路 A1 – A2 = A3 – A4（「–」不在匹配里，「=」在）是一条增广路；对调之后得到 A1 = A2、A3 = A4，从 1 对变成 2 对。

Idea 1 · Augmenting paths: one more pair at a time. A matching is a set of disjoint pairs (each alarm in at most one), and an alarm not yet paired is unmatched. An augmenting pathA path from one unmatched node to another whose edges alternate “not in the matching, in the matching, not in …”. Swapping the status of every edge on it adds one pair. starts at an unmatched node, alternates between edges not in the matching and edges in it, and ends at another unmatched node. Swap the status of every edge on it — in becomes out, out becomes in — and both end nodes get partners while every interior node still has exactly one: one pair more. Example: four alarms A1, A2, A3, A4 in a row, with only A2–A3 paired. The path A1 – A2 = A3 – A4 (“–” not in the matching, “=” in it) is augmenting; after the swap we have A1 = A2 and A3 = A4, two pairs instead of one.

想法二 · 菱形是一张「下界证书」。光会增加配对数还不够，还得保证最后的配法最轻。Edmonds 的办法是给每个点 v 一个数 yv，叫对偶变量dual variable，记作 yv：算法给每个点分配的一个数，画成以该点为中心、半径 yv 的菱形。规则是任意两点的菱形不重叠：yu + yv ≤ w(u, v)。没有花的时候，所有 y 的和就是任何配法总重量的下界（有花时的修正见 2.3 节想法四）。，画成以 v 为中心、半径 yv 的菱形（格点上只能横竖走，离一个点不超过 r 步的区域正好是菱形）。唯一的规则：任意两个菱形不重叠，即对每两点 u、v 都有 yu + yv ≤ w(u, v)。两者之差 w − yu − yv 叫这条边的松弛slack：w − yu − yv，两个菱形之间还剩的空隙，始终 ≥ 0。等于 0（两个菱形相碰）的边叫紧边，算法只沿紧边配对。，就是两个菱形之间还剩的空隙；空隙为 0、两个菱形正好相碰的边叫紧边。这些数买到的是一张证书：任取一种完美匹配，它的每一对 (u, v) 都满足 w(u, v) ≥ yu + yv；把所有对加起来，每个点恰好出现一次，所以任何配法的总重量 ≥ 所有 y 之和。如果我们找到一种配法，它的每一对都是紧边，那么它的重量恰好等于 y 之和——已经碰到下界，不可能有更轻的配法，而这个结论不需要去试那六亿种。算法的全部工作，就是一边把菱形撑大（抬高下界），一边只沿紧边配对。（这一段的规则和下界只在还没有花的时候原样成立；花出现后，记账要加一项，见想法四和它后面的折叠块。）

Idea 2 · The diamonds are a lower-bound certificate. Adding pairs is not enough; the final pairing must also be the lightest. The one rule: no two diamonds overlap, i.e. yu + yv ≤ w(u, v) for every two nodes. The difference w − yu − yv is the edge’s slackw − yu − yv: the gap left between two diamonds, always ≥ 0. What these numbers buy is a certificate. Take any perfect matching: each of its pairs (u, v) has w(u, v) ≥ yu + yv; add over all pairs, every node appearing exactly once, and every pairing weighs at least the sum of all y. If we find a pairing whose every pair is tight, its weight equals the sum of the y — it has hit the lower bound, no pairing can be lighter, and we know it without trying six hundred million of them. The algorithm’s whole job is to inflate the diamonds (raising the bound) while pairing only along tight edges. Idea 4 · Odd cycles shrink into a blossom. One kind of touch is left: (3) the other diamond belongs to an outer node of the same tree. The nodes of an odd cycle cannot all be paired among themselves — one is always left over — so swapping along it gets stuck. A blossom always has exactly one member that is not paired inside it (it is unmatched, or matched to a node outside); that member is the blossom’s base, and the other members are paired among themselves. When an augmenting path passes through a blossom, the blossom is re-paired in place so that the member the path passes through becomes the new base; the blossom itself stays. When a blossom hangs in a tree as an inner node, the member at which the tree edge from its outer parent arrives is its entry. An inner blossom shrinks, and once its z reaches 0 it may not shrink further (z cannot be negative; the fold below says why), so it is expanded: walk round the cycle from the entry to the base along the side with an even number of edges, label the members on that path inner, outer, inner, … back into the tree, and release the remaining members as free nodes. 花为什么要有自己的对偶变量Why a blossom needs its own dual variable

此刻回放里画出的四个半径是 2、2、2、2，加起来是 8，比最优的 6 还大——所以画出来的半径之和不是下界，要换一种数法。把花一起长的那 1 看成一圈围着 {A, B, C} 的「护城河」，宽度 t = 1；每个点自己单独长的是 A、B、C 各 1（第一轮）、D 共 2。护城河里装着奇数个点。任取一种完美匹配，设它有 k 对从河里跨到河外：河里的 3 个点去掉这 k 个，剩下的要在河里两两配完，所以 3 − k 是偶数，k 是奇数，至少是 1。每跨一次付河宽 t，其余的长度由各点自己的菱形保证。于是任何配法的重量 ≥ 1 + 1 + 1 + 2（各点自己的）+ k·t ≥ 5 + t = 6，正好等于算法给出的重量，最优性得证。这就是 z 的用处：一朵花的厚度在下界里只算一次，因为只能保证有一对跨过它。

At this point the player draws radii 2, 2, 2, 2, adding up to 8 — more than the optimum 6 — so the sum of drawn radii is not a bound; we must count differently. Regard the 1 the blossom grew together as a “moat” of width t = 1 around {A, B, C}; what each node grew on its own is 1 each for A, B, C (stage 1) and 2 in total for D. The moat encloses an odd number of nodes. Take any perfect matching and let k of its pairs cross from inside the moat to outside: the 3 nodes inside minus these k must pair up among themselves, so 3 − k is even, k is odd, and at least 1. Each crossing pays the moat width t, and each node’s own diamond accounts for the rest. Hence every pairing weighs ≥ 1 + 1 + 1 + 2 (each node’s own) + k·t ≥ 5 + t = 6, exactly the weight the algorithm returned, which proves optimality. That is what z is for: a blossom’s thickness counts once in the bound, because only one crossing pair is guaranteed.

z 为什么不能为负。上面最后一步用的是 k·t ≥ t：跨 k ≥ 1 次，至少付一次河宽。这一步要求 t ≥ 0。若 t < 0，跨得越多付得越少：t = −1 时一个跨 3 次的配法只付 3t = −3，比 t = −1 还少，「至少付 t」不再成立，证书作废。所以一朵内花缩到 z = 0 就必须停，不能接着缩；算法若还要往前走，就得把它展开（下面的第二个例子）。

Why z may not be negative. The last step above used k·t ≥ t: crossing k ≥ 1 times pays the moat width at least once. That step needs t ≥ 0. If t < 0, crossing more pays less: with t = −1 a pairing that crosses 3 times pays 3t = −3, less than t = −1, so “pays at least t” fails and the certificate is void. Hence an inner blossom must stop shrinking at z = 0; if the algorithm has to go on, it expands the blossom (the second example below).

Notation in the player: w = edge weight (lattice distance between two alarms, or from an alarm to its own boundary node); yu, yv = the dual variables at its ends (an inner node’s y may shrink below zero; a diamond can only show a positive radius); δ = one growth increment, the smallest amount until the next event; zB = blossom B’s dual, twice the thickness the blossom has grown as a whole (+2δ for an outer blossom, −2δ for an inner one); an inner blossom is expanded when it reaches zero. 上面的「算法逐步回放」实现的是带对偶变量的 Edmonds 开花算法（为演示而写，只处理最多十来个警报）。其余实验台里的「最轻配法」用的是另一种小规模精确法：把「还剩哪些警报没配」编成一个二进制数，对 2m 个状态逐个算最优——m ≤ 16 时瞬间完成，超过就退回贪心（第 3 章）。两种方法给出的最优重量完全一样（回放结束时会逐次核对；有并列时具体配法可以不同），只是枚举法不能扩展到几百个警报。《Surface Code · 高中数学版》的译码游戏用的正是同一段代码（那里的上限设为 14 个警报），这就是它在警报稠密时「退化为贪心」的原因。

The “algorithm step-through” above implements Edmonds' blossom algorithm with dual variables (written for demonstration; it handles a dozen alarms at most). The other benches' “lightest pairing” uses a different small-scale exact method: encode “which alarms remain unpaired” as a binary number and solve all 2m states in turn — instant for m ≤ 16, falling back to greedy beyond (Ch. 3). The two methods' optimal weights coincide exactly (the player checks this at the end of every run; with ties the actual pairing may differ); enumeration simply cannot scale to hundreds of alarms. The decoding game of “The Surface Code · High-School Edition” runs this same code (with its cutoff set at 14 alarms), which is why it “degrades to greedy” when alarms are dense.

关键想法Key idea

译码的第一次「翻译」：从「找最可能的错误链」到「在症状图上找最小重量完美匹配」。端点之间怎么走不重要，谁和谁配才重要；而配对问题有精确、多项式时间的算法。这就是为什么 MWPM 是表面码译码器的默认基准。

Decoding's first “translation”: from “find the most probable error chain” to “find a minimum-weight perfect matching on the syndrome graph”. How endpoints are joined does not matter; who pairs with whom does — and pairing has an exact polynomial-time algorithm. That is why MWPM is the default benchmark for surface-code decoders.

Now a problem that flips the verdict. Suppose that under some syndrome class A's shortest chain has length 5 and is unique, while class B's shortest chains have length 6 but there are 20 of them (a = b = 3). Matching picks A (5 < 6). Maximum likelihood compares totals. Here we make an approximation: compare only each class’s shortest chains. (A longer chain is individually less likely, each extra step multiplying by another p/(1−p), but the number of such chains grows quickly with length, so together they need not contribute little; the exact answer needs the sum over every chain of each class, which is precisely what a maximum-likelihood decoder does.) In this approximation: A ∝ e−5w₀, B ∝ 20·e−6w₀. B wins iff 20·e−w₀ > 1, i.e. p/(1−p) > 1/20, i.e. p > 1/21 ≈ 4.8%. So by the shortest-chain estimate, once the error rate passes about 4.8% the class that is “one step longer but twenty-fold” becomes likelier than the “one step shorter but unique” class, and matching bets wrong. The 4.8% is the crossover of this approximation, not an exact value; what it shows is the direction: the higher the error rate, the more the count matters.

匹配只看能量（最短长度），最大似然还看熵（有多少条链）。低错误率下能量压倒一切，两者几乎一致；错误率越高，熵的话语权越大。这就是为什么文献里表面码有两个码容量阈值：最大似然约 10.9%，匹配约 10.3%（出处见 6.2 节的账本）——两者之差不是数值误差，是两种译码器之间的 0.6 个百分点。

Matching sees only energy (shortest length); maximum likelihood also sees entropy (how many chains). At low error rates energy dominates and the two agree; the higher the error rate, the louder entropy speaks. That is why the literature quotes two code-capacity thresholds for the surface code: about 10.9% for maximum likelihood and about 10.3% for matching (sources in the ledger of §6.2) — the gap is not numerical uncertainty but 0.6 percentage points between two decoders.

学名一瞥：随机键 Ising 模型与自由能A glimpse of the scholarly name: the random-bond Ising model and free energy

Dennis、Kitaev、Landahl 与 Preskill（2002）发现：一类链的总概率与统计物理里的配分函数是同一个式子。配分函数把一个系统所有可能的构型按 e−能量/温度 加权求和；把链的长度 ℓ 看成「能量」、把 w₀ 看成「温度的倒数」（温度 T = 1/w₀），一类的配分函数就是 Z(类) = ∑C ∈ 类 e−ℓ(C)/T = ∑ e−w₀ℓ(C)。1.2 节的类概率正是 (1−p)n · Z(类)，公因子 (1−p)n 对两类一样。于是「最短链」= 能量最低的构型。自由能定义为 F = −T ln Z，也就是 Z = e−F/T，所以比两类的总概率就是比它们的自由能，F 小的那类更可能。一个特殊情形能看出 F 里装着什么：若一类里要算的构型都一样长，长度都是 E，一共 N 条，那么 Z = N·e−E/T，F = E − T ln N，即能量减去温度乘 ln（条数）；这个 ln N 就是这种情形下的熵 S，数的是「有多少种」。上面只算最短链的例子正属于这种情形：甲类 F = 5，乙类 F = 6 − T ln 20，乙类多出的 1 份能量被 T ln 20 抵消；乙胜出 ⇔ T ln 20 > 1 ⇔ w₀ < ln 20，和正文的 20·e−w₀ > 1 是同一个条件。链长短不一时就没有「熵 = ln 条数」这么简单的式子，只能直接用 Z 和 F。匹配相当于把温度降到零：只留能量最低的那一项。最大似然对应的温度恰好由真实的错误率 p 决定（w₀ = ln((1−p)/p)），这些点在统计物理的相图上连成一条线，叫 Nishimori 线。阈值在这幅图景里是一次相变：错误率低于它时，贴片越大，错误那一类的总概率相对正确那一类越小，趋于零；高于它时两类越来越难分——这种随尺寸变大而出现的突变，正是统计物理里相变的定义性特征。DKLP 引用的最大似然阈值 10.94% 就是在这条线上用蒙特卡洛模拟算出的相变点（见 6.2 节）。

Dennis, Kitaev, Landahl and Preskill (2002) noticed that a class’s total probability is the same expression as a partition function in statistical physics. A partition function sums over all configurations of a system, each weighted by e−energy/temperature; read the chain length ℓ as “energy” and w₀ as an inverse temperature (temperature T = 1/w₀), and a class’s partition function is Z(class) = ∑C ∈ class e−ℓ(C)/T = ∑ e−w₀ℓ(C). The class probability of §1.2 is exactly (1−p)n · Z(class), with the factor (1−p)n common to both classes. Then “shortest chain” = lowest-energy configuration. The free energy is defined as F = −T ln Z, i.e. Z = e−F/T, so comparing the two classes’ total probabilities means comparing their free energies, and the class with the smaller F is likelier. A special case shows what F contains: if all the configurations counted in a class have the same length E and there are N of them, then Z = N·e−E/T and F = E − T ln N, energy minus temperature times ln(count); this ln N is the entropy S of that case, a count of “how many”. The shortest-chains-only example above is such a case: class A has F = 5, class B has F = 6 − T ln 20, B’s one extra unit of energy is offset by T ln 20, and B wins ⇔ T ln 20 > 1 ⇔ w₀ < ln 20, the same condition as 20·e−w₀ > 1 in the main text. When the chains have different lengths there is no formula as simple as “entropy = ln count”; one works with Z and F directly. Matching amounts to cooling to zero temperature: only the lowest-energy term survives. Maximum likelihood sits at the temperature fixed by the true error rate p (w₀ = ln((1−p)/p)); these points form a line in the physicist’s phase diagram, the Nishimori line. The threshold, in this picture, is a phase transition: below it, the larger the patch, the smaller the wrong class’s total probability relative to the right one, going to zero; above it the two classes become ever harder to tell apart — an abrupt change that appears as the size grows, which is the defining feature of a phase transition. The maximum-likelihood threshold 10.94% quoted by DKLP is the transition point on this line, located by Monte Carlo simulation (see §6.2).

并查集译码器：长大、合并、剥皮The union-find decoder: grow, merge, peel

匹配精确但要算距离、排顺序；贪心快但会掉进陷阱。2017 年出现了第三条路：让每个警报像水滴一样向外长，碰到就合并，直到每一滴里的警报数变成偶数，然后沿一棵树从叶子往根「剥皮」。它几乎不需要算术，速度几乎与警报数成正比，阈值却只比匹配低一点。 Matching is exact but computes distances and sorts; greed is fast but falls into traps. In 2017 a third road appeared: let every alarm grow outward like a droplet, merge on contact until each droplet holds an even number of alarms, then “peel” a tree from its leaves to its root. It needs almost no arithmetic, runs in nearly linear time, and its threshold sits only slightly below matching's.

4.1为什么要更快Why faster matters

真实芯片大约每一微秒就产出一轮症状（例如 Google 2024 年的 Willow 芯片，一轮 1.1 微秒）。译码器若跟不上，未处理的症状会越积越多，而《格点手术 · 高中数学版》要讲的逻辑门必须等译码结果才能决定下一步——积压意味着整台机器越跑越慢，直到失控。所以译码器有两个指标：阈值（多准）和吞吐（多快），两者要同时达标。开花算法准，但在大贴片和长时间窗上很重。Delfosse 与 Nickerson 在 2017 年给出的并查集译码器union-find decoder（Delfosse–Nickerson 2017）：先让奇数簇生长合并（用「并查集」数据结构记录谁和谁同簇），再在每个簇里沿生成树剥皮得到修复。运行时间近似线性。把精度让出一点，换来几乎线性的运行时间。

A real chip emits one round of syndrome roughly every microsecond (Google’s 2024 Willow chip, for instance, runs one round per 1.1 µs). 并查集到底是什么？三行代码的数据结构What is union-find, really? A three-line data structure

一个数组 parent，parent[x] 是 x 的「上级」，根的上级是自己。find(x)：沿上级一路向上直到根——两个元素同簇当且仅当根相同。union(a, b)：把一个根挂到另一个根下面。例：parent = [0, 0, 1, 3]（元素 0 是根，1 的上级是 0，2 的上级是 1，3 自成一组）。find(2)：2 → 1 → 0，根是 0；find(3) = 3，所以 2 与 3 不同簇。union(2, 3) 把根 3 挂到根 0 下面，parent[3] = 0，现在四个元素同簇。两项优化让它快：按大小合并——总是把小组的根挂到大组的根下，树就不会长得太高；路径压缩——find 走过一路后，把沿途所有元素的上级直接改成根（上例 find(2) 之后 parent[2] = 0），下次再问就一步到位。Tarjan 1975 年证明，两项优化一起用时，n 次操作总共约需 n·α(n) 步，其中 α 是增长慢到离谱的反阿克曼函数：对任何能在物理宇宙里写出来的 n，α(n) ≤ 4。所以说「几乎线性」。（只用路径压缩而不按大小合并，保证的界要差一个对数因子。）

One array parent: parent[x] is x's superior, and a root is its own superior. find(x): follow superiors up to the root — two elements share a cluster iff their roots coincide. union(a, b): hang one root under the other. Example: parent = [0, 0, 1, 3] (element 0 is a root, 1’s superior is 0, 2’s is 1, and 3 is a group of its own). find(2): 2 → 1 → 0, root 0; find(3) = 3, so 2 and 3 are in different clusters. union(2, 3) hangs root 3 under root 0, parent[3] = 0, and all four now share a cluster. Two optimisations make it fast: union by size — always hang the smaller group’s root under the larger’s, so trees stay shallow; path compression — after find walks a path, re-point every element on it straight to the root (after find(2) above, parent[2] = 0), so the next query takes one step. Tarjan proved in 1975 that with both optimisations n operations take about n·α(n) steps in total, where α is the absurdly slow-growing inverse Ackermann function: α(n) ≤ 4 for any n that could be written down in the physical universe. Hence “almost linear”. (Path compression alone, without union by size, guarantees a bound worse by a logarithmic factor.)

4.3剥皮Peeling

生长结束后，每个簇里的警报数都是偶数（或者簇碰到了边界）。现在要在簇内找一批边，使它们的端点恰好是簇内的警报——但不必是最短的，簇本身已经不大。先借两个图论词。树是一组没有圈的、连成一片的边；簇的一棵生成树是用簇里的边把簇里所有检查连起来、又不含任何圈的那样一组边（每丢掉一条会闭合成圈的边，就离生成树近一步）。在树里选定一个根，每个点就有一个唯一的父节点（往根方向的下一个点）；只连着一条树边、又不是根的点叫叶子。做法叫剥皮peeling：在簇内取一棵生成树（触边的簇以边界为根）。反复取一片叶子：若叶子是警报，则把连接它的那条边计入修复并把父节点的警报状态翻转；然后删去叶子。树剥完，修复就得到了。：在簇内取一棵生成树（若簇碰到边界，就以边界为根），然后反复处理叶子。叶子若是警报，把连它的边计入修复，并把「警报」传给它的父节点（父节点原来是警报就变不是，原来不是就变是）；叶子若不是警报，什么也不做。删掉叶子，继续。树剥完，每条计入的边都恰好消掉了两端的警报状态，簇内症状清零。回放把「此刻还需要消掉的警报标记」叫缺陷：开始时缺陷就是警报，剥皮会把它从叶子一步步搬向根。

小例子：一个簇是一条直线 S1 – S2 – S3（两条边），S1、S3 亮着警报，以 S3 为根。叶子 S1 有缺陷：保留边 S1–S2，缺陷搬到 S2。此时 S2 成了叶子、带着缺陷：保留边 S2–S3，S3 的缺陷被翻掉（亮变不亮）。剩下根 S3，没有缺陷。修复 = 两条边，正是连接两个警报的那条链。

Once growth ends, every cluster holds an even number of alarms (or touches a boundary). We now need a set of edges inside the cluster whose endpoints are exactly the cluster's alarms — not necessarily the shortest, the cluster is small already. Two words from graph theory first. A tree is a connected set of edges with no cycle; a spanning tree of a cluster is a set of the cluster’s edges that connects all its checks without closing any cycle (dropping each edge that would close a cycle brings you one step closer to one). Choose a root in the tree; then every other node has a unique parent (the next node toward the root), and a non-root node touching only one tree edge is a leaf. The method is peelingTake a spanning tree inside the cluster (rooted at the boundary if the cluster touches one). Repeatedly take a leaf: if it is an alarm, add its edge to the repair and flip the parent's alarm status; then delete the leaf. When the tree is gone, the repair is complete.: take a spanning tree inside the cluster (rooted at the boundary if the cluster touches one) and process leaves repeatedly. If a leaf is an alarm, add its edge to the repair and pass the alarm to its parent (a parent that was an alarm stops being one, and vice versa); if the leaf is not an alarm, do nothing. Delete the leaf, continue. When the tree is gone, every chosen edge has cancelled the alarm status at both ends and the cluster's syndrome is clear. The player calls “an alarm mark still to be cancelled” a defect: at the start the defects are the alarms, and peeling carries them from the leaves toward the root.

A small example: a cluster is the straight line S1 – S2 – S3 (two edges) with alarms at S1 and S3, rooted at S3. Leaf S1 carries a defect: keep edge S1–S2 and move the defect to S2. Now S2 is a leaf carrying a defect: keep edge S2–S3, which flips S3’s defect off (lit becomes unlit). Only the root S3 remains, defect-free. Repair = two edges, exactly the chain joining the two alarms.

关键想法Key idea

The union-find decoder swaps “find shortest paths” for “test parity” and “merge sets” — two operations that barely compute. It does not guarantee the lightest repair, but it guarantees a cleared syndrome, and cluster size is naturally bounded by how sparse the errors are: at low error rates clusters are tiny and it nearly matches matching; its speed is almost linear and it fits in hardware. That trade between accuracy and speed is the theme of today's real-time decoder design.

时空译码：测量也会错Spacetime decoding: measurements fail too

前四章默认警报是真的。真实芯片上，辅助比特会出错、读出仪会看走眼——警报本身可能是假的。解药是反复测量，并只在读数变化时报警。这样一来，测量错误和数据错误在时空图上各有一种指纹，而译码仍然是同一个配对问题，只是多了一个维度。 The first four chapters assumed alarms were real. On a real chip, ancilla qubits fail and readout misfires — an alarm may be false. The remedy is to measure repeatedly and to raise an alarm only when a readout changes. 5.1假警报，与只报「变化」的探测器False alarms, and detectors that report only change

《Surface Code · 高中数学版》第 4 章说，一条检查的读数是由辅助比特收集、再单独读出的。若辅助比特在收集途中被翻、或读出仪读反了，这一轮的这条检查就报出一个错误的 ±1——数据比特其实好好的。单看一轮，真警报与假警报无法区分。但假警报有个弱点：它只持续一轮。下一轮重测，读数又回到正确值。相反，一个真实的数据错误会让该检查的读数从出错那一轮起持续翻转。于是改用探测器detector：同一条检查相邻两轮读数的异或，D(i,t) = s(i,t) ⊕ s(i,t−1)。读数不变时为 0，只有「变了」才亮。报警：D(i,t) = s(i,t) ⊕ s(i,t−1)，同一条检查相邻两轮读数不同才亮。这里 s(i,t) 是第 i 条检查在第 t 轮的读数，写成一位二进制数：读到 +1 记 0，读到 −1 记 1；⊕ 是一位数的异或，0 ⊕ 0 = 1 ⊕ 1 = 0，0 ⊕ 1 = 1 ⊕ 0 = 1；开始前没有错误，所以约定 s(i,0) = 0。

手算一遍。某条检查五轮的读数是 0, 0, 1, 1, 1（第 3 轮起一个数据错误让它一直报 −1）：探测器 D = 0, 0, 1, 0, 0，只在变化的那一轮亮一次。另一条检查的读数是 0, 0, 1, 0, 0（第 3 轮读反了一次）：D = 0, 0, 1, 1, 0，第 3、4 两轮各亮一次——一次读错留下的是时间上相邻的一对。

“The Surface Code · High-School Edition”, Chapter 4 explained that a check's value is collected by an ancilla and read out separately. If the ancilla is flipped midway or the readout misfires, that check reports a wrong ±1 this round — while the data qubits are fine. Within a single round, real and false alarms are indistinguishable. But a false alarm has a weakness: it lasts one round. Re-measure and the value returns to normal. A genuine data error, by contrast, flips that check's value persistently from the round it happens. So we raise alarms with detectorsThe XOR of the same check's readouts in consecutive rounds, D(i,t) = s(i,t) ⊕ s(i,t−1). Zero while the value stays put; lit only on change. instead: D(i,t) = s(i,t) ⊕ s(i,t−1), lit only when a check's value differs between consecutive rounds. Here s(i,t) is check i’s readout in round t written as one bit: +1 is recorded as 0 and −1 as 1; ⊕ is the XOR of bits, 0 ⊕ 0 = 1 ⊕ 1 = 0 and 0 ⊕ 1 = 1 ⊕ 0 = 1; there are no errors before the start, so by convention s(i,0) = 0.

Work one by hand. A check reads 0, 0, 1, 1, 1 over five rounds (from round 3 a data error keeps it at −1): its detectors are D = 0, 0, 1, 0, 0, lit once, in the round of the change. Another check reads 0, 0, 1, 0, 0 (misread once in round 3): D = 0, 0, 1, 1, 0, lit in rounds 3 and 4 — a single misreading leaves a pair adjacent in time.

5.4再往下一层：电路级噪声One layer down: circuit-level noise

现象学模型仍然是简化。真实的一轮测量由制备、四个 CNOT、读出组成，每一步都可能出错；一个辅助比特在第二个 CNOT 之后出错，会通过后两个 CNOT 传到两个数据比特上——《Surface Code · 高中数学版》第 4 章提过的 hook error（「钩子错误」：辅助比特上的一个故障，经过还没做完的 CNOT，变成数据比特上的两个错误）。在电路级噪声下，一个故障点亮的探测器不再总是「相邻的一对」：钩子错误留下的一对隔得更远；而一个同时带 X 与 Z 分量的故障，例如数据比特上的一个 Y 错误（Y = X·Z，只差一个相位），会同时点亮两族检查，一共四个探测器（图 5.1）。现代译码器先用模拟把每一种基本故障点亮哪些探测器、发生的概率多大列成一张表，叫探测器错误模型（detector error model）。可匹配图的一条边只能连两个探测器（或一个探测器与边界），所以只点亮一两个探测器的故障可以直接变成一条边，点亮三四个的故障就得先分解：拆成几块，每块只点亮一两个探测器，各当一条边。图 5.1 的 Y 错误拆成「Z 部分：点亮星 S1、S2」与「X 部分：点亮面 P1、P2」两条边，分别放进两族检查各自的匹配图。代价是丢掉关联：这两条边本来总是一起出现（一次故障），分开匹配时却被当成两次独立的故障，同时出现要付两份权重，这种组合的可能性就被低估了。以 PyMatching 为例，它的文档写明：从探测器错误模型建图时，点亮一两个探测器的故障成为边，点亮更多探测器、又没有给出分解的故障直接被忽略。尾声提到的 belief-matching 就是把这份关联找回来的一种办法。电路级噪声circuit-level noise：把一轮症状提取电路里的每个门、每次制备与读出都当作独立的出错位置。阈值数字依赖于具体电路与每步的错误定义，文献值约 0.5%–1%。下的阈值约 0.5%–1%（具体值取决于电路和「一步出错」的定义；例如 Fowler 等 2012 在他们的八步电路、每步错误率 p、匹配译码下得到 0.57%），这才是硬件团队真正对照的数字——第 6 章的账本会说清这些数字各自的前提。

The phenomenological model is still a simplification. A real round consists of preparation, four CNOTs and a readout, each of which can fail; an ancilla error after the second CNOT propagates through the remaining two onto two data qubits — the hook error mentioned in “The Surface Code · High-School Edition”, Chapter 4 (one fault on the ancilla which, through the CNOTs still to come, becomes two errors on data qubits). Under circuit-level noise a single fault no longer always lights “a neighbouring pair” of detectors: a hook error leaves a pair further apart, and a fault with both an X and a Z component, such as a Y error on a data qubit (Y = X·Z up to a phase), lights both families of checks, four detectors in all (Fig. 5.1). Modern decoders first tabulate, by simulation, which detectors each elementary fault lights and how likely it is: the detector error model. But an edge of a matching graph joins only two detectors (or one detector and the boundary), so a fault lighting one or two detectors becomes an edge directly, while a fault lighting three or four must first be decomposed: split into pieces that each light one or two detectors, each piece becoming an edge. The Y error of Fig. 5.1 splits into “the Z part, lighting stars S1 and S2” and “the X part, lighting plaquettes P1 and P2”, two edges placed in the matching graphs of the two check families. The price is lost correlation: the two edges always occur together (one fault), yet matched separately they count as two independent faults, their joint occurrence is charged two weights, and the combination is judged less likely than it is. PyMatching, for example, documents that when it builds a graph from a detector error model, faults lighting one or two detectors become edges, and faults lighting more that come without a suggested decomposition are ignored. Belief-matching, mentioned in the epilogue, is one way to recover that correlation. Under circuit-level noiseEvery gate, preparation and readout in one syndrome-extraction round is an independent fault location. 关键想法Key idea

测量错误不需要新思想，只需要新维度。探测器把「读数」换成「读数的变化」，于是测量错误变成时间方向上的一对端点，与数据错误在空间方向上的一对端点用同一个匹配算法处理。从此空间和时间是平等的两个方向：一个能骗过匹配的错误串，不论沿哪个方向延伸，都要凑齐许多个故障。实验通常把症状重复测约 d 轮，就是让时空块在时间方向上和空间方向一样「厚」。

Measurement errors need no new idea, only a new dimension. Detectors replace “the readout” with “the change in the readout”, turning a measurement error into a pair of endpoints along time, handled by the same matching algorithm as a data error's pair along space. From here on space and time are two equal directions: an error string that fools matching needs many faults whichever way it runs. Experiments usually repeat the syndrome for about d rounds precisely so that the spacetime block is as “thick” in time as it is in space.

阈值账本：译码器决定数字The threshold ledger: the decoder sets the number

「表面码的阈值是多少？」这个问题没有一个答案，有一本账。10.9%、10.3%、9.9%、2.9%、0.57%——每个数字都对，前提各不相同。这一章先立下记账规则，再把数字各归各位，最后让你在浏览器里亲手换译码器、看曲线搬家。 “What is the surface code's threshold?” has no single answer; it has a ledger. 10.9%, 10.3%, 9.9%, 2.9%, 0.57% — every number is right under its own premises. This chapter first lays down the bookkeeping rules, then files each number where it belongs, and finally lets you swap decoders in your browser and watch the curves move.

6.1一个数字，五个限定项One number, five qualifiers

一个阈值数字离开了它的模型就没有意义。至少要写清五件事：① 数据错误信道——只有 Z 错误？X 与 Z 独立？退极化？② 症状模型——完美测量、现象学（第 5 章）、还是电路级？③ 电路约定——若是电路级，一轮有几步、每步的错误怎么定义？④ 译码器——最大似然、匹配、并查集，以及是否利用了退化与相关性？⑤ 归一化——p 是每个位置、每步、每轮还是每周期的概率？缺任何一项，数字就只能留在文献综述里，不能写进读者面前的正文。

A threshold number is meaningless away from its model. Five things must be stated at minimum: ① the data error channel — Z errors only? independent X and Z? depolarising? ② the syndrome model — perfect, phenomenological (Ch. 5), or circuit-level? ③ the circuit convention — if circuit-level, how many steps per round and how is a step's error defined? ④ the decoder — maximum likelihood, matching, union-find, and whether it exploits degeneracy or correlations? ⑤ the normalisation — is p per location, per step, per round or per cycle? Missing any one, the number belongs in a literature survey, not in text put before a reader.

6.4Λ 不是 pth/pΛ is not pth/p

《Surface Code · 高中数学版》6.2 节的压制律 PL ≈ A(p/pth)⌈d/2⌉ 暗示：d 每加 2，逻辑错误率就除以 pth/p。实验上直接测量这个倍数，记作 Λ = PL(d)/PL(d+2)。Willow 芯片用离线神经网络译码器测得 Λ ≈ 2.14（换成实时译码器是 2.0 ± 0.1）：d 从 3 到 5、5 到 7，逻辑错误率各缩小约一半。同一份数据换个译码器，Λ 就变——这本身就说明 Λ 是整台机器加上它的译码器拟合出来的数，包含了非均匀的噪声、相关错误、译码器的精度与实时性；它不等于任何一行账本上的 pth 除以芯片的 p。把 Λ = 2.14 反推成「pth/p = 2.14」，是这本账最常见的误读。

The suppression law of “The Surface Code · High-School Edition”, §6.2 PL ≈ A(p/pth)⌈d/2⌉ suggests that each +2 in d divides the logical error rate by pth/p. Experiments measure that factor directly and call it Λ = PL(d)/PL(d+2). The Willow chip measured Λ ≈ 2.14 with an offline neural-network decoder (2.0 ± 0.1 with its real-time decoder): from d = 3 to 5 and 5 to 7, the logical error rate roughly halved each time. The same data give a different Λ under a different decoder — which by itself shows that Λ is a fit to the whole machine together with its decoder — heterogeneous noise, correlated errors, the decoder's accuracy and its real-time constraints; it equals no ledger row's pth divided by the chip's p. Reading Λ = 2.14 back as “pth/p = 2.14” is this ledger's most common misreading.

关键想法Key idea

阈值是「码 + 噪声模型 + 译码器 + 归一化」这一整套的属性，不是码单独的属性。换译码器，数字就动；换症状模型，数字动得更多。所以引用一个阈值时，带上它的五个限定项；比较两个阈值时，先确认它们在同一行。

A threshold is a property of the whole package — code + noise model + decoder + normalisation — not of the code alone. Change the decoder and the number moves; change the syndrome model and it moves more. So quote a threshold with its five qualifiers, and before comparing two, make sure they sit in the same row.

尾声Epilogue

从游戏到机器，与三条继续走的路From game to machine, and three roads onward

复盘整条推理链：译码是在两个类之间二选一（第 1 章）→ 对数把「最可能」变成「最短」，问题化为症状图上的最小重量完美匹配，配法数是双阶乘，而 Edmonds 的开花算法多项式时间可解（第 2 章）→ 贪心输给 3-2-3 陷阱，匹配输给 C(a+b, a) 条退化的链，这就是 10.9% 与 10.3% 之差（第 3 章）→ 并查集译码器用奇偶与合并换取几乎线性的速度（第 4 章）→ 探测器让测量错误变成时间方向的一对端点，同一个匹配问题多一维（第 5 章）→ 一本五项限定的账把所有阈值数字各归各位（第 6 章）。你现在读一篇译码器论文的摘要，应该能立刻找到它站在账本的哪一行。

Replaying the chain: decoding is a binary choice between two classes (Ch. 1) → logarithms turn “most probable” into “shortest”, the problem becomes a minimum-weight perfect matching on the syndrome graph, pairings number a double factorial, and Edmonds' blossom algorithm solves it in polynomial time (Ch. 2) → greed loses to the 3-2-3 trap and matching to C(a+b, a) degenerate chains, which is the gap between 10.9% and 10.3% (Ch. 3) → the union-find decoder trades parity and merging for almost-linear speed (Ch. 4) → detectors turn measurement errors into endpoint pairs along time, the same matching one dimension up (Ch. 5) → a five-qualifier ledger files every threshold number (Ch. 6). Reading a decoder paper's abstract now, you should be able to locate its ledger row at once.

三条继续走的路。其一，相关性：一个 Y 错误（同时是 X 错误和 Z 错误）同时触发 X 与 Z 两族检查，分开译码会丢掉这份线索。belief-matching 先用「置信传播」（让每个警报和它相邻的比特来回交换「这里出错的可能性有多大」的估计，几轮之后得到每个比特的出错概率）算出这些关联，再据此调整匹配的权重；Higgott 等（arXiv 2022）报告，在他们的电路级噪声模型下它的阈值约 0.94%，同一模型下普通最小重量匹配约 0.82%。其二，实时性：把匹配或并查集做进 FPGA（可以现场改写电路的芯片）与专用芯片，让译码稳定地跟上症状的节拍——Google 2024 年的实验已在 d = 5 上做到实时译码，平均延迟 63 微秒。其三，新码。qLDPC 码（量子低密度奇偶校验码）的定义有两半：每条检查只碰少数几个比特，每个比特也只被少数几条检查碰到，而且这两个数都不随码变大而增长。按这个定义，表面码本身就是 qLDPC 码（每条检查最多碰 4 个比特，每个比特最多在 4 条检查里）。人们说「新的 qLDPC 码」时，指的通常是表面码以外、检查不再局限于平面近邻的码，例如《BB 码》里的双变量自行车码：那里每个数据比特在 3 条 X 型检查里，一个 Z 错误就点亮 3 个警报。这样的码的症状图不再是「每个错误恰好点亮两个警报」的匹配结构，需要新工具，例如置信传播加有序统计译码（BP-OSD：置信传播给不出一致答案时，按出错概率从大到小挑出最可疑的一组比特，直接解一个线性方程组）。入口文献见下。

Three roads onward. One, correlations: a Y error (an X and a Z error at once) triggers both the X and the Z check families, and decoding them separately throws that clue away. Belief-matching first runs “belief propagation” (alarms and their neighbouring qubits repeatedly exchange estimates of “how likely is an error here”, yielding after a few rounds an error probability for each qubit) to capture such correlations, then reweights the matching accordingly; Higgott et al. (arXiv 2022) report a threshold of about 0.94% for it under their circuit-level noise model, against about 0.82% for standard minimum-weight matching in the same model. Two, real time: matching or union-find cast into FPGAs (chips whose circuitry can be rewired in the field) and dedicated chips, so that decoding reliably keeps pace with the syndrome — Google’s 2024 experiment already decoded in real time at d = 5 with an average latency of 63 µs. Three, new codes. A qLDPC code (quantum low-density parity-check code) is defined by two halves: every check touches only a few qubits, every qubit is touched by only a few checks, and neither number grows as the code gets larger. By this definition the surface code is itself a qLDPC code (each check touches at most 4 qubits, each qubit sits in at most 4 checks). When people speak of “new qLDPC codes” they usually mean codes beyond the surface code whose checks are no longer confined to planar neighbours, such as the bivariate bicycle codes of the BB tutorial: there every data qubit sits in 3 X-type checks, so a single Z error lights 3 alarms. The syndrome graphs of such codes lose the “every error lights exactly two alarms” matching structure and need new tools such as belief propagation with ordered-statistics decoding (BP-OSD: when belief propagation gives no consistent answer, pick the most suspicious set of qubits in order of error probability and solve a linear system for them directly). 诚实总账The honesty ledger

全篇简化五项，一次结清：① 「最轻配法」用 2m 状态的精确枚举，只到 16 个警报，超过退回贪心；② 并查集译码器整条边地生长，原文按半条边并规定生长顺序；③ 时空译码的实验台用一维重复码（二维时空图）演示，表面码的对应物是三维，算法相同；④ 所有蒙特卡洛只加 Z 错误、只看星检查，X 一侧完全对称；⑤ 账本里的数字是各文献在各自模型下的报告值，本页实验台的交叉点因贴片小、轮数少而偏低。以上不影响任何定性结论。

Five simplifications, settled in one bill: ① the “lightest pairing” uses exact enumeration over 2m states up to 16 alarms, then falls back to greedy; ② the union-find decoder grows whole edges, whereas the paper grows half-edges in a prescribed order; ③ the spacetime bench demonstrates on a 1D repetition code (a 2D spacetime graph), the surface-code analogue being 3D with the same algorithm; ④ every Monte-Carlo adds Z errors only and watches star checks, the X side being fully symmetric; ⑤ the ledger's numbers are the literature's values under their own models, and this page's crossings sit low because patches are small and rounds few. None of this touches any qualitative conclusion.
