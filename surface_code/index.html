  • 逻辑操作Logical operations→ 剪开、缝合：用格点手术做逻辑门。把两块贴片沿边界缝合，一排只碰邻近比特的新检查连乘起来，就测出了两个逻辑比特的联合奇偶 Z̄Z̄；测完再拆开。一个逻辑 CNOT受控非门：控制比特为 1 时翻转目标比特，为 0 时不动。 要三块贴片：控制 C、目标 T，和一块事先制备成逻辑 |+⟩（0 与 1 等权叠加）的辅助贴片 A。先缝合 C 与 A，测 Z̄CZ̄A；再缝合 A 与 T，测 X̄AX̄T（同样的联合奇偶，换成 ± 基来问）；最后把 A 的比特全部按 Z 读出，A 用完即弃。三个 ±1 读数按一条固定规则记账修正，结果就是 CNOT（逻辑操作篇第 5 章）；最后算清每次缝合为什么要维持 d 轮测量、要花多少时空。Cut and stitch: logical gates by lattice surgery. Stitch two patches together along a boundary, and a row of new checks, each touching only nearby qubits, multiplies out to the joint parity Z̄Z̄ of the two logical qubits; then cut them apart again. A logical CNOTControlled-NOT: flips the target qubit when the control is 1 and leaves it alone when the control is 0. takes three patches: the control C, the target T, and a helper patch A prepared beforehand in the logical |+⟩ (an equal superposition of 0 and 1). First stitch C to A and measure Z̄CZ̄A; then stitch A to T and measure X̄AX̄T (the same joint parity, asked in the ± basis); finally read every qubit of A in the Z basis and discard A. The three ±1 outcomes feed a fixed record-keeping rule, and the result is a CNOT (Logical operations, Chapter 5); finally, why each stitch must be held for d rounds of measurement and what it costs in space and time. 高中数学high-school

Toward bigger codes. The surface code is itself an LDPC code, but one block stores only 1 logical qubit; the families those two tutorials cover, such as BB codes, keep the same limits yet store many logical qubits in one block.

范围说明Scope note

Atlas 的构造器（按定义生成检查矩阵的程序）覆盖的是未旋转的平面族 [[2L²−2L+1, 1, L]]：一块 L × L 的贴片上，一组 L² 个比特加一组 (L−1)² 个比特，合计 L² + (L−1)² = 2L²−2L+1 个。条目导读各篇里的参数、证书与推导都针对这个子族。更宽的表面码集合还包括旋转版（图 1）：把 L = 3 贴片四个角上的比特剪掉，13 个数据比特剩 9 个；角旁的三腿边界检查各少一条腿，变成两腿，而每条斜边上相邻的两条两腿检查类型不同、只共用 1 个比特，会互相冲突，所以每条边只留一条；转 45° 看，剩下的 9 个比特排成 3 × 3，最短的逻辑算符仍要 3 个比特，码距不变。一般地，旋转版在同样码距 d 下只用 d² 个数据比特。此外还有 XZZX 版（每条检查混用 X 和 Z）、在贴片上挖洞或放缺陷来存信息的编码等，它们在「关系」篇中单独说明。

The Atlas constructor (the program that builds the check matrices from the definition) covers the unrotated planar family [[2L²−2L+1, 1, L]]: on an L × L patch, one set of L² qubits plus one set of (L−1)² qubits, L² + (L−1)² = 2L²−2L+1 in all. Parameters, certificates and derivations in the entry guides refer to that subfamily. The broader surface-code collection also contains the rotated version (Fig. 1): trim the four corner qubits of the L = 3 patch and 13 data qubits become 9; each three-leg boundary check next to a corner loses a leg and becomes two-leg, and on each slanted edge the two neighbouring two-leg checks are of different types and share just 1 qubit, so they would clash and only one per edge is kept; turned by 45°, the remaining 9 qubits form a 3 × 3 grid, and the shortest logical operator still needs 3 qubits, so the distance is unchanged. In general the rotated version reaches distance d with only d² data qubits. Further members are the XZZX version (each check mixes X and Z), encodings that store information in holes or defects cut into the patch, and others; these are treated separately in “Relations”.

Each guide is a single HTML file sharing the same page style and interactive components: switch language top right, the left rail follows your scroll, amber dashed citations pop up definition cards, and every lattice experiment and Monte-Carlo simulation (sample the noise many times at random, count the fraction of failures) runs locally in your browser with nothing uploaded. Numbers and citations keep the Atlas evidence words, which say how each was obtained: verified = recomputed independently by a machine, and it matched; bounded = only an upper and a lower bound are recorded; claimed = a paper says so, the Atlas has not recomputed it; demonstrated = an experimental paper has reported it on real hardware; proposed = the design is concrete enough to simulate or cost, but no hardware has run it.
