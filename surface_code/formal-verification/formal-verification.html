第 1 章Chapter 1

纸上的证明，与机器核对的证书A proof on paper, and a certificate a machine checks

参数页里 d = L（d = 码距，L = 家族变量，即格子边长）的证明是一段人类推理：读者点头，就算通过。证书走的是另一条路：把「为什么对」写成一份数据，让一个不认识表面码的程序逐位重算。这一章讲清两条路各自能到哪里。 The proof of d = L (d = distance, L = the family variable, i.e. the grid side) in the parameters guide is a piece of human reasoning: the reader nods and it passes. A certificate takes a different route: it writes “why this is true” as data and lets a program that has never heard of the surface code recompute it bit by bit. This chapter sets out how far each route reaches.

1.1证书 = 数据 + 一台不信任任何人的检查器A certificate = data + a checker that trusts no one

参数页的码距定理是好证明：短、对任何 L 成立、有文献支撑。但它依赖读者理解「不相交代表」这个想法。机器不理解想法，只会算。QEC-Bank 的证书certificate：绑定在一个有限对象上的数据包，附带一个可独立重算的检查器。检查器从对象本身重算每个字段并要求逐位相等；不接受任何「据称」的值。因此另起一套规则：一份证书是一包数据（例如「这个矩阵的化简结果是这些行、主元在这些列」），配一个通用检查器；检查器从对象本身重新算一遍，要求与数据完全一致。QEC-Bank 的契约文件（docs/design-references/2026-08-21-atlas-formal-ir-v1-contract.md）用一句话立下标准：「Supplying a rank integer alone is not a certificate」——只写一个「秩 = 6」不算证书，必须给出能被重算的化简矩阵。

The distance theorem in the parameters guide is a good proof: short, valid for every L, backed by the literature. But it relies on the reader grasping the idea of “disjoint representatives”. A machine grasps no ideas; it only computes. So the QEC-Bank certificateA data package bound to one finite object, together with an independently re-runnable checker. The checker recomputes every field from the object itself and demands bit-for-bit equality; no “stated” value is accepted. plays by different rules: a certificate is a package of data (for instance “the reduced form of this matrix has these rows, with pivots in these columns”) plus a generic checker; the checker recomputes everything from the object itself and requires exact agreement. The QEC-Bank contract (docs/design-references/2026-08-21-atlas-formal-ir-v1-contract.md) sets the standard in one sentence: “Supplying a rank integer alone is not a certificate”. Writing “rank = 6” is not a certificate; you must hand over a reduced matrix that can be recomputed.

另一条设计原则同样直白：证书「is generated from data; there are no per-code theorem files」。没有一份叫「表面码定理」的文件。同一台检查器对表面码、环面码、任何 CSS 码都做一样的事——正因为它对码一无所知，它的通过才有说服力。

A second design principle is equally blunt: a certificate “is generated from data; there are no per-code theorem files”. There is no file called “the surface-code theorem”. The same checker does the same thing for the surface code, the toric code, any CSS code, and precisely because it knows nothing about codes, its passing verdict carries weight.

1.2Lean Complete v1 是什么，不是什么What Lean Complete v1 is, and is not

QEC-Bank 的检查器用Lean一种交互式定理证明器兼编程语言。用 Lean 写的检查器，其正确性本身可以被 Lean 的内核审计（例如列出它依赖的全部公理）。实现，取名 qec-atlas-lean-complete-v1（表面码 card.yaml 中 lean.checker 一栏的原文）。它在 2026-08-21 的 QEC-Bank 任务 T195（QEC-Bank 用 T 加编号管理每一项工程任务）中被「封存」（sealed），意思是三件事：源代码逐字节冻结，以后改一个字节就不再是这台检查器；在一个断网的隔离环境里，从零构建和重放已有证书的全部测试都通过；并用 Lean 的内核列出它依赖的公理，结果只有 Lean 标准库自带的三条（propext、Classical.choice、Quot.sound，数学家日常默认的逻辑规则），源码里也没有 sorry（Lean 里「这一步先跳过、当作已证明」的占位符）。换句话说，检查器没有偷偷假设任何额外的东西。

The QEC-Bank checker is written in LeanAn interactive theorem prover and programming language. A checker written in Lean can itself be audited by Lean's kernel, for example by listing every axiom it depends on. and is named qec-atlas-lean-complete-v1 (the literal lean.checker field of the surface-code card.yaml). It was “sealed” in QEC-Bank task T195 (the QEC-Bank numbers every engineering task T plus a number) on 2026-08-21, which means three things: its source bytes are frozen, so changing one byte makes it a different checker; inside a network-denying sandbox, every test of building from scratch and of replaying existing certificates passed; and Lean's kernel listed the axioms it depends on, which turned out to be only the three shipped with Lean's standard library (propext, Classical.choice, Quot.sound, the logical rules mathematicians assume every day), with no sorry (Lean's placeholder for “skip this step and treat it as proved”) in the source. In other words, the checker assumes nothing extra behind your back.

同样重要的是 T195 结果文件写明它不接受什么：「It does not accept a per-code theorem, family-distance theorem, decoder, threshold, hardware model, Formal IR compiler, proposal referee, entry backfill, or claim promotion.」换句话说，参数页那条对所有 L 成立的定理，不在机器核对的范围内；机器只核对一个个有限实例。这也解释了 QEC-Bank 形式化页上那句总纲：「Eligible small exact-distance certificates are additive; claims outside Lean Complete v1 keep their existing evidence origin」——证书是加上去的一层，加不上的声明保留原有的证据词（verified / bounded / claimed）。

Equally important, the T195 result states what it does not accept: “It does not accept a per-code theorem, family-distance theorem, decoder, threshold, hardware model, Formal IR compiler, proposal referee, entry backfill, or claim promotion.” In other words, the all-L theorem of the parameters guide is outside what the machine checks; the machine checks finite instances one at a time. This also explains the headline sentence of the QEC-Bank formal-verification page: “Eligible small exact-distance certificates are additive; claims outside Lean Complete v1 keep their existing evidence origin”. A certificate is a layer added on top; claims that cannot receive one keep their original evidence word (verified / bounded / claimed).

下面就是机器实际拿到的第一个对象：L3，13 个数据比特（n = 13）、6 条 X 检查、6 条 Z 检查，存 1 个逻辑比特（k = 1；n、k 的记账见 Toric Code 直觉教程「记账」一节，码距 d 的定义见同教程「它的致命弱点」一节）。本篇接下来的一切——身份、证书、复现——都是对这一块（以及 L4、L5 两块）说的，不是对「表面码」这个族名说的。

Below is the first object the machine actually receives: L3, with 13 data qubits (n = 13), 6 X-checks and 6 Z-checks, storing one logical qubit (k = 1; the n, k bookkeeping is in the toric guide's “ledger” section, and distance d is defined in its “fatal flaw” section). 第 2 章Chapter 2

有限对象的身份：Formal IR 与语义哈希The identity of a finite object: Formal IR and the semantic hash

要对一个对象出证书，先得说清「哪个对象」。「L3 表面码」是个名字，名字会被改、会被重用。QEC-Bank 给每个实例一个由内容决定的 64 位十六进制身份，任何一个比特的改动都会换一个身份。 To certify an object you must first say which object. “The L3 surface code” is a name, and names get renamed and reused. The QEC-Bank gives every instance a 64-hex-digit identity determined by its content; change one bit and the identity changes.

2.1Formal IR：一份只放数学对象的文档The Formal IR: a document holding only the mathematical object

Formal IRFormal intermediate representation：QEC-Bank 为每个已发布实例生成的、无散文的 JSON 文档（schema 为 qec-atlas-formal-ir-v1），把有限码对象、构造轨迹、声明、见证、证书和附件分放在固定字段里。是 QEC-Bank 为每个实例生成的一份 JSON 文档。JSON 是一种纯文本数据格式：花括号 {…} 里是一组字段，每个字段写成 "名字": 值，值可以是数、字符串、方括号 […] 里的列表，或者又一个 {…}。把内存里的数据写成这样一串文字、最终存成一串字节，叫序列化。这份文档顶层恰好十个字段：schema, profile, semantic, semantic_hash, claims, traces, witnesses, certificates, attachments, provenance。契约刻意把四件常被混在一起的东西分开：① 有限数学对象本身；② 生成它的构造轨迹；③ 关于它的命题、见证与证书；④ 电路、基准、引文等非形式化附件。只有第 ① 项进入哈希。原文给了理由：「a new proof or citation must not change which code object the hash names」——多一篇论文引用、多一份证书，对象还是那个对象。

The Formal IRFormal intermediate representation: the prose-free JSON document (schema qec-atlas-formal-ir-v1) the QEC-Bank generates for every shipped instance, placing the finite code object, construction traces, claims, witnesses, certificates and attachments in fixed fields. is a JSON document the QEC-Bank generates per instance. JSON is a plain-text data format: curly braces {…} hold a set of fields, each written "name": value, where a value can be a number, a string, a list in square brackets […], or another {…}. Writing data held in memory out as such text, and finally as a string of bytes, is called serialisation. This document has exactly ten top-level fields: schema, profile, semantic, semantic_hash, claims, traces, witnesses, certificates, attachments, provenance. The contract deliberately separates four things that are often mixed: (1) the finite mathematical object itself; (2) a construction trace that produces it; (3) propositions, witnesses and certificates about it; (4) non-formal attachments such as circuits, benchmarks and citations. Only item (1) feeds the hash. The reason is stated: “a new proof or citation must not change which code object the hash names”. Add a paper, add a certificate, and the object remains the same object.

两类证书，与 L5 少的那一类Two certificate classes, and the one L5 lacks

结构有效性证书人人都有，它核对 n、k 和 CSS 条件（n = 物理比特数，k = 逻辑比特数，d = 码距）。小规模精确码距枚举证书只有 L3、L4 有，它把「没有更轻的逻辑算符」这句话逐个候选地写下来。L5 为什么没有？两个原因，一个是策略，一个是算术。 Every instance holds a structural-validity certificate, which checks n, k and the CSS condition (n = physical qubits, k = logical qubits, d = distance). Take the length-3 repetition code closed into a ring (the closed chain of §3.1 of the relations guide). Its check matrix has three rows: r₁ = (1, 1, 0), r₂ = (0, 1, 1), r₃ = (1, 0, 1). Gaussian elimination mod 2: the pivot of column 1 is r₁; r₃ also has a 1 there, so replace it by r₃ + r₁ = (0, 1, 1). The pivot of column 2 is r₂; clear it from the other rows: r₁ + r₂ = (1, 0, 1) and r₃ + r₂ = (0, 0, 0). The result is

RREF = [ 1 0 1 ; 0 1 1 ]　·　主元列pivot columns = {1, 2}　·　rank = 2

第三行消成了 0，说明三条检查里有一条是另外两条的乘积（这就是环面码「白送的恒等式」的一维版）。证书存的正是这两行和主元列 {1, 2}。检查器拿到原矩阵，自己再消元一遍，得到的两行和主元列必须与证书逐位相同。因为 RREF 对给定矩阵是唯一的，这种比对不依赖谁算、怎么算；而秩 = 主元个数 = 2 就可以直接从这份数据读出，并用它得到 k。只写「rank = 2」行不行？检查器当然也能自己从原矩阵算出秩，再和这个整数比对。RREF 和主元列必须给，是这种证书格式（canonical-rref-v1）的规定：契约说「单给一个秩整数不算证书」，证书要携带能逐位比对的化简结果，于是比对的对象从一个数变成整张化简矩阵和主元位置。给了它们，检查器也并不省掉重算：它照样从原矩阵消元一遍，再逐位比对。

The third row became 0: one of the three checks is the product of the other two (the one-dimensional version of the toric code's “free identity”). The certificate stores exactly these two rows and the pivot columns {1, 2}. The checker takes the original matrix, eliminates again on its own, and its two rows and pivot columns must equal the certificate's bit for bit. Because the RREF of a given matrix is unique, the comparison does not depend on who computed it or how; and rank = number of pivots = 2 can be read off this data and used for k. Would “rank = 2” alone do? A checker could of course compute the rank from the original matrix itself and compare it with that integer. The RREF and pivots are required by this particular certificate format (canonical-rref-v1): the contract says that “supplying a rank integer alone is not a certificate”, so the certificate carries a reduced matrix that can be compared bit by bit, and the comparison is made against a whole reduced matrix and its pivot positions instead of one number. Including them does not spare the checker the recomputation: it still reduces the original matrix itself and then compares bit by bit.

诚实说明Honesty box

「L5 没有精确码距证书」不是「L5 的码距可疑」。d = 5 有对所有 L 成立的定理撑着，比任何穷举更一般。证书体系只是诚实地记录：这一台机器、这一版策略下，能被逐位核对的是 L3 和 L4。这条边界是版本化的（@1、v1），将来可能移动；移动之前，页面上的词不变。

4.2默认验证不需要 Lean，也不需要网络Default verification needs neither Lean nor the network

证书那一层由仓库级门禁 python tools/build_formal_unification.py verify 覆盖。formal/ir/README.md 说明它做什么：「Default verification never invokes Lean or the network: it regenerates the Python projection, checks every certificate independently, compares the committed bytes, and validates the sealed-runtime identity.」也就是说，日常验证是用 Python 独立重算每份证书并与提交的字节比对；真正调用 Lean 的 replay 命令是「evidence-producing」的，只能在一项明确授权的 Board 任务下（Board 是 QEC-Bank 的任务登记表，每项任务写明谁在改什么），用那台封存的运行时执行。那台运行时目前只能在一种精确的机器上运行：苹果 ARM 芯片、macOS 的 Darwin 内核 25.5.0（平台标识 arm64-apple-darwin25.5.0），Lean 版本 v4.30.0-rc2。所以你在自己的机器上能做的是：重跑 Python 投影与证书核对；不能做的是：重新产出 Lean 证据。两者 QEC-Bank 都写在明处。

The certificate layer is covered by the repository gate python tools/build_formal_unification.py verify. formal/ir/README.md explains what it does: “Default verification never invokes Lean or the network: it regenerates the Python projection, checks every certificate independently, compares the committed bytes, and validates the sealed-runtime identity.” That is, everyday verification recomputes every certificate independently in Python and compares against the committed bytes; the replay command that actually invokes Lean is “evidence-producing” and may run only under an explicitly authorised Board task (the Board is the QEC-Bank task register, where each task states who changes what), on the sealed runtime. That runtime currently runs on exactly one kind of machine: Apple ARM hardware with macOS's Darwin kernel 25.5.0 (platform string arm64-apple-darwin25.5.0), Lean version v4.30.0-rc2. So on your own machine you can rerun the Python projection and certificate checks; you cannot regenerate the Lean evidence. The QEC-Bank states both in the open.

4.3诚实边界：当前证书不覆盖的东西The honest boundary: what certificates do not cover today

derivations.md 的「provenance split」把表面码条目的结论分成三层。机器验证：n、k、CSS 结构、两个小实例的精确码距。定理与文献 + 可重跑见证：L5 的下界与上界，故标 bounded。纯文献声明：「Thresholds and hardware results are not properties of a bare check matrix. They remain literature claims with the complete noise model and decoder written beside each number.」阈值（译码器教程的阈值账本列了四个，每个都写明它的噪声模型与译码器）、Willow 的 Λ = 2.14 ± 0.02（码距 3、5、7 的存储实验，离线神经网络译码器，arXiv:2408.13687；Λ：码距每增 2 时逻辑错误率的压制倍数，是设备与译码器的拟合值，不是阈值 pth 与物理错误率 p 之比 pth/p 的直接测量）——每个数都属于不同的噪声模型与译码器，QEC-Bank 在译码器教程的阈值账本里逐条列出限定项；它们今天都在 Lean Complete v1 之外：当前的证书只看一个有限的检查矩阵，这些声明保留原有的证据来源。同理，逻辑操作（格点手术、横向门等）在 QEC-Bank 中一律是 claimed：T195 明说它不接受「decoder, threshold, hardware model」。

The “provenance split” in derivations.md sorts the surface-code entry's conclusions into three layers. Machine-verified: n, k, CSS structure, and the two small exact distances. Theorem and literature plus a re-runnable witness: the L5 lower and upper bounds, hence bounded. Literature claims only: “Thresholds and hardware results are not properties of a bare check matrix. They remain literature claims with the complete noise model and decoder written beside each number.” The thresholds (the decoders guide's threshold ledger lists four, each with its noise model and decoder) and Willow's Λ = 2.14 ± 0.02 (a distance-3, 5, 7 memory experiment decoded offline by a neural network, arXiv:2408.13687; Λ: the factor by which the logical error rate drops when the distance grows by 2, a device-and-decoder fit, not a direct measurement of the ratio pth/p of threshold to physical error rate) each belong to a different noise model and decoder; the QEC-Bank lists the qualifiers line by line in the threshold ledger of the decoders guide. All of them are outside Lean Complete v1 today: the current certificates see only a finite check matrix, and these claims keep their existing evidence origin. Likewise every logical operation (lattice surgery, transversal gates and so on) is claimed in the QEC-Bank: T195 states outright that it accepts no “decoder, threshold, hardware model”.

易错点Pitfall

尾声Epilogue

三个哈希，五份证书，一条边界Three hashes, five certificates, one boundary

回放一遍：证书是数据加一台不信任任何人的检查器，一次只核对一个有限对象；Lean Complete v1 是 QEC-Bank 封存的那台检查器，明文列出它不接受的东西。每个实例的身份是 semantic 对象规范字节的 SHA-256，证明与引用都不进入哈希。三个实例都持有 structural-validity（n、k、css）；L3、L4 另持 small-exact-distance-enumeration（741 与 64 875 个候选，均在 65 536 上限内）；L5 因超限且本就 bounded 而没有，证据词不变。两条命令能在你的机器上重跑 Python 层的一切；Lean 证据的再生产只在封存运行时上进行。阈值、硬件与逻辑操作目前在 Lean Complete v1 之外。

Replay: a certificate is data plus a checker that trusts no one, checking one finite object at a time; Lean Complete v1 is the QEC-Bank's sealed checker, with an explicit list of what it does not accept. Each instance's identity is the SHA-256 of the canonical bytes of its semantic object; proofs and citations never enter the hash. All three instances hold structural-validity (n, k, css); L3 and L4 also hold small-exact-distance-enumeration (741 and 64,875 candidates, both under the 65,536 ceiling); L5 does not, being over the ceiling and bounded to begin with, and its evidence word is unchanged. Two commands rerun everything at the Python layer on your machine; regenerating Lean evidence happens only on the sealed runtime. Thresholds, hardware and logical operations are outside Lean Complete v1 today.
