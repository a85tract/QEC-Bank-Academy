穿不同的衣服 The same code
in different clothes

一个量子码就是一份检查清单。把比特重新编号、把某个比特上的 X 和 Z 对调、换一组等价的检查来写这份清单——清单的样子全变了，码却一个字没变，只是换了衣服。Atlas 里已经有 184 张卡片，其中至少有一对是同一个码穿了两套衣服：环面码 [[18,2,3]] 既是 BB 条目的实例 toric_L3，又是两条 3 比特重复码的超图积，而 gross 码 [[144,12,12]] 在两张卡上分别写着「d = 12，bounded」和「d = ?」。原则上把所有衣服试一遍就能判定「这两份清单是不是同一个码」，但在 18 个比特上就已是 1029 件；今天没有一台能在真实尺寸上做出这个判定的机器，Atlas 只能比对字节是否完全一致，再靠人手画几条「它们其实一样」的边。这一篇讲这道开放问题是什么、Atlas 现在怎么凑合、为什么我们想要答案、一个合格的答案长什么样。 A quantum code is a list of checks. Renumber the qubits, swap X and Z on some qubit, write the list with a different but equivalent set of checks: the list looks completely different, yet the code has not changed by a single letter. It has only changed clothes. The Atlas already holds 184 cards, and at least one pair among them is one code in two outfits: the toric code [[18,2,3]] is both the BB entry's instance toric_L3 and the hypergraph product of two 3-bit repetition codes, while the gross code [[144,12,12]] reads “d = 12, bounded” on one card and “d = ?” on another. In principle trying every outfit decides “are these two lists the same code?”, but at 18 qubits that is already 1029 outfits; no machine today makes the decision at real sizes, and the Atlas can only compare bytes for exact identity and then draw a few “these are really the same” edges by hand. This guide explains what the open problem is, how the Atlas copes today, why we want the answer, and what a qualifying answer looks like.

第 1 章Chapter 1

这个问题用人话说是什么：换衣服的三种方式The problem in plain words: three ways of changing clothes

先在一个 3 比特的经典码上亲手做三件事：换编号、换一组检查来写清单、再到环面码上把 X 和 Z 对调。每一件都让清单面目全非，却都没有改变码。把这三件事合起来命名，就是「局部等价」；问「两份清单是不是局部等价」，就是这道开放问题。 First do three things by hand on a 3-bit classical code: renumber the bits, write the list with a different set of checks, then go to the toric code and swap X with Z. Each one makes the list unrecognisable, and none of them changes the code. Naming the three together gives “local equivalence”; asking “are these two lists locally equivalent?” is this open problem.

1.1玩具一：3 比特重复码，换编号、换检查Toy one: the 3-bit repetition code, renumbered and rewritten

取 Toric Code 教程 2.2 节的 3 比特重复码：合法的码字只有 000 和 111。它的检查清单可以写成两条：「第 1 位 = 第 2 位吗」「第 2 位 = 第 3 位吗」。按第 0 章事实 1 写成矩阵，每行一条检查、每列一个比特：

Take the 3-bit repetition code of section 2.2 of the toric-code guide: the only legal codewords are 000 and 111. Its check list can be written as two lines: “is bit 1 = bit 2?” and “is bit 2 = bit 3?”. As a matrix per fact 1 of Chapter 0, one row per check and one column per bit:

H1 = [ 1 1 0 ; 0 1 1 ]

记号：H1 = 第一套写法的检查矩阵；分号隔开两行；每行三个数对应比特 1、2、3。

Notation: H1 = the check matrix of the first way of writing; the semicolon separates the two rows; the three numbers in a row belong to bits 1, 2, 3.

第一件事：换编号。把比特 1 和比特 3 的名字对调。第一条检查变成「第 3 位 = 第 2 位吗」，第二条变成「第 2 位 = 第 1 位吗」；矩阵变成 [ 0 1 1 ; 1 1 0 ]——两行掉了个头，两列也掉了个头。码字 000 和 111 对调编号之后还是 000 和 111。清单换了样子，码没变。

First: renumber. Swap the names of bit 1 and bit 3. The first check becomes “is bit 3 = bit 2?”, the second “is bit 2 = bit 1?”; the matrix becomes [ 0 1 1 ; 1 1 0 ], the two rows turned around and the two columns turned around. The codewords 000 and 111 are still 000 and 111 after the renaming. The list changed its look; the code did not.

第二件事：换一组检查。还是原来的编号，但这次写「第 1 位 = 第 2 位吗」和「第 1 位 = 第 3 位吗」：

Second: pick a different set of checks. Keep the original numbering, but this time write “is bit 1 = bit 2?” and “is bit 1 = bit 3?”:

H2 = [ 1 1 0 ; 1 0 1 ]

H2 和 H1 只有一行相同。它们是同一个码吗？是：一个串通过 H2 的两条检查，就是「1 = 2 且 1 = 3」，于是三位全等，只剩 000 和 111；反过来也一样。更机械的看法：H1 的第二行 0 1 1 等于 H2 两行按位相加（1+1 = 0，不进位）：1 1 0 + 1 0 1 = 0 1 1。第 0 章事实 3 说过，清单里几条检查的乘积（这里是按位相加）也算检查；所以两份清单生成的是同一组检查，只是各挑了两条当代表。人话：一个码不是它的检查清单，而是清单能生成的全部检查。

H2 and H1 share only one row. Are they the same code? Yes: a string passing both checks of H2 satisfies “1 = 2 and 1 = 3”, so all three bits agree and only 000 and 111 remain; and conversely. More mechanically: the second row of H1, 0 1 1, equals the bitwise sum of the two rows of H2 (1+1 = 0, no carry): 1 1 0 + 1 0 1 = 0 1 1. Fact 3 of Chapter 0 said that products of list entries (bitwise sums here) count as checks; so the two lists generate the same set of checks and merely picked two different representatives each. In plain words: a code is not its check list but everything the list generates.

1.2玩具二：环面码里把 X 和 Z 对调Toy two: swap X and Z in the toric code

现在到量子码。下面的沙盘是 L = 3 的环面码：18 个比特住在边上，9 个顶点各一条 X 型星检查（碰周围 4 条边），9 块面各一条 Z 型面检查（碰四周 4 条边）。点一条边放一个 Z 错误，看是哪两颗星报警。

Now a quantum code. The sandbox below is the toric code with L = 3: 18 qubits on the edges, an X-type star check at each of 9 vertices (touching its 4 edges), a Z-type plaquette check on each of 9 faces (touching its 4 sides). Click an edge to place a Z error and see which two stars fire.

第三件事：在每个比特上把 X 和 Z 对调。有一个 2 × 2 矩阵专门做这件事，叫阿达马矩阵 HHadamard：H = (1/√2)·[1 1 ; 1 −1]。用高中矩阵乘法可以验证 H·X·H = Z，H·Z·H = X（H 自己乘自己是单位矩阵）。它是一个「单比特换基」：换一种坐标看同一个比特，X 和 Z 的角色互换。——注意它和检查矩阵 H 撞了名字，本篇之后写 Had。在全部 18 个比特上各做一次 Had，每条 X 型星检查变成 Z 型，每条 Z 型面检查变成 X 型。新清单：顶点上是 Z 型 4 腿检查，面上是 X 型 4 腿检查。它和原来的清单一个字母都对不上。

Third: swap X and Z on every qubit. A 2 × 2 matrix does exactly this, the Hadamard matrix HH = (1/√2)·[1 1 ; 1 −1]. High-school matrix multiplication verifies H·X·H = Z and H·Z·H = X (H times itself is the identity). It is a “single-qubit change of basis”: look at the same qubit in different coordinates and the roles of X and Z swap.; it clashes in name with the check matrix H, so from here on it is written Had. Apply Had once on each of the 18 qubits: every X-type star check becomes Z type, every Z-type plaquette check becomes X type. The new list: Z-type 4-leg checks at vertices, X-type 4-leg checks on faces. Not one letter matches the old list.

它是同一个码吗？先数不变的东西：n 还是 18；检查还是 9 + 9 条、各 4 腿、独立的还是 16 条，所以 k 还是 2；最轻的逻辑算符还是绕一圈的 3 条边，d 还是 3。再看几何：在环面上，把每个顶点换成一块面、每块面换成一个顶点（每条边换成穿过它的那条边），得到的还是一张 3 × 3 的正方形网格。所以「Z 型星、X 型面」这份清单，其实就是原清单先换编号（每条边改叫穿过它的边）再换基的结果。两件衣服叠着穿，里面还是那个环面码。

Is it the same code? Count what did not change first: n is still 18; there are still 9 + 9 checks with 4 legs each, still 16 independent ones, so k is still 2; the lightest logical is still a loop of 3 edges, so d is still 3. Then the geometry: on the torus, replacing every vertex by a face and every face by a vertex (every edge by the edge crossing it) yields again a 3 × 3 square grid. So the list “Z-type stars, X-type plaquettes” is the original list renumbered (each edge renamed after the edge crossing it) and then re-based. Two outfits worn one over the other; inside is the same toric code.

1.3给这三件事起名：局部等价Naming the three moves: local equivalence

三种换衣服的方式，合起来叫局部等价local equivalence：两份检查清单，若能通过「重新给比特编号」「在单个比特上换基（把 X、Y、Z 三个字母重新命名）」「换一组生成同样检查的代表」这三种操作互相变到，就说它们是同一个码的两种写法。「局部」指的是每一步只碰一个比特。。说人话：

The three ways of changing clothes together are called local equivalenceTwo check lists are two ways of writing the same code if one can be turned into the other by “renumbering the qubits”, “changing basis on single qubits (renaming the three letters X, Y, Z)”, and “choosing a different set of representatives generating the same checks”. “Local” means every step touches only one qubit.. 为什么只允许这三种？因为它们都不会改变任何逻辑算符的重量：编号和改名只是换名字，换代表根本没动码本身。一旦允许同时碰两个比特的操作（比如把比特 1 的错误「传」到比特 2 上），一条重量 1 的错误可以变成重量 2，码距就会变，那就不是换衣服而是换人了。Atlas 登记检查时不记符号（sign-free），所以本篇也不追究 ± 号。

Why only these three? Because none of them changes the weight of any logical operator: renumbering and renaming are just names, and changing generators does not touch the code at all. Once operations acting on two qubits at once are allowed (say, “copying” an error from qubit 1 onto qubit 2), a weight-1 error can become weight 2 and the distance can change; that is no longer new clothes but a new person. The Atlas records checks without signs (sign-free), so this guide does not track ± signs either.

1.4问题：谁来判定，用什么判定The problem: who decides, and by what

现在可以说出这道开放问题了。给两份检查清单，判定它们是否局部等价；更好的是给每个码算出一个典范指纹canonical fingerprint：由码算出来的一串数或字符，满足两条：(i) 换任何衣服它都不变；(ii) 真正不同的两个码，它必然不同。有了它，「是不是同一个码」就变成「两串指纹相等吗」。——换衣服不变、不同的码必不同。高中里最熟的典范形是分数约分：2/4 和 3/6 长得不一样，约成最简分数都是 1/2，于是一比就知道相等；「最简分数」就是分数的典范形。Wanted 板的原文是：

Now the open problem can be stated. Given two check lists, decide whether they are locally equivalent; better still, compute for every code a canonical fingerprintA string of numbers or characters computed from the code with two properties: (i) it does not change under any change of clothes; (ii) two genuinely different codes must get different fingerprints. With it, “same code?” becomes “equal fingerprints?”., unchanged by clothes and different for different codes. The most familiar canonical form from school is reducing fractions: 2/4 and 3/6 look different, both reduce to 1/2, and equality is read off at a glance; “lowest terms” is the canonical form of a fraction. 检查站Checkpoint第 1 章Chapter 1
下面哪一个操作不是「换衣服」——做了它之后，得到的可能是一个真正不同的码？Which of the following is not a change of clothes, so that after it you may hold a genuinely different code?

对。前两项是 1.3 节的操作 ①、②，最后一项是操作 ③，都不改变码。「把字母从一个比特搬到另一个」同时碰了两个比特，会改变检查碰哪些比特、可能改变码距——那是换人，不是换衣服。

Right. The first two are moves ① and ② of 1.3, the last is move ③; none changes the code. “Moving a letter from one qubit to another” touches two qubits at once, changes which qubits the check touches and may change the distance: a new person, not new clothes.

再想：1.3 节的三种操作分别是换编号、单比特改名、换一组代表。你选的那一项属于其中之一，所以它是换衣服。找那个同时碰两个比特的。

Think again: the three moves of 1.3 are renumbering, renaming letters on one qubit, and changing representatives. Your choice is one of them, hence a change of clothes. Look for the one touching two qubits at once.

Atlas 的 Python 代码库 qeclib 里，真正给一个码算「指纹」的函数只有一个：qeclib/benchmarks.py 里的 checkmatrix_fingerprint(cm)。它的注释原文是 “Fingerprint exact stabilizer/gauge values, shapes, rows, and qubits.” 它做的事，逐行读是这样的：先写下一个版本标签 stab-gauge-uint8-v1；再写下检查矩阵的形状（几行乘几列，比如 toric_L3 是 18 行 × 36 列——每个比特占两列，一列记 X、一列记 Z）；再把矩阵的全部 0/1 按原来的顺序逐字节写下；如果这个码另有一组「不在乎」的检查（gauge，《不在乎的比特》专讲），也写下，否则写 no-gauge；最后把这一长串字节交给 SHA-256一种哈希函数：把任意长的一串字节压成固定的 64 个十六进制字符。同样的输入永远得到同样的输出；输入改一个比特，输出面目全非；从输出反推输入被认为不可行。，得到 64 个字符。

In the Atlas Python library qeclib exactly one function computes a “fingerprint” of a code: checkmatrix_fingerprint(cm) in qeclib/benchmarks.py. Its docstring reads “Fingerprint exact stabilizer/gauge values, shapes, rows, and qubits.” Line by line, this is what it does: write a version tag stab-gauge-uint8-v1; write the shape of the check matrix (rows × columns; toric_L3 is 18 rows × 36 columns, two columns per qubit, one for X and one for Z); write every 0/1 of the matrix in its original order, byte by byte; if the code has a second list of “don't-care” checks (gauge, the subject of “Don't-care qubits”) write it too, otherwise write no-gauge; finally hand the whole byte string to SHA-256A hash function: it compresses a byte string of any length into a fixed 64 hexadecimal characters. Same input, same output, always; change one bit of input and the output is unrecognisable; recovering the input from the output is believed infeasible. and get 64 characters.

指纹 = SHA-256( 标签 ‖ 形状 ‖ 矩阵字节 ‖ gauge )fingerprint = SHA-256( tag ‖ shape ‖ matrix bytes ‖ gauge )

记号：‖ 读「接上」，把两串字节首尾相连；标签 = 版本标签 stab-gauge-uint8-v1；矩阵字节按原顺序写入；gauge 一项没有时写 no-gauge。「按原顺序」是下面这段话的全部要点。

Notation: ‖ reads “concatenated with”, joining two byte strings end to end; tag = the version tag stab-gauge-uint8-v1; the matrix bytes are written in their original order; the gauge item reads no-gauge when absent. “In order” is the whole point of the next paragraph.

用第 1 章的三件事去试它。操作 ①，把两个比特换编号：矩阵的两列对调，字节顺序变了，SHA-256 给出完全不同的 64 个字符。操作 ②，在一个比特上 X ↔ Z：那个比特的两列互换，同样变。操作 ③，H1 换成 H2：一行的内容变了，同样变。也就是说，这枚指纹对三种换衣服全都敏感——它是衣服的指纹，不是人的指纹。它认得出的只有「字节完全一致的复制品」。Atlas 也正是这样用它的：每张卡片的构造记录里写着 match: exact-checkmatrix-v1，复现契约里写着期望的比对结果是 “byte-and-semantic-identical”——机器重新构造一次，和登记的矩阵逐字节相同才算通过。这对「同一台构造器有没有被改动」是完美的；对「两台不同的构造器造出的是不是同一个码」则一个字也说不了。

Try the three moves of Chapter 1 on it. Move ①, renumber two qubits: two columns of the matrix swap, the byte order changes, SHA-256 returns 64 entirely different characters. Move ②, X ↔ Z on one qubit: that qubit's two columns swap; changes again. Move ③, H1 to H2: one row's content changes; changes again. So this fingerprint is sensitive to all three changes of clothes: it is a fingerprint of the clothes, not of the person. All it recognises is “a byte-for-byte identical copy”. And that is exactly how the Atlas uses it: every card's construction record says match: exact-checkmatrix-v1, and the reproduction contract expects the comparison result “byte-and-semantic-identical”; the machine rebuilds the code and passes only if the result matches the registered matrix byte for byte. For “has the same constructor been tampered with?” this is perfect; for “do two different constructors build the same code?” it says nothing at all.

3.3今天一个 Atlas 用户做不到的事What a user of the Atlas cannot do today

合起来说三件。一，问「我手里这份检查清单，Atlas 里有没有」：今天只能得到「字节一致 / 不一致」的回答，换过编号就查不到。二，问「这两张卡是不是同一个码」：只能看有没有人画过边，没画不代表不是（BB 关系导读用的说法是「尚未调研，不是负结论」）。三，把一张卡上的 verified / bounded 借给另一张：没有等价证明，借了就是抄。这三件事都不需要新的物理，只需要一台判定局部等价的机器——它今天不存在。

Three things in all. One, ask “is this check list in my hand already in the Atlas?”: today the answer is only “bytes identical / not”, and a renumbered copy is invisible. Two, ask “are these two cards the same code?”: only whether someone drew an edge can be seen, and no edge does not mean no (the BB relations guide's phrase is “not yet surveyed, not a negative conclusion”). Three, lend one card's verified / bounded to another: without an equivalence proof, lending is copying. None of the three needs new physics, only a machine deciding local equivalence, and that machine does not exist today.

第 4 章Chapter 4

合格的答案长什么样，为什么难What a qualifying answer looks like, and why it is hard

板上把难度标为 open-research。这一章先说清什么算解决（一台判定机，或一枚典范指纹），再用高中的计数说明为什么「把所有衣服都试一遍」不可行，最后说明「找一套足够细的不变量」为什么不是工程量的问题。 The board rates the difficulty open-research. This chapter first says what counts as solved (a decision machine, or a canonical fingerprint), then uses high-school counting to show why “try every outfit” is infeasible, and finally why “find a fine enough set of invariants” is not a matter of effort.

4.1什么算解决：一台判定机，或一枚典范指纹What counts as solved: a decision machine, or a canonical fingerprint

statement 里有两个「或」着的目标。弱的：一台判定机——输入两份检查清单，输出「局部等价 / 不等价」，并且答「等价」时附上那件衣服（编号对应表、每个比特的改名、代表的换法），让任何人能一步步核对。强的：一枚典范指纹——输入一份清单，输出一串字符，满足 1.4 节的两条性质；有了它，判定机就是「比较两串字符」，而且 184 张卡片只需各算一次、两两比较。分数约分是强的那种；「两个分数交叉相乘看是否相等」是弱的那种。两种都算完整解决；只给出更多不变量（比如第 2 章末那个「共用比特」的问题）算进展，不算解决，因为不变量相同仍推不出等价。

The statement holds two targets joined by “or”. The weak one: a decision machine that takes two check lists and outputs “locally equivalent / not”, attaching, when it says “equivalent”, the outfit itself (the renumbering table, the renaming on each qubit, the change of representatives) so anyone can verify step by step. The strong one: a canonical fingerprint that takes one list and outputs a string with the two properties of 1.4; with it, the decision machine is “compare two strings”, and the 184 cards need one computation each and pairwise comparison. Reducing fractions is the strong kind; “cross-multiply two fractions and compare” is the weak kind. Either counts as a full solution; merely adding more invariants (such as the “shared bits” question at the end of Chapter 2) counts as progress, not as a solution, because equal invariants still do not imply equivalence.

4.2为什么不能把衣服全试一遍Why every outfit cannot be tried

最笨的判定机：把甲的所有衣服都穿一遍，看有没有一件和乙字节一致。衣服有多少件？操作 ① 换编号：n 个比特的排法有 n! 种（n 的阶乘，n × (n−1) × … × 1）。操作 ② 改名：每个比特 6 种，共 6n 种。两者相乘：

The dumbest decision machine: put every outfit on A and see whether one matches B byte for byte. How many outfits? Move ① renumbering: n qubits can be ordered in n! ways (n factorial, n × (n−1) × … × 1). Move ② renaming: 6 per qubit, 6n in all. Multiply:

n = 18:　18! × 618 ≈ 6.4 × 1015 × 1.0 × 1014 ≈ 6.5 × 1029
n = 144:　144! × 6144 ≈ 5.6 × 10249 × 1.1 × 10112 ≈ 6 × 10361

记号：n! 读「n 的阶乘」；6n 读「6 的 n 次方」；≈ 读「约等于」。这几个数是本篇自己算的。操作 ③（换代表）还没算进去，它另有一大堆。

Notation: n! reads “n factorial”; 6n reads “6 to the n”; ≈ reads “approximately”. These numbers were computed for this guide. Move ③ (changing representatives) is not yet included and adds a large multitude of its own.

对比《大码的码距》1.4 节的 218 = 262 144：码距那道题在 18 比特上一下午能穷举，这道题在 18 比特上就已经是 1029，比宇宙年龄的秒数还多 12 个数量级。换句话说，「换衣服」的自由度比「放错误」的自由度大得多，穷举在玩具尺寸就已经失效。判定机必须绕开枚举，直接看穿衣服——这就回到了不变量。

Compare 218 = 262 144 from §1.4 of “Distance for large codes”: the distance problem can be exhausted in an afternoon at 18 qubits, while this problem is already 1029 at 18 qubits, twelve orders of magnitude more than the age of the universe in seconds. In other words, the freedom of “changing clothes” is far larger than the freedom of “placing errors”, and exhaustion fails already at toy size. A decision machine must bypass enumeration and see through the clothes directly, which brings us back to invariants.

4.3为什么「够细的不变量」不是工程量问题Why “fine enough invariants” is not a matter of effort

Wanted 板给每道题两种难度。hard-engineering = 「知道怎么做，但要做很多」，比如把一个已有算法接进 Atlas 的验证器；open-research = 「没人知道怎么做」。这道题标的是 open-research。诚实地说难在哪里：

The board grades every problem one of two ways. hard-engineering = “we know how, but there is a lot to do”, such as wiring an existing algorithm into the Atlas verifier; open-research = “nobody knows how”. This problem is rated open-research. Honestly, where the difficulty lies:

难点Difficulty在玩具上是什么样What it looks like on the toy
不变量要「完备」Invariants must be “complete”2.2 节的「共用比特」问题分开了甲和乙，但你怎么知道再没有一对码，连这个问题也答一样却仍不同？每加一个不变量只能堵一个洞，「没有洞了」需要一个证明，而不是更多例子。The “shared bits” question of 2.2 separated A from B, but how do you know there is no further pair answering even that question alike while still differing? Each added invariant plugs one hole; “no holes left” needs a proof, not more examples.
量子比经典多两件衣服Quantum has two more outfits than classical经典码只有操作 ①、③；量子码多了操作 ②（每个比特 6 种改名）。1.2 节里 X ↔ Z 之后连「星」和「面」都互换了，不变量必须对这种整体翻转也视而不见。Classical codes have only moves ① and ③; quantum codes add move ② (6 renamings per qubit). After X ↔ Z in 1.2 even “stars” and “plaquettes” swapped roles; the invariants must be blind to such wholesale flips too.
「等价」的边界本身要定The boundary of “equivalent” must itself be fixed2.3 节两条边都在说「像但不是」：环面码与表面码内部相同、码空间不同；蜂窝码每一帧像环面码、整部电影不像。判定机先要被告知，哪些差别算衣服、哪些算人——对有「不在乎比特」的码（《不在乎的比特》）和随时间变的码（《两张测量时间表》），这条线今天都还没画好。Both edges of 2.3 say “alike but not the same”: toric and surface share a bulk but not a code space; every honeycomb frame resembles a toric code, the whole movie does not. A decision machine must first be told which differences are clothes and which are a person; for codes with don't-care qubits (“Don't-care qubits”) and codes that change in time (“Two measurement schedules”) that line is not yet drawn today.

所以这不是「写更多代码」的问题。原则上问题是可判定的——4.2 节的穷举总会停下——缺的是一套算得快、又完备的不变量：「这一套不变量相同 ⇔ 局部等价」这句话，连同算它的方法。在它出现之前，每一样工具都只有一头可信：字节指纹说「相同」时可信（字节一致 ⇒ 同一份清单），说「不同」时不可信（H1、H2 字节不同却是同一个码）；不变量说「不同」时可信，说「相同」时不可信。本篇不假装知道那套完备的不变量长什么样。

So this is not a “write more code” problem. In principle the question is decidable, the exhaustion of 4.2 always terminates; what is missing is a set of invariants that is fast to compute and complete: the sentence “this set of invariants agrees ⇔ locally equivalent”, together with a way to compute it. Until it exists, every tool is trustworthy at one end only: the byte fingerprint when it says “same” (identical bytes ⇒ the same list) but not when it says “different” (H1 and H2 differ in bytes yet are one code); invariants when they say “different” but not when they say “same”. This guide does not pretend to know what that complete set looks like.

从这里出发能做什么：手证一对不等价，再看两台机器造同一个码What you can do from here: prove one pair inequivalent by hand, then watch two machines build one code

两个练习。第一个用一句话替 2.2 节的甲、乙证明「不是换编号能变到的」——这是不变量的正用，也是今天唯一可靠的方向。第二个在 BB 实验台上用多项式造出环面码 [[18,2,3]]，亲眼看第 2 章那张「没有边」的表里第一行。最后是往哪里走。 Two exercises. The first proves in one sentence that A and B of 2.2 are “not reachable by renumbering”, the proper use of an invariant and the only reliable direction today. The second builds the toric code [[18,2,3]] from polynomials on the BB bench, to see with your own eyes the first row of Chapter 2's “no edge” table. Then, where to go next.

5.1手证：甲、乙不等价，且再算一个不变量By hand: A and B are inequivalent, plus one more invariant

第一步，确认它们的四个不变量确实相同（表已给出；重量直方图请自己数一遍 8 个码字）。第二步，找一个换编号不变的量并算出不同的值：数「重量 2 的码字对中，共用比特的对数」。甲：000011 与 000101 共用第 6 位，000011 与 000110 共用第 5 位，000101 与 000110 共用第 4 位——3 对。乙：三个重量 2 码字互不相交——0 对。换编号只改名字不改「共用」，所以 3 ≠ 0 一票否决：甲不是乙的换编号版本。第三步（可选），验证甲、乙各自的三行确实生成表里的 8 个码字：把三行两两相加、三行全加，再加上全零串。

Step one, confirm the four invariants really agree (the table gives them; count the weight histogram yourself over the 8 codewords). Step two, find a quantity unchanged by renumbering and compute different values: count “pairs of weight-2 codewords that share a bit”. A: 000011 and 000101 share bit 6, 000011 and 000110 share bit 5, 000101 and 000110 share bit 4: 3 pairs. B: the three weight-2 codewords are pairwise disjoint: 0 pairs. Renumbering changes names, not sharing, so 3 ≠ 0 is a veto: A is not a renumbered B. Step three (optional), verify that the three rows of A and of B generate the 8 codewords in the table: add the rows pairwise, add all three, and include the all-zero string.

陷阱Pitfall

若你换一对码来练，算出的所有不变量都相同，你没有证明它们等价——只是没找到区别。要证等价，必须交出那件衣服：一张编号对应表（和量子情形下每个比特的改名），让对方逐位核对。

If you practise on another pair and every invariant you compute agrees, you have not proved them equivalent; you have merely found no difference. To prove equivalence you must hand over the outfit: a renumbering table (and, in the quantum case, each qubit's renaming) that the other side can verify bit by bit.

5.2实验台：用多项式 1 + x、1 + y 造出环面码On the bench: build the toric code from the polynomials 1 + x, 1 + y

下面的 BB 实验台预设为 toric3：A = 1 + x、B = 1 + y、l = m = 3。它按 BB 的配方（BB 直觉教程 3.1 节）从两个多项式造出一张 18 比特的检查矩阵，读数里两块矩阵的秩各 8，k = 18 − 16 = 2。点一条检查，数它的 4 条腿：这就是环面码的星与面，只是比特按「左层 9 个、右层 9 个」编号，而不是按「横边、竖边」。它和 1.2 节沙盘里的码只差操作 ①（换编号）。同一张矩阵还可以由第三台机器造出：超图积 HGP(C₃, C₃)（qLDPC 教程 3.1 节）。三台机器、一个码：toric 卡片与超图积之间有一条人画的边和一个机器 derived 的视图（2.3 节；两台构造器恰好逐字节一致），而 BB 的 toric_L3 与它们之间没有任何边、任何比对。

The BB bench below is preset to toric3: A = 1 + x, B = 1 + y, l = m = 3. Following the BB recipe (BB intuition guide, §3.1) it builds an 18-qubit check matrix from the two polynomials; the readout shows both blocks with rank 8, k = 18 − 16 = 2. Click a check and count its 4 legs: these are the toric code's stars and plaquettes, with the qubits numbered “9 in the left layer, 9 in the right” rather than “horizontal edges, vertical edges”. It differs from the code in the sandbox of 1.2 by move ① (renumbering) alone. The same matrix is built by a third machine as well, the hypergraph product HGP(C₃, C₃) (qLDPC guide, §3.1). 尾声Epilogue

三件衣服、一枚字节指纹、一对分不开的码Three outfits, one byte fingerprint, one inseparable pair

回放一遍。一个码不是它的检查清单，而是清单生成的全部检查；换编号、单比特改名、换一组代表，三种操作都不改变码，合称局部等价。Atlas 今天有 184 张卡，判定「同一个码」的工具只有两样：checkmatrix_fingerprint——把矩阵字节按原顺序交给 SHA-256，三种换衣服都会让它改变，所以它只认字节一致的复制品；以及人手登记的 curated 边，写得细，但没人写就没有。环面码 [[18,2,3]] 以 toric_L3、HGP(C₃,C₃)、toric 三副面孔出现，只有 toric 与 HGP 之间有边（因为字节恰好一致）；gross 的同一张矩阵在两张卡上分别写 d = 12 bounded 与 d = ?，中间没有边。n、k、d、重量直方图这四样不变量能一票否决、不能一票通过：一对 6 比特经典码四样全同却不是换编号能变到的。合格的答案是一台判定机或一枚典范指纹；问题原则上可判定，但穷举衣服在 18 比特上已是 1029，而「算得快又完备的不变量」今天不存在——难度 open-research。

Replay. A code is not its check list but everything the list generates; renumbering, renaming letters on single qubits and changing representatives leave the code unchanged and together are called local equivalence. The Atlas holds 184 cards today and has two tools for “the same code”: checkmatrix_fingerprint, which feeds the matrix bytes in their original order to SHA-256 and changes under all three changes of clothes, so it recognises only byte-identical copies; and hand-registered curated edges, precise in their fine print but absent unless someone writes them. The toric code [[18,2,3]] appears with three faces, toric_L3, HGP(C₃,C₃) and toric, and only toric and HGP are joined by an edge (their bytes happen to agree); gross's one matrix reads d = 12 bounded on one card and d = ? on another, with no edge in between. The four invariants n, k, d and weight histogram can veto but never approve: a pair of 6-bit classical codes agrees on all four yet is not reachable by renumbering. A qualifying answer is a decision machine or a canonical fingerprint; the question is decidable in principle, but exhausting outfits is already 1029 at 18 qubits, and “fast, complete invariants” do not exist today; difficulty open-research.
