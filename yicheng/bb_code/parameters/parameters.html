1.3构造器拿到四个变量后做了什么What the constructor does with the four variables

atlas/bivariate_bicycle/constructor.py 只有几十行，做的正是 BB 教程 2.3 节与3.1 节的翻译：① 造一个 l × l 的循环移位 S（第 i 行的 1 在第 (i+1) mod l 列，这是「正向」约定）；② 令 x = Sl ⊗ Im、y = Il ⊗ Sm；③ 对 a_terms 的每一对 (a, b) 算出置换矩阵 xayb，全部按 mod 2 相加，得到 lm × lm 的矩阵 A，B 同理；④ 拼出 HX = [A | B]，HZ = [Bᵀ | Aᵀ]；⑤ 交给 CheckMatrix.from_css 并调用 validate()，即当场核对 CSS 条件。格子 (i, j) 的编号是 i·m + j（先数行再数列），左层比特占第 0 到 lm−1 列，右层占第 lm 到 2lm−1 列。

atlas/bivariate_bicycle/constructor.py is a few dozen lines and performs exactly the translation of BB guide section 2.3 and section 3.1: (1) build an l × l cyclic shift S (row i has its 1 in column (i+1) mod l, the “forward” convention); (2) set x = Sl ⊗ Im, y = Il ⊗ Sm; (3) for each pair (a, b) in a_terms form the permutation matrix xayb and add them all mod 2, giving the lm × lm matrix A, and likewise B; (4) assemble HX = [A | B], HZ = [Bᵀ | Aᵀ]; (5) hand them to CheckMatrix.from_css and call validate(), which checks the CSS condition on the spot. Site (i, j) is numbered i·m + j (rows first, then columns); left-layer qubits occupy columns 0 to lm−1, right-layer qubits columns lm to 2lm−1.

这套约定不是抽象的。reproduce.py 断言 gross 第 0 条 X 检查（格子 (0,0)）恰好碰这六个比特：[1, 2, 18, 75, 78, 84]。自己数一遍：A 的三项 x³、y、y² 把 (0,0) 送到 (3,0)、(0,1)、(0,2)，编号 3·6+0 = 18、1、2，这是左层的三腿；B 的三项 y³、x、x² 送到 (0,3)、(1,0)、(2,0)，编号 3、6、12，加上右层的偏移 72 得 75、78、84。第 0 条 Z 检查是 [3, 60, 66, 76, 77, 126]：Bᵀ 把三次平移倒过来走，(0,−3) = (0,3) → 3、(−1,0) = (11,0) → 66、(−2,0) = (10,0) → 60；Aᵀ 在右层给 (−3,0) = (9,0) → 54+72 = 126、(0,−1) = (0,5) → 77、(0,−2) = (0,4) → 76。下面的实验台把预设固定在 gross，点任何一条检查看它的六条腿，把读数里的比特编号和这两行对一对。图上横轴是 i（x 方向，向右），纵轴是 j（y 方向，向上）；实心点是左层比特，空心点是右层比特；高亮的腿旁边标着它的编号，格子 (0,0) 在左下角。

1.4范围：一个固定约定下的环面 BB 码Scope: torus BB codes under one fixed convention

必须说清一次：Atlas 的这个条目对应 eczoo（Error Correction Zoo，一个公开的纠错码百科网站）的集合 qcga（正式身份 eczoo-entity:qcga#collection），构造器覆盖的是平移不变、写在有限二维环面上、按 HX = [A | B]、HZ = [Bᵀ | Aᵀ] 拼装的那一族。文献里同样冠以 BB 之名的开边界平面版、剪枝版、自对偶版、多变量版、qudit 版，都不是这个构造器生成的对象，它们的 n、k、d 不在本篇的表里；Atlas 的「关系」侧面和 pedagogy/variant-boundary-map.md 专门处理它们。反过来，环面码本身在这一族之内：A = 1 + x、B = 1 + y 就是它（BB 教程 3.1 节）——这正是 Atlas 把 toric_L3 收作第二个实例的原因。

This must be said once, plainly: this Atlas entry corresponds to the eczoo (the Error Correction Zoo, a public encyclopaedia website of error-correcting codes) collection qcga (formal identity eczoo-entity:qcga#collection), and the constructor covers the family that is translation-invariant, written on a finite two-dimensional torus, and assembled as HX = [A | B], HZ = [Bᵀ | Aᵀ]. The open-boundary planar, pruned, self-dual, multivariate and qudit variants that the literature also files under “BB” are not objects this constructor produces, and their n, k, d are not in this guide's tables; the Atlas “Relations” facet and pedagogy/variant-boundary-map.md handle them. Conversely, the toric code itself is inside the family: A = 1 + x, B = 1 + y is exactly it (BB guide section 3.1), which is why the Atlas keeps toric_L3 as its second instance.

关键想法Key idea

一族码 = 一个构造器 + 几个家族变量。BB 的四个变量里，l、m 定环面大小，a_terms、b_terms 定两个多项式；约定（正向移位、先行后列、左层在前、交换转置）由构造器固定。Atlas 的每一条 [[n,k,d]] 记录都挂在一个实例上——四个变量取定后的那个有限对象——而不是挂在「BB 码」这个族名上，因为只有有限对象能被机器逐位重算。

A code family = one constructor + a few family variables. Of BB's four, l and m fix the torus size and a_terms, b_terms fix the two polynomials; the conventions (forward shift, rows before columns, left layer first, swapped transposes) are fixed by the constructor. Every [[n,k,d]] record in the Atlas hangs on an instance, the finite object obtained once the four variables are set, never on the family name “BB code”, because only a finite object can be recomputed bit by bit by a machine.

四个变量进去，四类数字出来：比特数 n、检查重量、逻辑比特数 k、码距 d。前三类是「一算便知」的算术，第四类要两份证书。这一章按 Atlas 的 gross-parameter-ledger.md 逐项走，每项先给公式，再代入 gross 与 toric_L3 的数。 Four variables go in, four kinds of numbers come out: the qubit count n, the check weight, the logical count k, the distance d. The first three are arithmetic you can do at once; the fourth needs two certificates. This chapter follows the Atlas file gross-parameter-ledger.md item by item, giving the formula first and then the gross and toric_L3 values.

2.1n = 2lm：每个格子两个比特n = 2lm: two qubits per site

环面有 N = lm 个格子，每个格子放两个数据比特（左层一个、右层一个），所以 n = 2lm。矩阵语言里：A、B 都是 N × N，[A | B] 有 2N 列，列数就是比特数。gross：N = 12 × 6 = 72，n = 144；toric_L3：N = 3 × 3 = 9，n = 18。人话：n 数的是数据比特，账本原文特意补了一句，它「excludes syndrome ancillas, couplers, routing workspace, spare modules, and decoder hardware」——不含帮手比特、耦合器、布线、备用模块和译码硬件。第 5 章再把帮手加回来。

The torus has N = lm sites and each site carries two data qubits (one in the left layer, one in the right), so n = 2lm. In matrix language: A and B are both N × N, [A | B] has 2N columns, and the column count is the qubit count. Gross: N = 12 × 6 = 72, n = 144; toric_L3: N = 3 × 3 = 9, n = 18. In plain words: n counts data qubits; the ledger adds deliberately that it “excludes syndrome ancillas, couplers, routing workspace, spare modules, and decoder hardware”. Chapter 5 puts the helpers back.

2.2检查重量 = |A| + |B|；左层比特度 = |A| 条 X 加 |B| 条 Z，右层反过来Check weight = |A| + |B|; a left-layer qubit meets |A| X-checks and |B| Z-checks, a right-layer qubit the reverse

一个单项式是置换矩阵，每行每列恰有一个 1；一个有 |A| 个不同约化项的多项式，矩阵每行每列恰有 |A| 个 1（BB 教程 2.3 节）。于是 HX = [A | B] 的每一行有 |A| + |B| 个 1：每条 X 检查碰 |A| + |B| 个比特；HZ 同理。反过来看列：左层比特所在的列在 A 里有 |A| 个 1、在 Bᵀ 里有 |B| 个 1，所以每个左层比特被 |A| 条 X 检查和 |B| 条 Z 检查碰到；右层比特的列在 B 里、在 Aᵀ 里，所以反过来，被 |B| 条 X 检查和 |A| 条 Z 检查碰到。|A| = |B| 时两层一样；不相等时两层不同，例如 bb5（|A| = 2，|B| = 3）：左层比特 2 X + 3 Z，右层 3 X + 2 Z。gross：|A| = |B| = 3，检查重量 6，比特度 3 + 3。账本特意说，「degree six」这个压缩说法会丢掉 Pauli 类型的划分，而电路里三条 X 型和三条 Z 型相互作用「have different ancilla preparations and fault propagation」——帮手比特的制备方式与错误传播路径都不同，所以要写成 3 + 3。reproduce.py 不是从「三项」推出重量，而是逐行逐列真的数了一遍：A、B 的每行每列都是 3，HX、HZ 的每行都是 6、每列都是 3。

A monomial is a permutation matrix, exactly one 1 per row and per column; a polynomial with |A| distinct reduced terms is a matrix with exactly |A| ones per row and per column (BB guide section 2.3). So every row of HX = [A | B] has |A| + |B| ones: every X check touches |A| + |B| qubits, and likewise HZ. Reading columns instead: a left-layer qubit's column has |A| ones in A and |B| ones in Bᵀ, so every left-layer qubit sits in |A| X checks and |B| Z checks; a right-layer qubit's column lies in B and in Aᵀ, so it is the other way round, |B| X checks and |A| Z checks. When |A| = |B| the two layers agree; otherwise they differ, e.g. bb5 (|A| = 2, |B| = 3): left-layer qubits 2 X + 3 Z, right-layer 3 X + 2 Z. Gross: |A| = |B| = 3, check weight 6, qubit degree 3 + 3. The ledger points out that the compressed phrase “degree six” loses the Pauli split, while in a circuit the three X-type and three Z-type interactions “have different ancilla preparations and fault propagation”, so it is written 3 + 3. reproduce.py does not infer the weight from “three terms”; it actually counts every row and column: every row and column of A and B is 3, every row of HX and HZ is 6, every column is 3.

The stabilizer count gives k = n − rank HX − rank HZ. BB guide section 4.1 proves the two ranks are equal (call the value r), so k = 2lm − 2r = 2(lm − r). The ledger adds why the two may simply be added: the CSS stabilizer rank is their sum “because pure-X and pure-Z binary symplectic rows cannot cancel each other”; pure-X and pure-Z rows live in different halves of the symplectic representation and cannot cancel. Gross: Gaussian elimination over GF(2) gives rank HX = rank HZ = 66, stabilizer rank 132, k = 144 − 132 = 12. toric_L3: both ranks 8, k = 18 − 16 = 2.

k = 逻辑比特数，n = 数据比特数，HX/HZ = X/Z 检查矩阵，rank = 秩（独立检查数），r = 两个相等的秩，lm − r = 秩的亏损（多余的检查条数）。k = logical qubits, n = data qubits, HX/HZ = the X/Z check matrices, rank = number of independent checks, r = the common value of the two ranks, lm − r = the rank deficit (redundant checks).

亏损 lm − r 有一个更有解释力的读法（BB 教程 4.2 节）：把一对多项式 (u, v) 送到 uA + vB，所有这样的 uA + vB 组成理想 (A, B)（补课 2.A 在 toric_L3 上数了一遍）。按「系数 ↔ 格子」的编码（xiyj ↔ 格子 (i, j)，编号 i·m + j）写成矩阵，这个映射是 [Aᵀ | Bᵀ] 乘列向量 (u; v)，不是 [A | B]：构造器约定下，A 的第 0 列落在编号 4、5、54 上，那是 Aᵀ 的图案；A 的第 0 行（1、2、18）才是多项式 A 的图案，所以 Aᵀ 的第 s 列正是把 A 的形状平移到格子 s。[Aᵀ | Bᵀ] 与 HZ = [Bᵀ | Aᵀ] 只差左右两块的次序，秩相同，都是 r = 66，这就是理想的维数；剩下的 72 − 66 = 6 维是商空间 R/(A,B)。账本原话：「the dual side has the same six-dimensional defect, leaving twelve logical dimensions in the middle」。两个重要的诚实限定紧跟其后。第一，这是「a computed fact for these periods and polynomials」——对这组 l、m、A、B 算出来的事实，不是所有三项 BB 多项式都编码 12 个比特的承诺。第二，「Three terms in A and three in B do not determine the rank: changing their exponents changes the common ideal and can change k」——三项不决定 k，改指数就改理想，k 随之变。最直接的证据你在 BB 教程见过：同一对 A、B 放到 9 × 6 的环面上，k 从 12 掉到 8。

The deficit lm − r has a more explanatory reading (BB guide section 4.2): send a pair of polynomials (u, v) to uA + vB; all such uA + vB form the ideal (A, B) (catch-up 2.A counts it on toric_L3). Written as a matrix under the coefficient-to-site encoding (xiyj ↔ site (i, j), index i·m + j), this map is [Aᵀ | Bᵀ] acting on the column vector (u; v), not [A | B]: under the constructor's convention column 0 of A sits on indices 4, 5, 54, which is the pattern of Aᵀ; row 0 of A (1, 2, 18) is the pattern of the polynomial A, so column s of Aᵀ is the shape of A translated to site s. [Aᵀ | Bᵀ] differs from HZ = [Bᵀ | Aᵀ] only in the order of its two blocks, so both have rank r = 66, and that is the dimension of the ideal; the remaining 72 − 66 = 6 dimensions are the quotient R/(A,B). In the ledger's words: “the dual side has the same six-dimensional defect, leaving twelve logical dimensions in the middle”. Two honest qualifiers follow at once. First, this is “a computed fact for these periods and polynomials”, not a promise that every three-term BB polynomial pair encodes twelve qubits. Second, “Three terms in A and three in B do not determine the rank: changing their exponents changes the common ideal and can change k”. The most direct evidence you have already seen in the BB guide: the same A, B on a 9 × 6 torus drops k from 12 to 8.

补课 · 「理想 (A, B)」与「商 R/(A,B)」是什么：在 toric_L3 上数一遍Catch-up · What “the ideal (A, B)” and “the quotient R/(A,B)” are: counted on toric_L3

把环面上的一种 0/1 格子图案看成一个多项式：格子 (i, j) 上有 1，就写一项 xiyj。所有图案组成的集合记作 R（约定 xl = ym = 1，加法是逐格异或），它有 lm 维：gross 72 维，toric_L3 9 维。多项式相乘就是图案的平移叠加：u·A 是「把 A 的形状按 u 的每一项平移一次，再全部叠起来」。理想 (A, B) 就是所有形如 uA + vB 的图案（u、v 任取）。写成矩阵：Aᵀ 的第 s 列是把 A 的形状平移到格子 s 的图案（A 的第 s 行就是第 s 条 X 检查的左层腿），所以理想正是矩阵 [Aᵀ | Bᵀ] 的列能叠出来的全部图案，维数是它的秩；[Aᵀ | Bᵀ] 与 HZ = [Bᵀ | Aᵀ] 只差两块的次序，秩就是 r。商 R/(A,B) 不是「剩下的那些图案」，而是把 R 里的图案分组：两个图案 p、q 算同一类，当且仅当 p + q 在理想里（p 加上某个 uA + vB 就变成 q）。每一类的图案个数都和理想一样多（2r 个），所以一共 2lm ÷ 2r = 2lm − r 类，商的维数是 lm − r，正是亏损。

Read a 0/1 pattern on the torus as a polynomial: a 1 on site (i, j) is the term xiyj. The set of all patterns is called R (with xl = ym = 1, and addition is site-wise XOR); it has lm dimensions: 72 for gross, 9 for toric_L3. Multiplying polynomials is translating and overlaying patterns: u·A means “translate the shape of A by each term of u and overlay everything”. The ideal (A, B) is the set of all patterns of the form uA + vB (u and v arbitrary). As a matrix: column s of Aᵀ is the shape of A translated to site s (row s of A holds the left legs of X check s), so the ideal is exactly the set of patterns the columns of [Aᵀ | Bᵀ] can build, and its dimension is that matrix's rank; [Aᵀ | Bᵀ] differs from HZ = [Bᵀ | Aᵀ] only in the order of the blocks, so the rank is r. The quotient R/(A,B) is not “the patterns left over”; it sorts the patterns of R into classes: p and q are in the same class exactly when p + q lies in the ideal (adding some uA + vB turns p into q). Every class holds as many patterns as the ideal does (2r), so there are 2lm ÷ 2r = 2lm − r classes, and the quotient has dimension lm − r, which is the deficit.

toric_L3 手算：A = 1 + x，B = 1 + y。u·A 的每一项放下一对横向相邻的格子，v·B 的每一项放下一对纵向相邻的格子；叠加时的抵消也是一个格子被放了两次，所以 uA + vB 里 1 的个数总是偶数。反过来，任何偶数个格子都凑得出来：把它们两两配对，每一对之间沿一条路径走，路径上每一步都是一对相邻格子，叠起来中间全部抵消，只剩两端。所以 (A, B) 恰好是「偶数个 1 的全部图案」，共 28 = 256 个，维数 8，与表中 toric_L3 的秩 8 一致。于是 toric_L3 的 29 = 512 个图案正好分成两类：偶数个 1 的全部图案是一类（包括全 0，也就是理想本身）；奇数个 1 的全部图案是另一类（例如单个格子 (0,0)）。两类 = 21，商的维数 9 − 8 = 1，k = 2 × 1 = 2。注意奇数类里任意两个图案相加都回到偶数类，它不是一块「A、B 够不着的补集」，而是一个类。gross 的图案不能这样一眼看出，秩 66 要靠消元，商的维数 72 − 66 = 6，k = 12。

By hand on toric_L3: A = 1 + x, B = 1 + y. Each term of u·A drops a horizontally adjacent pair of sites, each term of v·B a vertically adjacent pair; cancellation when overlaying also removes a site placed twice, so uA + vB always has an even number of 1s. Conversely any even set of sites can be built: pair them up and walk a path between the two sites of each pair; every step of the path is an adjacent pair, and overlaid they cancel everywhere except at the two ends. So (A, B) is exactly “all patterns with an even number of 1s”, 28 = 256 of them, dimension 8, matching the rank 8 of toric_L3 in the table. The 29 = 512 patterns of toric_L3 therefore fall into exactly two classes: all patterns with an even number of 1s form one class (it contains the all-zero pattern and is the ideal itself); all patterns with an odd number of 1s form the other (for example the single site (0,0)). Two classes = 21, the quotient has dimension 9 − 8 = 1, and k = 2 × 1 = 2. Note that adding any two patterns of the odd class lands back in the even class: it is a class, not a “complement that A and B cannot reach”. For gross the patterns cannot be read off at a glance: the rank 66 takes elimination, the quotient has dimension 72 − 66 = 6, and k = 12.

一个具体的路径例子（图 2.A）：单格 (0,0) 与单格 (2,1) 同类，因为它们的和 1 + x2y 在理想里：(1 + x)·A + x2·B = (1 + x2) + (x2 + x2y) = 1 + x2y。一步一步看：1·A 放下 (0,0)、(1,0)，x·A 放下 (1,0)、(2,0)，x2·B 放下 (2,0)、(2,1)；(1,0) 与 (2,0) 各被放两次，模 2 消掉，只剩两端。

A concrete path example (Fig. 2.A): the single site (0,0) and the single site (2,1) are in the same class, because their sum 1 + x2y lies in the ideal: (1 + x)·A + x2·B = (1 + x2) + (x2 + x2y) = 1 + x2y. Step by step: 1·A drops (0,0), (1,0); x·A drops (1,0), (2,0); x2·B drops (2,0), (2,1); (1,0) and (2,0) are each placed twice and cancel mod 2, leaving only the two ends.

n、重量、k 都是一次高斯消元的事；d 不是。账本这一节的标题就叫「Distance: two certificates, not one label」。说 d = 12 要同时交两份东西：下界——证明不存在重量小于 12 的非平凡逻辑算符（要排除的对象太多，不能靠找）；上界——拿出一个重量恰为 12 的逻辑算符（一个具体的见证witness：一个具体的、可机器复核的例子。这里指一个与所有检查对易、却不是检查乘积、重量恰为某个数的 Pauli 算符；它只证明 d 不超过那个数。，找到就算）。BB 教程 4.4 节讲过这个分工；第 3 章把 gross 的两份证书各自是谁写的、写在哪里，逐字抄下来——那正是「bounded」这个词的全部内容。

n, weight and k are one Gaussian elimination each; d is not. The ledger's section is titled precisely “Distance: two certificates, not one label”. To say d = 12 you must hand over two things at once: a lower bound, a proof that no non-trivial logical operator of weight below 12 exists (too many objects to exclude by searching); and an upper bound, an actual logical operator of weight exactly 12 (a concrete witnessA concrete, machine-checkable example: here a Pauli operator that commutes with every check, is not a product of checks, and has weight exactly some number; it proves only that d does not exceed that number., which counts as soon as it is found). BB guide section 4.4 introduced this division of labour; Chapter 3 copies out who wrote each of gross's two certificates and where, which is the entire content of the word “bounded”.

Fooling the detectors is not enough: some fault combinations cancel each other, or add up to a mere stabilizer; they escape detection and do no harm, and they do not count. The definition of Bravyi et al. (arXiv 2308.07915, section 6): the Z-type circuit distance is “the minimum number of faulty operations in the SM circuit that can generate an undetectable Z-type logical error”, likewise for X, and the circuit distance is the smaller of the two; for the depth-7 circuit of gross they obtain only the upper bound dcirc ≤ 10 (Table 1). The reason was given in BB guide section 6.2: a helper qubit that fails midway spreads through later CNOTs onto several data qubits, and the CNOT order decides where. Hence the ledger lists four things that do not follow from the static ledger: “a distance-12 fault circuit; a universal threshold; a decoder-independent logical error rate; a logical-gate error rate”. They belong to the Decoders and Logical operations facets. Plainly: this guide's 12 is a property of a matrix; whether a chip gets 12 depends on the circuit.

5.4渐近：一条文献声明，不是账本结论Asymptotics: a literature claim, not a ledger conclusion

gross 的 k·d²/n = 12 远高于表面码的约 1，很容易让人以为「把环面放大，这个数会一直涨」。Atlas 的 intuition.md 把这列为失败模式之一：「Finite constants do not imply asymptotic goodness. The gross point is a strong finite block. It is not evidence that fixed sparse polynomials evade two-dimensional tradeoffs as the torus grows.」人话：gross 是一个很强的有限块；固定两个多项式、只放大环面，并不能逃出 BPT 界那种二维权衡。BPT 界（Bravyi、Poulin、Terhal，arXiv 0909.5200）的前提有两条：比特排在二维格子上，单位面积里的比特数有上限；每条检查只碰相距不超过某个固定距离的比特。满足这两条的码必须有 k·d² ≤ c·n，常数 c 只取决于检查的作用范围和每个格点的维数，与码有多大无关。固定两个多项式、只放大环面时，每条检查的腿仍是那几个固定的平移，作用范围不变，两条前提都成立，界直接管用，k·d²/n 不能无限上涨。若只固定项数、让指数随环面一起变大，检查可以伸得越来越远，第二条前提不再成立，BPT 不再直接适用；那种情形的限制来自下面这条文献声明。card.yaml 的表示阶梯里有一条 R5 层的「quotient-module」断言，证据词 curated、出处 postema2025existence：商空间 R/(A,B) 控制 k，多项式的因子与公共根解释了「why finite blocks can have high rate, and why the studied subclass is not an asymptotically good family」——为什么有限块可以有高码率，以及为什么所研究的子类不是渐近好的一族。BB 教程 6.6 节用一句话转述过：固定项数、无限放大环面时，码率与相对距离不能同时保持非零。

Gross's k·d²/n = 12 is far above the surface code's roughly 1, and it is tempting to think “enlarge the torus and this number keeps rising”. The Atlas file intuition.md lists this among the failure modes: “Finite constants do not imply asymptotic goodness. The gross point is a strong finite block. It is not evidence that fixed sparse polynomials evade two-dimensional tradeoffs as the torus grows.” Plainly: gross is a strong finite block; fixing the two polynomials and only enlarging the torus does not escape the two-dimensional trade-off of the BPT bound. The BPT bound (Bravyi, Poulin, Terhal, arXiv 0909.5200) has two premises: the qubits sit on a two-dimensional lattice with a bounded number per unit area, and every check touches only qubits within some fixed distance of each other. Codes meeting both must satisfy k·d² ≤ c·n, where the constant c depends only on the check range and the dimension per lattice site, not on the size of the code. With the two polynomials fixed and only the torus growing, the legs of every check are still the same few translations, the range does not change, both premises hold, and the bound applies directly: k·d²/n cannot rise without limit. If only the number of terms is fixed and the exponents grow with the torus, checks can reach further and further, the second premise fails and BPT no longer applies directly; the limit in that case comes from the literature claim below. In card.yaml's representation ladder there is an R5 “quotient-module” assertion, evidence word curated, source postema2025existence: the quotient R/(A,B) controls k, and polynomial factors and common roots explain “why finite blocks can have high rate, and why the studied subclass is not an asymptotically good family”. BB guide section 6.6 paraphrased it in one sentence: with a fixed number of terms and an ever-larger torus, rate and relative distance cannot both stay non-zero.

关键想法Key idea

「十二倍」是一句有四个限定的话：只比数据比特、且码距相同（144/12 对 144/1；若按电路级模拟、逻辑错误率大致相当（约 2 × 10⁻⁷ 对 10⁻⁶）来比，论文给的是 288 对近 3000，超过 10 倍）；加帮手后 288 对 287，倍数仍近十二，但两边都没数耦合器、调度、译码器；12 是静态码距，电路码距另算；这是有限块的常数，不是渐近性质。四个限定各有出处，前三条在 Atlas 账本，第四条是文献声明。

“Twelve-fold” is a sentence with four qualifiers: data qubits only, at equal distance (144/12 against 144/1; compared in circuit-level simulation at roughly comparable logical error rates (about 2 × 10⁻⁷ versus 10⁻⁶), the paper gives 288 against nearly 3000, more than ten-fold); with helpers 288 against 287, still nearly twelve, but neither side counts couplers, schedule or decoder; 12 is the static distance, the circuit distance is a separate matter; and it is a finite-block constant, not an asymptotic property. Each qualifier has its source: the first three in the Atlas ledger, the fourth a literature claim.
